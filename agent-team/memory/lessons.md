# Lessons — mc_protocol

Curated by the team leader after task close: things that cost time once and
should not cost time twice. Newest first.
Format: `- [T-xxx] What happened → what to do instead.`

- [T-064] The HIL safety gate took four rounds: each fix closed the attack just found (truncated `readOnly` write, `1402`, `frameOverride`, 4C on a 3C port, unknown serial commands) and the next tester found the next one. Only "default deny" — every command at every frame start must be an allowed read or a mock-decoded write inside scratch — converged. For a safety check, design it as an allow-list over everything the input can contain from the start, and set a stopping rule (which severities block) before the first re-test.
- [T-064] Phase 7 developers resumed across eight tasks reached 0.5–0.9 M tokens of context; the owner asked for a fresh agent per task. Task files must carry everything a new agent needs; resume only for the current task's rework.
- [T-063] `RESOURCE_LOCK` serialises serial tests inside one `ctest` only: the leader's run and an agent's run collided on COM54/COM55 and an entry hung to the 120 s timeout. One agent at a time sets `MC_TEST_SERIAL_PAIR`; serial tests carry their own watchdog.
- [T-061] A replay compared on whole-millisecond stamps and missed a live tick at 19.58 ms against a 20 ms deadline — 4 of 10 loaded runs failed. A replay of timed captures must state its clock rule and be stress-run under load (10+ runs) before it is trusted; keep the failing capture as a fixture.
- [T-060] A runner kept finished-request results by id; a new `Session` after `setConfig` restarts ids at 1, so stale results completed the next step instantly and were recorded as 0.07 ms "timeouts". Found only by replaying the captures. Any map keyed by an id that a reset re-issues is cleared on that reset.

- [T-055] Dropping serial junk so it never overflows (owner decision) removed the only thing that ended a line sending junk forever: each junk byte still re-armed the inter-character deadline, so the request would never time out. The re-reviewer caught it by reading. When a change removes one terminating path (overflow), check every other path that bounds the same wait (deadlines) for inputs that never reach it — and test the "never stops" input explicitly.
- [T-051] One stray byte before a maximum-size serial response counted toward the receive bound and forced EOT + flush + retry; every test stayed green because the retry recovered. A recovery path can hide a defect: tests assert "no retry / no EOT" on inputs the spec says are harmless, not only the final result.
- [T-054] The virtual `COM50->COM51` port went to PnP Error during a `ctest -j 8` run with several entries opening the pair at once. Every test that opens a shared physical/virtual resource gets a ctest `RESOURCE_LOCK` from the start.
- [T-052] A mock mutation (1C points `00` not mapped to 256) survived every vector and test and was found only by the tester's mutation run. Encoding edge values (`00` = 256, max counts) get a dedicated test in each frame family, not just vector coverage.
- [T-051] A developer wrote temp files to `%TEMP%` (outside the project). Every brief repeats the scratch rule: `build/_scratch-<task>/` or `temp-docs/`, never `%TEMP%`.

- [T-050] The serial parser's "no rescan" property was tested on `serialFeed()` only; the `Parser` wiring that stores the scan cursor could reset it to 0 (rescan every feed, same output) and all 122 cases stayed green — the tester's mutation found it. A property proven on an internal helper must also be pinned through the public API that wires it in, with a test that fails when the property breaks but the output does not.
- [T-044] Three defects from Phases 1 and 3 (`chunkCount()` applying the 256-point rule to the unsplit request; `subscribe()` checking the raw bit head; `autoGap(ReadBits)` wrapping unsigned) surfaced only when a second frame family arrived — every earlier test ran 3E, and 3E Binary's own `autoGap(ReadBits)` was already wrong. A table-driven function (sizes, limits, alignment) is tested on every frame family and op it claims to serve, with literals worked out by hand, as soon as it exists — not when the family is implemented.
- [T-040] BLD-05(d) (since T-004) matched the text `mc_mock` in `mc_device`'s LINK_LIBRARIES, but CMake keeps the name as written, so `mc::mock` passed; four phase reviews missed it and the Phase 5 tester found it by mutating the link line. A guard that matches names must be proven with every spelling a user can write (alias, target name), each as its own negative control.
- [T-040] `setConfig()` deleted the transport synchronously; a slot on the transport's own failure signal calling `setConfig()` would delete it mid-emission. Found by reading, not by a test (Qt 6.11 did not crash). An object owned by a QObject and reachable from its own signal chain is released with `disconnect()` + `deleteLater()`, and the test asserts the lifetime, not a crash.
- [T-034] BLD-04 required a `.pri` whose CMake target is switched off to list no files, so disabling a layer (`MC_BUILD_MOCK=OFF`, and from T30 the `cmake-core` stage with `MC_BUILD_DEVICE=OFF`) would fail the guard — no stage exercised the OFF path. Fixed by exporting each layer's source list regardless of its option; `mc_device` (T30) must define its source list the same way. When a build guard compares two systems, run it once with every optional layer off.
- [T-034] Two tests passed while pinning nothing independent: INT-07 ASCII compared the core's `chunkCount()` with the core's own `chunk()`, and the `session_loop` smoke test checked only exit 0 while an early `break` also exited 0. A test that asserts a number must take it from the reference spec or a literal, not from the code under test; a smoke test checks a success marker in the output too.
- [T-028] Three separate output-lifetime mechanisms (plan refs T-024, ad-hoc confirmDrained T-025, drain discard T-026) were each correct alone; the later drain discard bypassed the other two and could stop the engine for good. When a new code path removes items from a queue, route it through the same release routine as the normal path — and let the phase reviewer look across tasks, which is what caught it.
- [T-028] The coverage report (since T-012) read gcov output with `file(STRINGS)`, which splits on `;` — most C++ lines were merged and one file showed 0/0 = 100 %. Earlier numbers happened to be unaffected. A tool that produces a gate number needs its own sanity test (a file with known coverage) before its result is trusted.
- [T-023] A dangling-pointer bug (queued outputs pointing into a plan replaced in the same call) was found by the developer reading code, not by a test — no test combined a re-plan with back-to-back rounds. For output records that point into engine storage, test the lifetime contract explicitly (T-024 2a).
- [T-019] Two qmake test `.pro` files shared one object directory; the protocol binary linked core-model's `test_alloc.obj` and still reported all green — a test binary can pass while its real tests never ran. When a checkpoint compares build systems, compare the test-case lists (`--list-test-cases`), not only pass counts.
- [T-019] Phase 1 added `mc_core_model_tests` without a qmake `.pro`; BLD-03 ("every test through the .pri files") was in no acceptance criterion, so nobody checked it → every task that adds a test binary lists its `tests/qmake` `.pro` (now in the Definition of Done).
- [T-007] A spec sketch declared a `constexpr` function defined in a `.cpp` — impossible in C++; found only at link time. When planning a task, check that the spec's sketch compiles as declared (constexpr/inline/template bodies must be visible to callers).
- [T-002] The leader fixed `.gitignore` (an "Ask first" file) mid-task without recording owner approval → review FAIL. Get and record the owner's approval in the task file before touching an owner-gated file, even for an obvious fix.
- [T-001] A Plan said "not a Linux Qt path" and the developer fixed the comment but kept `/opt/Qt/…` → when a Plan asks for changed text, write the exact target text in the Plan.
