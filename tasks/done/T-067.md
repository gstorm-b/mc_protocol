## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `tools/mc_workbench` builds on MSVC and MinGW with CMake and qmake, links ADS and qpb,
  and opens an empty main window with docking.
- **Approach** (`SPEC-gui-tool.md` "Build and third-party components"):
  - CMake option `MC_BUILD_GUI` (ON when top-level, `MC_BUILD_TOOLS` on and ADS found; otherwise
    skipped with a status message). Qt ≥ 6.5 required for the GUI target only.
  - `MC_ADS_DIR` cache variable (env `MC_ADS_DIR`, else `C:/build_packages/qtadvanceddocking-5.1.1`)
    added to `CMAKE_PREFIX_PATH` for `find_package(qtadvanceddocking-qt6)`.
  - `scripts/build-ads.ps1`: builds ADS from `MC_ADS_SOURCE_DIR` (default
    `C:/build_packages/Qt-Advanced-Docking-System`, **read only**) with a chosen Qt kit into
    `build/ads-<kit>/install` (Debug and Release), so MinGW has an ADS; prints the `MC_ADS_DIR` to
    use. Nothing is written outside the project.
  - qmake: `mc_local.pri.example` (committed) and the git-ignored `mc_local.pri` set `MC_ADS_DIR`;
    `tools/qmake/mc_workbench.pro`; `components/qpb.pri` wrapper **outside** the vendored folder.
  - `add_subdirectory(components/qpb)` (unmodified vendored copy), link `qpb::widgets`.
  - App skeleton: `MainWindow` with an `ads::CDockManager`, placeholder dock widgets for the areas
    of the spec, menu, status bar, About (versions of mc, Qt, ADS, qpb). Copy the ADS DLL next to
    the executable after build; tests get it on `PATH`.
  - Static library `mc_workbench_core` (non-UI, starts empty) + app; QtTest `mc_workbench_tests`
    (label `gui`, `QT_QPA_PLATFORM=offscreen`) with GUI-09.
- **Acceptance criteria:**
  1. GUI-09 green on MSVC and MinGW (CMake), and the qmake twin builds and runs on both kits.
  2. With ADS absent (bogus `MC_ADS_DIR`) the configure succeeds and the GUI is skipped with a
     clear message; the rest of the build is unchanged (BLD guards green).
  3. `scripts/build-ads.ps1` produces a working MinGW ADS under `build/`; the MSVC kit can use either
     the prebuilt package or a script build.
  4. `check.ps1` (both kits) and `check.sh` stay green.
- **Gate 1 approval:** 2026-10-03 — leader, under the owner's delegation extended to Phase 8
  (`rules.md`). Gate 2: leader, one commit for Phase 8 after Checkpoint H.

- Deviations from plan (+ reason):
  - A second static library `mc_workbench_ui` besides `mc_workbench_core`: the main window needs widgets and ADS, the Plan says core is non-UI, and the test and the program must compile `MainWindow` once. Core holds only `component_versions` for now (a static library cannot be empty).
  - qmake: no `MC_ADS_DIR` default path (spec says `mc_local.pri` only) and two keys: `MC_ADS_DIR` (MSVC kits) and `MC_ADS_DIR_MINGW` (MinGW kits), because one path cannot serve both kits. The env var `MC_ADS_DIR` is a fallback for both.
  - CMake finds ADS with `find_package(... PATHS ${MC_ADS_DIR} NO_DEFAULT_PATH)` instead of appending to `CMAKE_PREFIX_PATH`: same effect, and a stale cached result cannot survive a changed `MC_ADS_DIR`.
  - Extra guard not in the Plan: ADS built for the other compiler (the MSVC prebuilt package seen by a MinGW configure) is detected and the GUI skipped with a message; without it every default MinGW configure (check scripts, `build/cmake-coverage`) would fail at link time.
  - New root file `mc_gui_deps.pri` (not listed): one place for the qmake decision, used by `tools.pro`, `tests.pro` and `mc_workbench.pri`.
  - Not done: `MC_BUILD_GUI` is not an explicit "ON only if ADS found" cache value; it stays ON and the skip is decided in `tools/CMakeLists.txt` (message), so a later configure with a good `MC_ADS_DIR` needs no `-DMC_BUILD_GUI=ON`.
