  the heartbeat on; the benchmark `mc_bench_session` (built only with

## Dev notes  *(developer writes)*

- **Status: ready-for-test**

- Files changed:
  - `tests/core/session/test_alloc.cpp`: added the real ALC-01 (`"ALC-01 Session steady state:
    zero allocation across rounds 3-10 with changes every round and the heartbeat on"`) — one
    subscription (D100x4), heartbeat on (alternating bit each round), rounds 1-2 run as warm-up
    (re-plan settles, decision S4's silent baseline covers round 1's own report), then
    `mc::test::resetAllocCount()` before rounds 3-10, each driven by draining raw
    `Session::nextOutput()` (never `OutputRecorder` — see Deviations) and feeding pre-built
    response buffers (see Deviations). Also renamed the file's own three pre-existing "ALC-01
    ..." TEST_CASEs (see Deviations) and added a small `okWords()` helper (mirrors the one every
    other `test_session_*.cpp` already has locally). Top-of-file banner comment rewritten to
    describe both ALC-01 (T-027) and ALC-02 (T-025) and the rename.
  - `tests/bench/bench_session.cpp` (new, 165 lines): `main()` runs `benchOne()` over 5
    point-count/chunk-count configurations, prints a `points | ns/round | ns/point` table.
    `benchOne()` builds a `Session` with `deviceCount` disjoint D-device subscriptions
    (`pointsPerDevice` each, gap 32 points — never merged), heartbeat on, drives one warm-up
    round (re-plan) then times 200 steady-state rounds via `std::chrono::steady_clock` (a
    scripted peer answers every `Send` immediately, values changing every round — the same
    scenario ALC-01 checks for zero allocation, timed here instead), and returns the average
    `ns`/round and `ns`/point. Reuses `tests/core/session/harness.h`/`.cpp`
    (`FakeClock`/`ScriptedPeer`/`PeerScript`) directly — no doctest dependency of its own, so it
    links cleanly into this plain (non-ctest) executable.
  - `tests/bench/CMakeLists.txt` (new): defines `mc_bench_session`, compiling
    `bench_session.cpp` plus `../core/session/harness.cpp`, linked against `mc::core` only (no
    `mc_doctest`, no `add_test()` — matches the spec's own "no threshold").
  - `tests/CMakeLists.txt`: added `if(MC_BUILD_BENCH) add_subdirectory(bench) endif()` at the end
    (nested under `tests/`, not the top-level `CMakeLists.txt` — see Deviations).

- Deviations from plan (+ reason):
  - **Top-level `CMakeLists.txt` was *not* touched** ("bench wiring if needed" in the Plan's own
    Files list correctly anticipated this might not be needed): `option(MC_BUILD_BENCH ...)` was
    already declared there (predates this task), and `add_subdirectory(bench)` only needed a
    home *somewhere* that runs whenever `tests/` itself does. I put that guard in
    `tests/CMakeLists.txt` instead, since `tests/bench` is physically a child of `tests/` (matches
    the spec's own Project Structure tree) and `MC_BUILD_TESTS` already defaults `ON` at the top
    level, covering the task's own specified verification command
    (`-DMC_BUILD_BENCH=ON -DCMAKE_BUILD_TYPE=Release`, no `MC_BUILD_TESTS` override) without any
    top-level change. One known consequence, worth flagging: `-DMC_BUILD_TESTS=OFF
    -DMC_BUILD_BENCH=ON` would build neither tests nor the bench (since `tests/CMakeLists.txt`
    itself is only reached when `MC_BUILD_TESTS` is on) — not exercised by this task's own
    acceptance criterion, but a real coupling a reviewer may want revisited (e.g. moving the
    `MC_BUILD_BENCH` guard up to the top-level `CMakeLists.txt` instead, independent of
    `MC_BUILD_TESTS`, if the bench is ever meant to build standalone).
  - **Found and fixed a real pre-existing mislabeling in `test_alloc.cpp`, not part of this
    task's own new code:** the spec's own "Testing Strategy" table names exactly two allocation
    tests for this file, `ALC-01` (rounds 3-10, Session-level — this task's own job) and `ALC-02`
    (T-025's 1000-cycle ad-hoc test). T-021 had already added three `TEST_CASE`s all prefixed
    `"ALC-01 ..."` for its own `ValueStore::apply()`/`markFailed()`/positive-control checks,
    before this task's real, spec-defined `ALC-01` existed to claim that name — a placeholder
    label that stopped being correct the moment a real `ALC-01` was added to the same file.
    Fixed by renaming: the positive control is now generic (`"ALC positive control: the
    allocation counter is live"`, since it backs every zero-count check in the file, not just one
    ID), and the two `ValueStore`-only checks now say plainly what they test without claiming an
    ID (`"ValueStore::apply(): zero allocations (narrower than ALC-01: ValueStore alone, no
    Session)"`, similarly for `markFailed()`) — kept rather than deleted, since they still isolate
    `ValueStore`'s own allocation behaviour from the rest of the engine for future diagnosis.
    Flagged here explicitly for the checkpoint reviewer since it touches T-021's own prior work,
    not just this task's.
  - Not using `OutputRecorder` in the new ALC-01 test (draining via raw `nextOutput()` instead):
    same reasoning as ALC-02's own comment (T-025) — `RecordedOutput` copies every view into
    owned storage on every `drain()` call, which would allocate and swamp the very thing this
    test measures.
  - **A real bug caught while first running the new ALC-01 test, before it ever passed:** my
    first draft called `ScriptedPeer::respond()` *inside* the measured loop (rounds 3-10), once
    per round for both the heartbeat ack and the poll-chunk response. `respond()` returns a
    `std::vector<uint8_t>` by value, allocating on every call — a test-harness allocation, not a
    `Session` one, but `mc::test::allocCount()` counts every `operator new` process-wide and
    cannot tell the two apart, so the first run reported 232 (non-zero, but harness-caused, not a
    real regression). Fixed by pre-building every response buffer before
    `resetAllocCount()`: one fixed heartbeat-ack buffer (a write ack's own bytes never depend on
    the request at all — confirmed against `harness.cpp`'s own `buildReadData()`, "a write's
    response carries no data" — so the same buffer answers every round's heartbeat write
    regardless of which bit `Session` actually sent), and one poll-chunk response buffer per
    round's own changing value (1..10), precomputed up front. `bench_session.cpp` was written
    with this same lesson already applied (its own heartbeat-ack buffer is likewise built once,
    outside the timed loop) — no rebuild-after-failure cycle needed there, though the underlying
    mechanism is only a wall-clock timer, not an allocation counter, so it would not have failed
    loudly the way ALC-01 did regardless.

  - `bench_session.cpp`'s own `driveRound()` lambda silently returns early (does nothing further)

    number change rather than a loud failure. If Checkpoint C wants stronger guarantees here, the
