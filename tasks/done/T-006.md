## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** The error and byte-view vocabulary every other module uses:
  `include/mc/core/types.h` and `include/mc/core/result.h`, header-only.
- **Approach:** `ByteView`, `MutableByteView`, `ByteBuf`, `kNoCode`;
  `ErrorCategory`, `ErrorCode` (incl. `NotSubscribed`), `ErrorInfo`, `Error`
  with `ok()`, `Expected<T>` (implicit from value and from `Error`; a
  move-only `T` makes `Expected` move-only) and `Expected<void>`. No
  exceptions, no allocation of its own. Creates the test binary
  `mc_core_model_tests` with `tests/core/model/main.cpp` holding the one
  `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN`. Header-only headers still appear in
  the `mc_core` header list and in `mc_core.pri` `HEADERS`.
- **Files expected to change:** `include/mc/core/types.h`,
  `include/mc/core/result.h`, `src/CMakeLists.txt`, `mc_core.pri`,
  `tests/CMakeLists.txt`, `tests/core/model/main.cpp`,
  `tests/core/model/test_result.cpp`.
- **Acceptance criteria:**
  1. RES-01…RES-03 pass: value/error semantics of `Expected<T>` and
     `Expected<void>`, `Error::ok()`, `message` is a static string.
  2. RES-04 passes: `Expected<std::unique_ptr<int>>` moves in and out, and a
     static check proves copying it does not compile
     (`!std::is_copy_constructible_v<…>`).
  3. `static_assert`s: `Error` and `Expected<int>` are trivially copyable.
  4. `ctest -L "core_model|build"` green on MSVC; BLD-04/05 green with the
     new headers.

- Deviations from plan (+ reason):
  - `CHANGELOG.md` was not in the Plan's file list but was touched anyway: `agent-team/project/definition-of-done.md` requires an `Unreleased` line for every consumer-visible change, and this task adds two new public headers. Same class as `tests/CMakeLists.txt`'s extra line below — a Definition-of-Done obligation, not a scope change.
  - `tests/CMakeLists.txt` (already an in-scope file) also gained `target_compile_definitions(mc_doctest INTERFACE DOCTEST_CONFIG_USE_STD_HEADERS)`, applying to every test binary (`mc_build_tests` too), not just `mc_core_model_tests`. Reason: without it, MSVC only forward-declares `std::ostream` inside `doctest.h`; the moment a test stringifies a `std::string_view` (used here for `Error::message`, and by every future `parseDevice`/`convert` test per the spec's public API) doctest's fallback stream path instantiates the standard library's own `operator<<(ostream&, string_view)` against that incomplete forward declaration and the build fails deep inside `<__msvc_string_view.hpp>`. This is documented, known doctest/MSVC behavior; the macro just tells doctest to include the real standard headers instead of forward-declaring them. Rebuilt `mc_build_tests` (BLD-08) afterward — still green, so no regression. Applying it project-wide (rather than only in `test_result.cpp`) avoids doctest-config mismatches between translation units of the same binary and pre-empts the same failure for T06 onward.
