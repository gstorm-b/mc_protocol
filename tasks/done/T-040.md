### Owner demo steps (Checkpoint D: `virtual_plc` and `qt_console_poller`, MSVC build tree)

One-time build (any PowerShell), from `C:\DGB\Project\mc_protocol`:

```powershell
cd C:\DGB\Project\mc_protocol
. scripts/vsdev.ps1
cmake --build build/cmake-debug --target virtual_plc qt_console_poller
```

Terminal 1 (the PLC). The Qt DLLs must be on PATH:

```powershell
cd C:\DGB\Project\mc_protocol
$env:PATH = "C:\Qt\6.11.1\msvc2022_64\bin;$env:PATH"
build\cmake-debug\examples\virtual_plc.exe --frame 3E --port 5000 --set D100=1234 --wiggle D105
```

You should see `virtual_plc listening on 127.0.0.1:5000 (3E Binary)`; when the poller connects, `client connected: 127.0.0.1:<port>`, then one line `wiggle D105 = N` every second.

Terminal 2 (the poller), started after terminal 1 says "listening":

```powershell
cd C:\DGB\Project\mc_protocol
$env:PATH = "C:\Qt\6.11.1\msvc2022_64\bin;$env:PATH"
build\cmake-debug\examples\qt_console_poller.exe --host 127.0.0.1 --port 5000 --frame 3E --sub D100:64 --sub M0:32
```

You should see: `link: Connecting (Requested) 127.0.0.1:5000`, `link: Connected (Requested) 127.0.0.1:5000`, then the round-1 snapshots (`snapshot M, round 1` with the 32 bits as rows of eight, then `snapshot D, round 1` with D100 = 1234 and the rest 0), then about once a second a line like `changed D105: 4 -> 5 (round 41)` (a round is 100 ms). Nothing is printed for values that do not change. The wiggle in terminal 1 starts when terminal 1 starts, not when the poller connects: if terminal 2 is started more than a second later, the round-1 snapshot already shows D105 = 1 (or higher, e.g. `D100: 1234 0 0 0 0 1 0 0`) and the first change line reads `changed D105: 1 -> 2`, not `0 -> 1`. The last line `link: Disconnected (Requested)` has a trailing space.

How to stop: press Ctrl+C in terminal 2 first, then in terminal 1 (`client disconnected` appears in terminal 1). A scripted variant that exits by itself: add `--rounds 35` to the poller (prints `done after 35 rounds`); read its exit code right after it returns with `echo $LASTEXITCODE` in terminal 2: 0 after `--rounds` completes, 1 after a link fault or a failed open, 2 for a bad argument. (Ctrl+C ends a poller without `--rounds` with the console's own exit code, not one of these.)

Optional checks the owner can try:
- **Link loss:** with the poller running, press Ctrl+C in terminal 1; the poller prints `link: Disconnected (PeerClosed) ...` and exits with code 1 (`echo $LASTEXITCODE`). The device does not reconnect by itself; the program decides.
- **No PLC:** start only the poller; after about 2 s it prints `link: Disconnected (OpenFailed) connect timed out after 2000 ms` and exits 1.
- **ASCII frame:** start `virtual_plc.exe --code ASCII --port 5001 --wiggle M5 --set M3=1` and `qt_console_poller.exe --port 5001 --code ASCII --sub M0:16 --sub D0:4`.
- If port 5000 is taken, use another port in both commands.
