## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `Session` ↔ `MockPlc` in one process over an in-memory pipe and a
  fake clock, running the v1 integration scenarios on 3E Binary and 3E ASCII.
- **Approach:**
  - `tests/mock/integration/pipe.h`: in-memory byte pipe that splits every
    transfer into random fragments from a fixed seed (`std::mt19937` with an
    explicit seed; no `random_device`).
  - `tests/mock/integration/rig.h/.cpp`: `Session` + `MockPlc` + fake clock +
    two pipes; one call per scenario step. It drains `Session::nextOutput()`
    after **every** input (`bytesIn`, `tick`, subscribe/ad-hoc calls), as the
    drain contract requires, routes `Send` → pipe → `MockPlc::bytesIn` and
    `MockPlc::nextResponse` → pipe → `Session::bytesIn`, and records the
    other outputs for assertions. A muted mock is a jump of the clock past
    `nextDeadline()` followed by `tick()` — no sleeps. Rig defaults:
    `readRetries = 2`, `maxConsecutiveLinkErrors = 3` (spec).
  - `tests/mock/integration/test_integration.cpp`: the scenarios, each run for
    3E Binary and 3E ASCII (doctest subcases or a loop naming the
    combination on failure). Structure the matrix so Phase 6 adds 1E/3C/1C
    combinations by extending a list, not by copying scenarios.
  - Binary `mc_integration_tests`, label `integration`, built when
    `MC_BUILD_MOCK` and `MC_BUILD_TESTS` (SPEC-build-packaging change 2);
    qmake twin `tests/qmake/mc_integration_tests.pro` in `tests.pro`.
  - If a scenario exposes an engine or mock defect, fix it in the owning
    module only if the fix is local and within that module's spec; otherwise
    stop and report (Dev notes, `Status: blocked`). Any `src/core/session`
    change is listed in Deviations with its reason.
- **Files expected to change:** `tests/mock/integration/pipe.h`,
  `tests/mock/integration/rig.h/.cpp`,
  `tests/mock/integration/test_integration.cpp`, `tests/CMakeLists.txt`,
  `tests/qmake/mc_integration_tests.pro`, `tests/qmake/tests.pro`.
- **Acceptance criteria:**
  1. INT-01, 02, 03, 07, 08, 10, 11, 12, 13, 14, 15, 16 pass for 3E Binary and
     3E ASCII, with the expectations of the spec's table (3E column where it
     differs: INT-07 logs 3 requests on 3E Binary — `chunkCount()` of the
     frame for ASCII; INT-11 `LinkFault{Timeout, reopen}`; INT-12
     `LinkFault{ProtocolError, reopen}`).
  2. INT-04/05/06/09 are not implemented (tagged `v1.1`/`v2` by the spec) —
     note them as skipped in a comment, no disabled test bodies needed.
  3. `mc_integration_tests` completes in under 5 s of wall time (report the
     measured time from ctest).
  4. The qmake binary lists the same test cases as the CMake one.
- **Common to every Phase 4 task:** see T-029 (the independence rule does not
  apply to `tests/`; the rig may include anything public).
- **Gate 1 approval:** 2026-09-30 — leader, under the owner's delegation
  extended to Phase 4 (`rules.md`). Gate 2: leader, one commit for the phase.

## Dev notes  *(developer writes)*

- Files changed:
  - `tests/mock/integration/pipe.h` (new): `Pipe`, an in-memory byte pipe; every `write()` is cut
    into fragments of 1..16 bytes with `std::mt19937(seed)` (raw output `% n`, no `std::`
    distribution, so the cuts are the same on MSVC and GCC); no `random_device`.
  - `tests/mock/integration/rig.h/.cpp` (new): `Rig` = `Session` + `MockPlc` + fake clock + two
    pipes. Every input (`linkUp`, `linkDown`, `submit`, `tick`, and each fragment fed to
    `Session::bytesIn`) is followed by a full `nextOutput()` drain; `Send` goes to the mock pipe,
    `MockPlc::nextResponse` to the session pipe, until both pipes are empty; every output is
    recorded as an owned `Event`. `jumpToDeadline()` (clock to `nextDeadline()`, then `tick()`) is
    how a round starts and how a muted mock times out; `runRound()` = one jump, true when a
    `CycleDone` followed. Frame gets `readRetries = 2`, session `maxConsecutiveLinkErrors = 3`.
    `combos()` is the matrix list (3E Binary, 3E ASCII); Phase 6 adds cells there.
  - `tests/mock/integration/test_integration.cpp` (new): INT-01, 02, 03, 07, 08, 10, 11, 12, 13,
    14, 15, 16 as 12 test cases; each runs as a doctest subcase per matrix cell. INT-04/05/06/09
    are noted as skipped in the file header (no test bodies).
  - `tests/CMakeLists.txt`: `mc_integration_tests` (label `integration`, ctest
    `integration.mc_integration_tests`), inside the `MC_BUILD_MOCK` block; links `mc::mock`,
    `mc_doctest`, public headers only (no `src/` include path).
  - `tests/qmake/mc_integration_tests.pro` (new, own intermediate dirs, `include(../../mc_mock.pri)`,
    `QT =`), `tests/qmake/tests.pro` (entry + `.file` line).

- Notes for the tester:
  - The matrix is 3E only: 1E and the serial frames are not implemented in the mock or the core
    yet, and `combos()` is where Phase 6 adds cells. INT-11 and INT-12 assert the Ethernet
    outcome only (`reopenTransport = true`, no resend); their serial branches (EOT, retries,
    `reopen=false`) do not exist yet.
  - INT-11 additionally pins: `nextDeadline()` == round start + `effectiveTimeoutMs()` while the
    request is unanswered; the fault marks chunk 0 `Failed`; `stats().timeouts == 1`,
    `retries == 0`; 60 s later nothing more is sent (the muted request is the only one in the mock
    log); after `linkDown` + `linkUp` round 1 restarts (silent baseline, snapshot, `CycleDone{1}`).
  - INT-13 also asserts that the two settings differ on the wire (`ReadWords` vs `ReadBits` for
    the M chunk) and that some rounds do change values, so the equality is not vacuous. INT-15
    asserts that the 20 seeds produce more than one distinct total fragment count, for the same
    reason. INT-15 compares every output (Send bytes included) as text.
  - Fragmentation runs in both directions (requests to the mock, responses to the session).
