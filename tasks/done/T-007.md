- Deviations from plan (+ reason):
  - `deviceInfo()` is declared plain `noexcept`, not `constexpr` (the module spec's `device.h`
    sketch shows `constexpr`). As specified — declared `constexpr` in the header, defined only in
    `device_table.cpp`, with nothing in that `.cpp` ever calling it — the build does not link:
    MSVC only emits an out-of-line body for an inline/constexpr function in a translation unit
    that itself odr-uses it, and no translation unit here both sees the definition and calls it,
    so every caller gets `LNK2019 unresolved external symbol ... deviceInfo`. Confirmed by
    building before this change (full link failure) and after (clean link). Dropping `constexpr`
    keeps the file split the Plan and spec's Project Structure ask for (table + function live
    only in `device_table.cpp`, out of the public header) and keeps the same signature otherwise,
    `O(1)`/no-allocation contract, and doc comment. Nothing in this module's spec (validate(),
    maxPoints(), chunk() — the only in-tree callers named) needs `deviceInfo()` usable in a
    constant expression. Flagging for leader/reviewer visibility per rules.md ("any deviation
    from the spec is recorded ... and raised to the leader").
  - Touched `CHANGELOG.md`, not in the Plan's file list: `definition-of-done.md` Documentation
    section requires a consumer-visible change to have an `Unreleased` line "from T04 on"; this
    task adds a new public header, so it applies.

## Review verdict  *(reviewer writes — skipped only if Class says so)*

- Findings (severity · file:line · what/why):
  1. **blocker** · `include/mc/core/device.h:115` (declaration) and
     `src/core/model/device_table.cpp:70` (definition) · `deviceInfo()` is declared plain
     `noexcept`, not `constexpr`. `SPEC-core-model.md`'s `device.h` Public API sketch reads
     `constexpr const DeviceInfo& deviceInfo(DeviceType t) noexcept;`, and the Plan's "Common to
     every Phase 1 task" clause (Gate-1-approved) says "Implement exactly the public API of
     `docs/spec/SPEC-core-model.md` for the headers named here" — this diff does not. Per
     `definition-of-done.md` (Library contract): "A public API change the spec does not describe
     is a blocker, raised to the leader."
     This is a real, well-reasoned technical finding, not carelessness: the developer's Dev notes
     document a genuine MSVC link failure (confirmed before/after), and re-deriving it independently
     during review, the root cause is a real contradiction inside the module spec itself —
     `device.h`'s sketch wants `deviceInfo()` `constexpr` and callable from any translation unit,
     while the same spec's "Project Structure" section deliberately keeps `kDeviceTable` and
     `deviceInfo()`'s body private to `device_table.cpp`, out of the header. A function whose
     compile-time-evaluable body is hidden in a different TU than its caller cannot be a true,
     standards-portable `constexpr` function — the two requirements cannot both hold. Dropping
     `constexpr` (keeping the file split, the O(1)/no-allocation contract and the doc comment) is
     very likely the right resolution.
     Marked blocker anyway because this is a public-API deviation that Gate 1 has not yet
     explicitly signed off on — Gate 1's 2026-09-27 approval predates the deviation being
     discovered during implementation, and a spec contradiction is resolved by the
     owner/leader, never silently by the developer alone (rules.md: "a spec changes only by owner
     decision"; DoD: never "a silent library change"). The developer already did the required part
     (recorded the deviation in Dev notes and raised it — this review is that raising reaching its
     destination). Resolution is expected to be procedural: leader/owner rules on it (most likely
     accepting non-`constexpr`, then amending `SPEC-core-model.md`'s `device.h` sketch and Project
     Structure note to stop contradicting each other) — no further code change is anticipated once
     that sign-off exists.
