## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the two Qt console programs of the Checkpoint D demo.
- **Approach:**
  - `examples/virtual_plc/main.cpp`: `QTcpServer` in front of `mc::MockPlc`
    (one mock per connection, sharing one memory image is not required —
    document what it does); arguments `--frame 3E --code Binary|ASCII
    --port N --set D100=1234 (repeatable) --wiggle D105 (repeatable, changes
    the device once a second)`. Serial (`QSerialPort`) arrives with T46 —
    reject a serial option with a clear message now.
  - `examples/qt_console_poller/main.cpp`: `McDevice` from arguments
    `--host --port --frame --code --sub D100:64 (repeatable)`; prints link
    states, round-1 snapshots, then each `valuesChanged`. An extra
    `--rounds N` option exits 0 after N rounds (1 on a link fault or
    `OpenFailed`) so the demo can be scripted; without it, it runs until
    Ctrl+C.
  - Both link `mc::device` + `mc::mock` (spec "Changes required" 1), built
    under `MC_BUILD_EXAMPLES` and `MC_BUILD_DEVICE`; `mc_apply_coverage` on
    both (build-env.md); qmake `.pro` files in `examples/qmake/` and in
    `examples.pro`.
  - Teaching code: short, commented where it matters (no blocking, signals).
- **Files expected to change:** `examples/virtual_plc/main.cpp`,
  `examples/qt_console_poller/main.cpp`, `examples/CMakeLists.txt`,
  `examples/qmake/examples.pro`, `examples/qmake/virtual_plc.pro`,
  `examples/qmake/qt_console_poller.pro`.
- **Acceptance criteria:**
  1. On one machine `virtual_plc --frame 3E --port 5000 --wiggle D105` and
     `qt_console_poller --host 127.0.0.1 --port 5000 --sub D100:64` show
     round-1 snapshots, then a change of D105 every second — run by the
     developer (MSVC build) as one scripted PowerShell call (start
     `virtual_plc`, run the poller with `--rounds`, stop `virtual_plc`),
     output quoted in Dev notes.
  2. Both build through qmake (`build/qmake-debug`).
  3. `mc_device` still links no `mc_mock` (BLD-05(d)).

## Dev notes  *(developer writes)*

- Files changed:
  - `examples/virtual_plc/main.cpp` (new): `QTcpServer` on 127.0.0.1 in front of `mc::MockPlc`; options `--frame 3E`, `--code Binary|ASCII`, `--port N`, `--set DEV=VALUE` (repeatable), `--wiggle DEV` (repeatable; a word counts up, a bit toggles, once a second, in every live connection), `--help`; `--serial` / `--baud` are recognised only to answer "not available yet" (exit 2); `--frame` other than 3E is refused (the mock answers only 3E). One mock per connection, all started from the same `--set` image, no shared memory (stated in the file header and in the usage text). No `Q_OBJECT`, no moc: plain lambdas.
  - `examples/qt_console_poller/main.cpp` (new): `McDevice` from `--host --port --frame --code --sub DEV:COUNT (repeatable) --rounds N`; prints link states (with reason and detail), the round-1 snapshot of each type (words as decimal rows of eight, bits as 0/1, failed chunks listed), then each `valuesChanged` as `changed D105: 5 -> 6 (round 9)`; `--rounds N` prints `done after N rounds`, calls `disconnectFromPlc()` and exits 0; a `linkFault` or a `Disconnected` whose reason is not `Requested` exits 1; without `--rounds` it runs until Ctrl+C. `connectToPlc()` is started from a `QTimer::singleShot(0)` so `QCoreApplication::exit()` always has a running loop. Comments explain no-blocking, the signals, and that the exit-on-fault policy is this program's own (decision 7).
  - `examples/CMakeLists.txt`: `if(MC_BUILD_DEVICE AND MC_BUILD_MOCK)` block: `find_package(Qt6 6.2 REQUIRED COMPONENTS Core Network SerialPort)` (imported Qt targets are directory-scoped, so this directory finds Qt itself), both executables link `mc::device` + `mc::mock`, `mc_apply_warnings`, `mc_apply_coverage`; the executables land in `build/<dir>/examples/` as the spec's commands show.
  - `examples/qmake/virtual_plc.pro`, `examples/qmake/qt_console_poller.pro` (new; `mc_device.pri` + `mc_mock.pri`, own intermediate dirs, not `testcase`), `examples/qmake/examples.pro` (entries).
