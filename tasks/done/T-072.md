## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the "HIL runner" row of the spec, on top of `mc_hil_tool`.
- **Approach:** load a profile and a plan; run the **unchanged** `mc_hil_tool` safety gate and
  show its report and the dry run; the confirmation dialog requires typing the profile id when the
  run contains `readOnly` frames (exactly like `hil_capture`; no GUI-only bypass); run the plan on a
  runner thread with live step outcomes; open the capture; run the replay; show the bench report.
  No real PLC in automated tests.
- **Acceptance criteria:** GUI-07 passes: the gate decisions and dry runs equal `hil_capture`'s on
  every committed plan and example profile; a refused plan sends nothing (loopback listener sees 0
  connections); the `readOnly` confirmation cannot be skipped; a run against a `MockRunner`
  produces a capture that replays green.
- **Gate 1 approval:** 2026-10-03 — leader (Phase 8 delegation). Common rules: `T-067.md`.

- How the run works: `HilView::check()` posts to the HIL runner thread, which runs `prepareHil()`; the GUI gets value copies (verdict, refusal text, dry run, confirmation text, read-only frames, a SHA-256 digest of dry run + confirmation). Run is enabled only after a passing check with unchanged inputs; it opens the dialog; the request carries paths, the digest, the typed id and the `--yes` flag. On the runner thread `HilRunner::run()` repeats `prepareHil()` (gate again), compares the digest (what was shown is what runs), applies `confirmationAccepted()`, applies the output rules (`checkOutputTarget`, loopback + "Real PLC" refused, existing folder needs "replace"), and only then builds `mc::hil::Runner` (its `McDevice` is born on the runner thread inside `Runner::run()`). The tool's console stream is a `QIODevice` that turns lines into `outputLine` / `stepOutcome` signals; its input stream blocks on `HilControl` until the GUI answers a prompt ("press Enter to continue") or the run is cancelled. A capture of a mock / virtual_plc gets `# source: mock` (resp. `virtual_plc`) in `steps.vec` and `session.vec`, `capture_source:` and "not hardware" in `run.meta`, written by `tagCaptureSource()` after the run (the tool writes `plc` for every record; `tools/hil_capture` stays untouched).
- Deviations from plan (+ reason):
  - Stop button (not named in the Plan): `HilControl::cancelRequested()` is checked in the `stepStarted` hook, which throws a private `RunCancelled` that ends `Runner::run()` between two steps. Reason: a plan can run for minutes against a real PLC and the runner thread cannot be interrupted any other way; closing a tab needs it. A cancelled run writes no capture (the half-created capture folder is removed when it did not exist before).
  - `RunnerBase::shutdownDeferred()` + `RunnerThread::shutdownOnThread()` (T-068 files, additive behaviour): `Runner::run()` spins nested event loops, so the thread's queued shutdown (which deletes the runner and calls `QThread::quit()`) would run inside the run. The shutdown now waits (20 ms retries) until the HIL runner is idle. Every other runner returns false, so their behaviour is unchanged (GUI-01/03/04 green).
  - The "confirm without typing" box (`--yes`) exists in the dialog for runs without read-only frames, as `hil_capture --yes` allows; with read-only frames it is not created. Plan said "exactly like hil_capture".
  - Source of a run is a choice in the view (default: loopback TCP host -> Mock PLC, else Real PLC), as in the capture panel of T-071; a "Real PLC" run against a loopback host is refused, a capture of a mock never goes under `tests/vectors/captured/`. An existing capture folder is refused unless "Replace an existing capture" is ticked (stricter than the CLI, which replaces).
  - The run test uses `tests/hil/e2e/plan_3e.json` without step E-10 (generated into the build tree): E-10 sends a truncated frame and reconnects, and a `MockRunner` serves all its clients with one parser (T-070 "Known limits"), so the half frame is still there after the reconnect (E-10.2 got `LengthMismatch`). `virtual_plc` gives each connection its own `MockPlc`. Consequence: a catalogue plan with truncated-frame steps (`recover: reconnect`) does not pass against a GUI mock tab; against `virtual_plc` or a PLC it does. A library-level fix is the same as the one T-070 named (per-client parser).
  - The replay button runs `mc_replay_tests --replay-root=<capture folder root> -tc="RPL-sweep: every*"` (same filter as T-071's tests) on the runner thread through `QProcess`; the program is searched next to `mc_workbench` and in the CMake / qmake build trees, editable in the view.
  - Not done: the run output is not fed into the Debug log dock or the trace dock (the HIL run uses its own transport); the HIL view settings are not saved (T-073 workspace).

- Notes for the tester:
  - Closing the window or the view during a run: `HilHost` cancels, the prompt is released, the run ends at the next step boundary, then the thread shuts down (`GUI_07_closingTheViewDuringARunStopsItWithinTheBound`). A step that outlasts the 3 s bound (e.g. a long poll on a real PLC) leaves the thread stuck and abandoned as for any runner; it ends by itself, the shutdown retries every 20 ms without spinning.
  - The cancel is at step granularity only: a single long step (a poll, a bench of many repetitions) runs to its end first.
  - Mutation ideas that should fail a test: skip the second `prepareHil()` in `HilRunner::run`; drop the digest comparison; let `confirmationAccepted` ignore the read-only list (done); skip `checkOutputTarget`; drop `tagCaptureSource`; create the `Runner` on the GUI thread.
  - Not covered by an automated test: the look of the view; the real `QFileDialog` browse buttons; `Open folder` (`QDesktopServices`); a serial profile (only the loopback TCP target is used; a COM-pair run would use the same code); a real PLC (never).
  - Env notes for `build-env.md`: a Qt `QIODevice` subclass can serve as `QTextStream` target for the tool's console and as a blocking input (`Unbuffered`, sequential) for the operator prompt; `QThread::quit()` called while a nested `QEventLoop` runs on that thread makes later `exec()` calls return at once (busy loops), so shutdown must not run inside a nested-loop job; PowerShell `Set-Content -NoNewline` round-trips ASCII sources fine for mutation tests; perl `-0pi` replacement with `\n` inside a `.pro` line continuation writes a literal `\n` again (use the Edit tool).
  - What is left for later tasks: the workspace (T-073) can save the HIL view inputs (`HilView::input()`, output root, source); the HIL run output is not in the Debug log dock; a per-client parser in the mock would remove the E-10 limitation.
