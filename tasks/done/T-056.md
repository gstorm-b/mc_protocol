## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `scripts/check.ps1` and `scripts/check.sh` use the PC's cores, as every other build
  already does (`agent-team/project/build-env.md`, "Parallel builds — always").
- **Owner permission (2026-10-02):** "Cho phép sửa script để build song song." Only the
  build/test commands change; the five stages, their names, their order, what each stage
  proves and the exit-code contract stay exactly as they are.
- **Approach:**
  - Job count: a parameter (`-Jobs` in `check.ps1`, an env var or option in `check.sh`),
    default the logical processor count (`[Environment]::ProcessorCount` / `nproc`).
  - `cmake --build <dir> --parallel <jobs>` in every CMake stage.
  - `ctest ... -j 8` (the value used everywhere, `build-env.md`); serial tests already carry
    `RESOURCE_LOCK mc_serial_pair`.
  - qmake stages, MSVC kit: `jom -j <jobs>` (and `jom -j <jobs> check`) when jom exists:
    `C:\Qt\Tools\QtCreator\bin\jom\jom.exe` or a `jom` on PATH; otherwise the current
    `nmake` with a one-line note that it runs single-threaded. MinGW kit (both scripts):
    `mingw32-make -j<jobs>`. The consumer-qmake stage the same.
  - Comment headers of both scripts updated to say the builds are parallel and how the job
    count is chosen.
- **Files expected to change:** `scripts/check.ps1`, `scripts/check.sh`, `CHANGELOG.md`
  (one line under Unreleased, or folded into the Phase 7 entry at T-064).
- **Acceptance criteria:**
  1. `scripts/check.ps1 -QtDir C:/Qt/6.11.1/msvc2022_64`, `scripts/check.ps1 -QtDir
     C:/Qt/6.11.1/mingw_64` and `sh scripts/check.sh C:/Qt/6.11.1/mingw_64` (Git Bash) each
     exit 0 with all 5 stages passed, run one after another (never two at once).
  2. Wall times recorded before/after. Before (batch 6c): check.ps1 MSVC 322–449 s, MinGW
     543 s, check.sh 397–529 s.
  3. The nmake fallback runs once (e.g. jom hidden from the script through its parameter
     or a temporary override, not by renaming anything under `C:\Qt`) and passes.
  4. A deliberately failing stage still stops the script with the same message and a
     non-zero exit code (one negative run per script on a scratch copy of the tree or
     with a broken argument; the real tree stays unchanged).
- **Verification commands:** the three runs in criterion 1, one after another.
- **Constraints:** never two check scripts or two builds of one folder at once; temp files in
  `build/_scratch-t056/`, never `%TEMP%`; nothing outside the project except reading the
  toolchain under `C:\Qt`; no commit.
- **Gate 1 approval:** 2026-10-02 — leader, under the owner's delegation extended to Phase 7
  (`rules.md`). Gate 2: leader, one commit for Phase 7 after Checkpoint F.
