## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the `mc_mock` target exists on CMake and qmake with the public
  `mock_plc.h`, a sparse memory image, device limits and the request log;
  `bytesIn`/`nextResponse` exist but may answer nothing yet (T-030 adds the
  3E server direction).
- **Approach:**
  - `include/mc/mock/mock_plc.h` exactly as the spec's "Public API" (types
    `MockOptions`, `Corruption`, `MockRequestRecord`, `MockPlc`), documented
    per `docs/rules/doc_comment_style.md`. Pimpl (or a private `Impl` in
    `src/mock`) so the public header needs no private include. Fault and
    corruption member functions are declared now; they may store state only
    (T-031 makes them act).
  - `src/mock/memory_image.h/.cpp`: sparse per-`DeviceType` pages; bit devices
    store single bits, and word access to a bit device sees bit i of word k at
    head + 16k + i (spec §2.4); unwritten memory reads 0; no aliasing;
    `setDeviceLimit` stored per type (a helper answers "does [head, head+n)
    reach the limit?").
  - `src/mock/mock_plc.cpp`: facade and request log (`requests()`,
    `clearLog()`, `eotCount()` returning 0 for Ethernet).
  - Build: `mc_mock` static library (alias `mc::mock`) in `src/CMakeLists.txt`,
    built when `MC_BUILD_MOCK`, links `mc::core`, `src/` private include, no
    Qt; add it to the pri-sync targets (the comment at `src/CMakeLists.txt`
    ~line 61 marks the spot); `mc_mock.pri` lists the same files (BLD-04);
    BLD-05 hygiene already covers `include/mc/mock` and `src/mock` — confirm
    it runs over them. Mirror whatever install/export `mc_core` has.
  - Tests: new binary `mc_mock_tests` (label `mock`, `tests/mock/main.cpp`,
    links `mc_test_vectors`, `MC_TESTS_SOURCE_DIR`), plus
    `tests/qmake/mc_mock_tests.pro` (own intermediate dirs, added to
    `tests/qmake/tests.pro`). With `MC_COVERAGE`, a
    `mc_coverage_report_mock` target over `mc_mock`'s objects, bar 90
    (spec), labelled `src/mock`.
- **Files expected to change:** `include/mc/mock/mock_plc.h`,
  `src/mock/memory_image.h/.cpp`, `src/mock/mock_plc.cpp`, `src/CMakeLists.txt`,
  `mc_mock.pri`, `tests/CMakeLists.txt`, `tests/mock/main.cpp`,
  `tests/mock/test_mock_memory.cpp`, `tests/qmake/mc_mock_tests.pro`,
  `tests/qmake/tests.pro`.
- **Acceptance criteria:**
  1. MCK-04: word write, bit write with odd count, word write to a bit device
     packs 16 points per word; bit and word views agree both ways.
  2. MCK-12 (memory side): `setDeviceLimit` — the range helper reports a range
     reaching the limit as out of range and one ending below it as in range
     (the out-of-range *response* is checked end-to-end in T-030).
  3. `mc_mock` builds without Qt on its include or link line; BLD-04 and
     BLD-05 green with `mc_mock` present.
  4. `mc_mock_tests` runs under ctest label `mock`; its qmake twin lists the
     same test cases.
- **Common to every Phase 4 task (T-029…T-033):**
  - `docs/spec/SPEC-mock-plc.md` is binding (Objective, Public API, Behaviour,
    Boundaries). "spec §N" there means `docs/mc_reference/mc-protocol-frame-spec.md`.
  - **Independence rule:** files under `src/mock/` include only `mc/core/*.h`
    and the private headers `core/protocol/hexascii.h`, `sumcheck.h`,
    `field_codec.h`, `device_encode.h`. Never `frame_*.h`, `command_*.h`,
    `serial_parser.h`, `McProtocol` or `Parser`. The server direction is
    written from the reference spec's tables, never by calling the client.
  - The mock is std-only, deterministic, no I/O, no clock, no thread, no
    exceptions across the public boundary; it may allocate.
  - "Ask first" (stop and report, do not decide): another private core
    header in `src/mock`, a changed `MockOptions` default, timing behaviour in
    the mock, any change to a public `mc/core` header.
  - Before writing code, check that the spec's sketches compile against the
    existing `mc/core` types (lesson T-007); report contradictions instead of
    choosing silently.
  - New sources go into CMake **and** the matching `.pri` (BLD-04); a new test
    binary gets its `tests/qmake/*.pro` (Definition of Done; `build-env.md`
    qmake gotchas). Test names start with the spec's test ID.
  - Verification (MSVC daily loop, `agent-team/project/build-env.md`), one
    PowerShell call:
    `. scripts/vsdev.ps1; cmake --build build/cmake-debug; ctest --test-dir build/cmake-debug -L "mock|integration|core_session|core_protocol|core_model|build" --output-on-failure`
    — MinGW, qmake and coverage run at Checkpoint C4 (T-034).
  - Phase-batched verification (`rules.md`): no tester or reviewer per task,

## Dev notes  *(developer writes)*

- Files changed:
  - `include/mc/mock/mock_plc.h` (new): `MockOptions`, `Corruption`, `MockRequestRecord`,
    `MockPlc` exactly as the spec's Public API, documented per `doc_comment_style.md`; pimpl
    (`std::unique_ptr<Impl>`) so no private header leaks; destructor and move operations added
    (out of line, see Deviations).
  - `src/mock/memory_image.h/.cpp` (new): sparse per-`DeviceType` pages (4096 points, one
    `uint16_t` per point/word), bit and word views of one memory, per-type limit and
    `outOfRange(type, first, pointCount)` helper (a point >= limit does not exist).
  - `src/mock/mock_plc.cpp` (new): `Impl` (config, memory, request log, EOT counter, stored
    faults / mute / corruption state, response queue), the memory API, `nextResponse`.
    `bytesIn` is an empty stub that recognises nothing; T-030 gives it the 3E server direction.
  - `src/CMakeLists.txt`: `mc_mock` static library (alias `mc::mock`) under `MC_BUILD_MOCK`,
    public include `include/`, private `src/`, links `mc::core` publicly, warnings, coverage;
    added to the pri-sync target list (guarded by `if(TARGET mc_mock)`).
  - `mc_mock.pri`: HEADERS/SOURCES of the same files (BLD-04).
  - `tests/CMakeLists.txt`: `mc_mock_tests` (label `mock`, ctest `mock.mc_mock_tests`, links
    `mc_test_vectors`, `MC_TESTS_SOURCE_DIR`, private `src/` path), `mc_coverage_report_mock`
    (bar 90, label `src/mock`, object dir `src/CMakeFiles/mc_mock.dir/mock`) under `MC_COVERAGE`
    with GCC.
  - `tests/mock/main.cpp`, `tests/mock/test_mock_memory.cpp` (new): MCK-04 (word write, odd bit
    write, word write to a bit device packs 16 points, both views agree, no aliasing, sparse
    pages, 2^32 edge) and MCK-12 memory side (range helper), plus a fresh-facade check.
  - `tests/qmake/mc_mock_tests.pro` (new, own intermediate dirs, `include(../../mc_mock.pri)`),
    `tests/qmake/tests.pro` (entry added).
- Deviations from plan (+ reason):
  - `MockPlc` got a declared destructor and move constructor / move assignment (all out of
    line) and deleted copy operations. The spec sketch shows none; a pimpl class needs an
    out-of-line destructor, and moves let a test rig hold it in a container. No sketch member
    changed.
  - Public `setBit/bit/setBits` on a word device: ignored / `false` (a word device has no bit
    view). The spec sketch is silent; documented in the header. T-030 must therefore decide what a
    bit-unit command on a word device does (see T-030 notes).
- Commands run / outcomes:
  - `. scripts/vsdev.ps1; cmake --build build/cmake-debug; ctest --test-dir build/cmake-debug -L "mock|integration|core_session|core_protocol|core_model|build" --output-on-failure`
    -> build clean (warnings as errors), 7/7 ctest entries passed (BLD-08, core_model,
    core_protocol, core_session, mock, BLD-04, BLD-05). `mc_mock_tests`: 13 test cases, 88
    assertions, all passed. `mc_sources.txt` lists the four `mc_mock` files; BLD-04 green.
  - Not run (planned for Checkpoint C4): MinGW, qmake, coverage.
- Env notes: none new.
- Notes for the tester:
  - `mc_mock_tests --list-test-cases` is the list to compare with the qmake twin (the qmake
    build of `mc_mock_tests.pro` was not run by the developer at T-029; see T-030/T-031 notes for
    whether it was).
  - `MC_BUILD_MOCK=OFF`: `mc_mock.pri` lists files while CMake has no `mc_mock` target, so
