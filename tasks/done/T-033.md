## Dev notes  *(developer writes)*

- Files changed:
  - `examples/session_loop/main.cpp` (new): the usage example of SPEC-core-session with its own
    `std::deque<uint8_t>` wires and `std::chrono::steady_clock`; includes only `mc/core/*.h` and
    `mc/mock/mock_plc.h` (no header under `tests/`). Subscribes D2000x4, M2000x16, X0x8; runs three
    rounds with a 50 ms cycle; prints round-1 snapshots (X, M, D), changes mock values after
    rounds 1 and 2, prints the resulting `ValuesChanged` and snapshots; `done after 3 rounds`,
    exit 0. Exits 1 on a `LinkFault` or after 5 s of wall time. Comments mark the drain contract
    (every input followed by a full drain) and the application's own wait until `nextDeadline()`.
  - `examples/CMakeLists.txt` (new): `session_loop` target (links `mc::mock`, `mc::core`), only
    under `MC_BUILD_MOCK`; runtime output in `<build>/examples/session_loop/`; smoke test

- Notes for the tester:
  - The example sleeps (`std::this_thread::sleep_for`) until `Session::nextDeadline()`: that is the
    application's own wait, as in the spec's usage example; the run takes about 0.1-0.15 s.
  - Output order within a round follows `DeviceType` order (X, M, D): a `ValuesChanged` precedes
    its own type's snapshot, and a type without changes prints only its snapshot.
  - The example changes the mock between rounds inside the program (after `CycleDone` of rounds 1
    and 2), so a run with fewer than three rounds would not show the second change.
  - The core-only configure was made without `-DMC_BUILD_TESTS=OFF`, so `build/cmake-core` also
    holds the test binaries (all built without Qt, `MC_BUILD_DEVICE=OFF`).
