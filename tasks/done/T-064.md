- **S1 · should-fix · `tests/hil/replay/replay_session.cpp:415-435` (`advanceTo`), 14-16 · the RPL-04

  replay ticks at `max(Session deadline, time of the next captured output)` and never compares the
  two. So a Session whose cycle interval or response timeout became shorter or longer, or that no
  longer waits at all, still emits the same frames in the same order at the capture's times: nothing

  say so in the file comment. Add a negative test with a fixture whose `cycleIntervalMs` in run.meta
  is changed (it must fail). Also "does not tick for a deadline when nothing is owed" means a Session
  that stopped faulting on a late response is invisible; that is accepted by the stall test, but name
  it in the comment.

**The rules as implemented** (`safety_gate.h` has the full text)

- One locator per family, one accounting loop. `commandsIn()` returns a `CommandHit` per command found:
  `locateQna` (3E/4E, Binary and ASCII, at every offset where a whole frame fits; at offset 0 also truncated, as long
  as the command is there), `locateE1` (1E, after each fixed-size read), `locateSerial` (every ENQ/STX; frame id `F9`
  = 3C with an 8-char route, `F8` = 4C with a 14-char route, no id = 1C with a 2-letter command; format 2 block number
  tried with and without). Ethernet profiles are searched for 3E/4E in both data codes whatever the profile says (and
  for 1E on a 1E profile); serial profiles for 3C, 4C and 1C whatever the profile says.
- `FrameGate` (one per raw/mutate operation, `readOnly` or not): `checkClaim` (a mutate of a write is never
  readOnly), `accountForCommands` (every hit is an allowed read, or - with `readOnly` it is refused outright - a write
  that a fresh mock decodes at that same offset, in the slice up to the next frame start, and whose points are checked
  against scratch; otherwise "(command not accounted for)" naming step, command and byte offset), `checkDecodedWrites`
  (the mock's own view, from every offset: second net), `checkCompleteness` (the old fragment rule: `readOnly` +
  `reconnect`/`eot`, listed for the prompt).
- Item 2: `checkOverride` compares the step's effective frame with the profile's. Raw and mutate: refused when
  `frame`, `code`, `format`, `sumCheck` or a routing key (`network pc io station stationNo selfStation`) differs.
  Any other step that writes (write, `then` write, poll heartbeat or write action, bench write or poll set): refused
  when a routing key differs. Every other key stays allowed, a key that keeps the profile's value is not refused; the
  set is listed in `plan.h` and `safety_gate.h`. Reads may change the routing (G8-Q5).
- Item 3 (F2): a 1E first byte above 3CH (or a non-hex ASCII one) is "no command", and admitted as a fragment only when
  the rest of the bytes is no longer than one read request (12 bytes, 24 characters); longer, it is refused as a
  command of its own (the 1E write behind one junk byte is 14 bytes at the least). Item 4 (A09): a frame cut off right
  after its command is located and refused (readOnly: allow-list; not readOnly: not accounted for). Item 5: `plan.h`
  comment fixed; the 3CH bound is cited to the reference spec's scope line (`mc-protocol-frame-spec.md` 0.1).
- Documented residual risk (`safety_gate.h`): the mock decodes like the reference model, not like one PLC; route
  fields inside hand-written frame bytes are not compared with the profile's (the override keys, the documented way,
  are refused); a 1E frame on a 3E/4E/serial profile and binary format 5 are not searched (those ports take none;
  the profile loader rejects format 5); a garbled frame start shows no command and is a fragment; write data that looks
  like a frame start can make a legitimate frame be refused, never admitted.
