## Dev notes  *(developer writes)*

- Files changed:
  - `tests/core/session/test_session_fault.cpp` — `expectedHandlerCalls(n)` (n in Debug, 0 under NDEBUG) replaces the hard-coded `== 1` (:370) and `== cycles` (:436).   - `tests/common/alloc_counter.h` — (1) local `#pragma GCC diagnostic ignored "-Wmismatched-new-delete"` around the six plain `operator delete` forms, GCC only, with the reason in a comment; (2) new `probeAllocCount()` (new through a volatile pointer, so it cannot be elided).
  - `tests/core/model/test_alloc.cpp`, `tests/core/protocol/test_alloc.cpp`, `tests/core/session/test_alloc.cpp` — the "counter is live" positive control calls `probeAllocCount()`.
  - `tools/mc_workbench/CMakeLists.txt` — MSVC only: `/wd4702` on the vendored target `qpb_widgets` (Release C4702 inside Qt's `qnumeric.h`, reached from qpb `Int64SpinBox.cpp`).
  - `tools/CMakeLists.txt` — `MAP_IMPORTED_CONFIG_RELWITHDEBINFO/MINSIZEREL "RELEASE;DEBUG"` on `ads::qtadvanceddocking-qt6`.
  - `CMakeUserPresets.json.example` and local `CMakeUserPresets.json` — `msvc-release` / `mingw-release` (configure, build, test presets; `mc-release` base, same paths as debug).
- Causes:
  1. MSVC drain tests: `notifyDrainViolation()` is a no-op under NDEBUG, so the recording handler is never called in Release; the tests asserted the Debug count. Library behaviour is as the T-026 decision says (verified in `drain_violation.cpp`, `session.cpp`); only the tests were wrong.
  2. MinGW `-O3` `-Werror=mismatched-new-delete` (:73, sized `operator delete` -> `free`): GCC inlines the vector's `operator new` (malloc) and the replaced delete (free) into one function and flags the pair. The helper is correct (new=malloc, delete=free; aligned forms=_aligned_malloc/_aligned_free), so a local suppression is the fix, not a code change.
  3. Found after 2 — MinGW Release: the three "positive control: the counter is live" tests read 0. GCC -O3 elides the unobserved `new int(42)`/`delete` pair (allowed by C++14). Fixed with `probeAllocCount()`.
  4. Found: MSVC Release warning C4702 in `qnumeric.h` (qpb). Fixed per target, see above.
  5. Found: RelWithDebInfo MSVC GUI test hangs ("QWidget: Must construct a QApplication before a QWidget"): CMake picked the first imported config of ADS (Debug, `qtadvanceddocking-qt6d.lib`) next to release Qt. Fixed with the config mapping (build files only).
