- **Background:** `docs/spec/SPEC-gui-tool.md`, amended 2026-10-12; this decision supersedes the owner's decision C of 2026-10-04. The contract is:
  - the "HIL runner" row;
  - GUI-07;
  - the "Always" boundary.

  Today `HilConfirmDialog` (`tools/mc_workbench/hil_confirm_dialog.h/.cpp`) asks for the typed profile id. It offers a "confirm without typing" box only for a loopback profile with no `readOnly` frames, and `confirmationAccepted(...)` decides.
- **Goal:** for every profile (loopback, other host, COM port; `readOnly` frames or not), a run starts after the user presses **Confirm** in the dialog. The dialog shows:
  - the profile id;
  - the endpoint (host:port, or COM port with its line settings);
  - the scratch areas;
  - the dry-run summary.

  Cancel or closing the dialog sends nothing. The safety gate itself is **unchanged**: a refused plan shows its refusal, offers no Confirm, and sends nothing.
- **Approach:**
  1. **`HilConfirmDialog`:**
     - Remove the line edit, the "confirm without typing" box and their API: `typedId`, `setTypedId`, `skipTyping`, `hasSkipBox` or the equivalent; check the header.
     - The OK button is labelled **Confirm** and is enabled whenever the check passed.
     - Show the endpoint and scratch areas if the dialog does not already show them; take them from the prepared check or profile the dialog already receives.
     - Keep the dialog's other content.
  2. **`confirmationAccepted(...)` and anything in `hil_prepare` / `hil_runner` / `hil_view` that re-checks the typed id before `runTool()`:** simplify to "the gate passed and the user confirmed". Grep for every caller. No path may run a plan without the dialog's Confirm. A refused plan never reaches the dialog's Confirm.
  3. **`tools/hil_capture` (CLI) is not changed:** its prompt and `--yes` stay as they are. Say so in the Dev notes; the owner asked about the workbench.
  4. **Tests** (`tests/gui/tst_gui_hil.cpp`, plus probes such as `tst_gui_tester_probes.cpp` that drive the dialog). Adapt the GUI-07 tests to the amended row:
     - Confirm starts the run for a loopback profile, a non-loopback TCP profile and a COM profile, each with and without `readOnly` frames, using the existing fixtures and runs against `virtual_plc` / mocks only;
     - Cancel or close sends nothing (assert zero bytes, or the runner not started, as the existing tests do);
     - a refused plan offers no Confirm and sends nothing;
     - the gate decisions identical to `hil_capture` (dry runs) stay unchanged.

     Remove or rewrite only the assertions about typing and the skip box, and list each one in the Dev notes.
  5. **Docs:** if the workbench README or the help text mentions typing the id, update it.
