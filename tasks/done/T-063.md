## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the machine form of `docs/hil/COMMAND-CATALOGUE.md`, one plan per frame family,
  with identical step ids.
- **Approach:**
  - `tests/hil/plans/qna_ethernet.json` (3E), `a1e.json` (1E), `qna_serial.json` (3C),
    `a1c.json` (1C), in the schema of T-057. Every catalogue step id appears in exactly one
    plan; device references relative to the profile (`@s`, `@end`, `specialBit` /
    `specialWord` for G1-09, G2-10, G3-04); `mirrors` set on `GV` steps.
  - The catalogue is the source; do not edit it. A step the plan schema cannot express, or
    a catalogue ambiguity, is listed in Dev notes for the leader (it may become an owner
    question), not silently changed.
  - Test: parses the catalogue's step ids from the markdown and checks each appears in
    exactly one plan and no plan has an id the catalogue lacks; each plan passes
    `--dry-run` (gate included) against the matching example profile.
- **Files expected to change:** the four plan files, the test source.
- **Acceptance criteria:**
  1. Every catalogue step id appears in exactly one plan (test), and no extra ids.
  2. Each plan passes `--dry-run` against a matching example profile (four dry runs in a
     test; outputs summarised in Dev notes).
  3. At least the 3E and 3C plans run end-to-end against `virtual_plc` without a tool
     error (outcomes may be `plcError`/`notSupported` where the mock lacks a command;
     list them).
- **Gate 1 approval:** 2026-10-02 — leader, under the owner's delegation extended to Phase 7
  (`rules.md`). Common rules and decisions D1–D5: `tasks/active/T-057.md`.
