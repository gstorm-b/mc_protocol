## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** every byte on the wire is recorded with a monotonic nanosecond stamp, and the
  capture files of spec "Output" are written in formats the shared loader reads unchanged.
- **Approach:**
  - `recording_transport.h/.cpp`: a `Transport` decorator over the real `TcpTransport` /
    `SerialTransport` (public `Transport` interface only, D1). Stamps every written chunk
    and every received chunk with `QElapsedTimer::nsecsElapsed()` from one clock shared by
    the whole run; forwards every signal and call unchanged (including
    `lastLossWasPeerClose()`). It must also let `mutate`/`raw` steps send on the same
    recording while `McDevice` is not using the transport (spec "The capture tool"):
    design how, within D1, and explain it in Dev notes.
  - `capture_writer.h/.cpp`:
    - `steps.vec`: one request + one response record per api/mutate/raw step, `.vec` format
      of `SPEC-core-protocol.md` with the spec's extra keys (`source`, `profile`, `step`,
      `mirrors`, `frame`, `code`, `op`, `device`, `count`, `kind`, `of`, `outcome`, `expect`,
      `ttfb_ms`, `rx_ms`, `rtt_ms`); `kind: response-partial` for a timeout that received
      part of a frame; the `outcome` spellings of spec "Output".
    - `session.vec`: the poll step's transcript (tx/rx chunks with times, then events).
    - `run.meta`: `key: value` lines — tool and library version, git commit, date, operator
      note, PLC state, profile identity, scratch area, `deviceEnd`, serial line settings,
      and **every** `FrameConfig` and `SessionConfig` field; **never** an IP address, TCP
      port or COM port name.
    - `bench.csv` with the spec's columns (rows come in T-062).
    - Re-running a profile replaces its folder (under the output root, D3).
  - `tests/common/vectors.h` is read as is; if it cannot read a written file, stop and
    report rather than changing it.
- **Files expected to change:** `tools/hil_capture/recording_transport.h/.cpp`,
  `capture_writer.h/.cpp`, the test source, CMake + qmake source lists.
- **Acceptance criteria:**
  1. HIL-05: files written by the capture writer are read back by
     `tests/common/vectors.h` with every metadata key and value intact (round-trip test
     over every key the writer emits, including `response-partial`).
  2. `run.meta` contains every `FrameConfig` and `SessionConfig` field (the test enumerates
     the fields independently, e.g. from a list kept next to the test, and fails when one
     is missing) and none of the profile's host, port or COM name strings.
  3. `RecordingTransport` stamps are monotonic, every chunk in both directions is recorded
     once, and signals pass through (tested over a loopback `TcpTransport`).
- **Gate 1 approval:** 2026-10-02 — leader, under the owner's delegation extended to Phase 7
  (`rules.md`). Common rules and decisions D1–D5: `tasks/active/T-057.md`.

- Design: how `mutate`/`raw` send on the same recording while `McDevice` is not using the transport (within D1).
  - `McDevice` owns the `RecordingTransport` (injected through the existing `McDevice(cfg, std::unique_ptr<Transport>)`); the runner keeps a non-owning pointer to it. The decorator drains the wrapped transport itself on `readyRead`, stamps the chunk once, and hands bytes out through its own `read()`. So one stamp per arrival, whoever reads.
  - **Raw mode** (`setRawMode(true)`): a mutate or raw step writes with `RecordingTransport::write()` (recorded, same clock) and the responses are kept and announced with the extra signal `rawReadyRead()` instead of `readyRead()`. `McDevice`'s `Session` never sees them (an unsolicited response in an idle `Session` is a link fault). The runner reads with `read()` / `takeRaw()`. `setRawMode(false)` drops what the runner left unread (it stays in the recording). `opened`, `openFailed` and `lost` always pass through, so a link loss during a raw step still reaches `McDevice`.
  - Chosen over disconnecting `McDevice` (which closes the socket for every probe and would hide connection-level effects such as an `Ethernet` peer reacting to a half frame).
- Format decisions (spec "Output" is silent on these; read the header comment):
  - **A `.vec` record needs at least one byte** (the loader refuses a record with no hex line). So when no byte came back (timeout, noResponse) there is no response record and the request record carries `outcome`, `expect` and `waited_ms`; when nothing was sent (`notSent`: the library refused the request) there is no record at all and `run.meta` lists it as `notsent.<id>: <error>`. Skipped steps are `skipped.<id>: <reason>` in `run.meta`.
  - Every frame exchange is one request record (+ response record); a step's later operations are `<id>.2`, ... and the later frames of an operation split into several commands `<id>+2`, ... Extra keys beyond the spec's list: `via` (`api` | `mutate` | `raw`; only `api` is re-encodable from metadata), `format` (serial), `waited_ms`.
  - `session.vec`: wire chunks first, then events; every record has `t_ns` and `seq` (one counter over both); an event's hex line is a tag byte plus little-endian data because a record cannot be empty (tags 01 snapshot, 02 valuesChanged, 03 cycleDone, 04 requestFinished, 05 linkState, 06 linkFault; layouts in the header). The endpoint text of `linkStateChanged` is left out (it holds an address). The cycle durations of T-062 are the `duration_ms` key of the `cycleDone` events.
  - `run.meta`: `frame.<key>` and `session.<key>` for every field, taken from the library's own JSON mapping of `McDeviceConfig` (so spellings are the ones of SPEC-qt-device: `Binary`, `Ascii`, `Format4`, `FixedRate`, `true`, `session.heartbeat.device`); `tcp` settings are never written, `serial.*` carries the line settings without the port name. Also written: `special_bit`, `special_word`, `device_end` (`D=12287 W=1FFF`, DeviceType order), `supports`, `scratch`, `git_commit`, `date`, `operator_note`, `plc_state`, `plc_state_note` (the profile's text).
  - `CaptureWriter::prepare()` replaces the folder but keeps the owner-maintained `divergences.txt` (the spec says a re-run replaces the folder and `divergences.txt` is owner-maintained; deleting the owner's tags on every re-run seemed wrong; say if you want it deleted). It refuses a profile id that is not a folder name before it deletes anything.
- Deviations from the Plan: none beyond the above format decisions; `tests/common/vectors.h` reads every written file unchanged (HIL-05 loads both files).
- Commands run / outcomes (MSVC, `build/cmake-debug`; `--parallel 32`, `ctest -j 8`):
  - `cmake --build build/cmake-debug --parallel 32`: warning-free (`/W4 /WX`).
  - `ctest -L hil_tool`: 1 entry, 101 test cases (71 profile/plan + 21 gate + 9 capture), 0 failures. The full verification command is re-run at the end of T-060.
  - qmake (MSVC, `build/qmake-debug`, stale Makefiles deleted first): `mc_hil_tool_tests.exe` 101 passed, same as CMake.
- Notes for the tester:
  - The round-trip test checks, key by key, the first request, its response, a `response-partial`, a PLC error with its information block, a request that got no byte back, a raw frame, a serial frame, a split-frame suffix `+2` and the absence of a record for `notSent`; then it compares the set of keys found in the loaded file with the documented key set (nothing undocumented is written, every documented key was exercised).
  - `run.meta` is checked against two lists of field names kept in the test (27 `FrameConfig` fields, 12 `SessionConfig` fields), independent of the writer; a profile with `192.0.2.77`, port `40123` and `COM77` must leave none of the three in the file (a TCP profile with another host and port too).
  - The transport test uses a loopback `QTcpServer`; the sending socket flushes from the event loop, so it waits with `QTRY_*`. `waitForNewConnection()` returns false when the event loop already took the connection (use `hasPendingConnections()` first).
  - Mutation ideas: drop one `frame.*` line, write the tcp host, make `read()` stamp a second chunk, make raw mode emit `readyRead()`.
