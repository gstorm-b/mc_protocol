## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** every Qt part except the GUI builds and passes its tests with **Qt 5.15**:
  - the library parts: `mc_device`, examples, the Qt test binaries and their consumer smokes;
  - the tool `tools/hil_capture` (`mc_hil_tool`, `hil_capture`, `hil_fault_proxy`).

  This holds for CMake and qmake. Qt 6 stays fully supported and unchanged in behaviour.
- **Environment (leader checked C:\Qt with the owner's permission, 2026-10-07):**
  - Qt **5.15.0** is installed with the **`msvc2019_64`** kit only, at `C:\Qt\5.15.0\msvc2019_64`. Core, Network, SerialPort, Test and Widgets are present.
  - No Qt5 MinGW kit is installed, so **Qt 5.15 is verified on MSVC only** (VS 2026 cl with the msvc2019 kit; the ABI is compatible). If the owner later installs `mingw81_64`, add it as a follow-up.
- **Spec and rule amendments.** The owner decided the Qt 5.15 scope. The leader writes these at Gate 1 and the owner sees them in the batch report:
  - `SPEC-build-packaging.md` (Qt row): Qt **5.15 or 6.2+**;
  - `SPEC-qt-device.md` (dependency row): the same;
  - `rules.md` and `definition-of-done.md`: the API surface becomes "Qt 5.15 **and** Qt 6.2". Code must compile on both, with Qt 6 deprecations still clean;
  - `README.md`.
- **Approach:**
  1. **CMake:**
     - `find_package(QT NAMES Qt6 Qt5 …)`, then `find_package(Qt${QT_VERSION_MAJOR} …)` with a 5.15 or 6.2 minimum.
     - Link the versionless `Qt::Core`, `Qt::Network`, `Qt::SerialPort` and `Qt::Test` targets, which Qt 5.15 provides.
     - An option or cache variable lets a Qt6 machine force Qt5 (`-DMC_QT_MAJOR=5`). `CMAKE_PREFIX_PATH` alone must also work.
     - The installed `mcConfig.cmake` finds the same major version. Consumer smokes run on both.
  2. **qmake:** the `.pri`/`.pro` files work with the Qt 5.15 `qmake.exe`, including the subdirs, the test `.pro`s and `mc_gui_deps.pri`. On Qt5, `mc_gui_deps.pri` skips the GUI with a message until T-079 lands.
  3. **Source portability** in `src/device`, `examples`, `tests/device` and `tools/hil_capture`:
     - replace Qt 6-only APIs (`qsizetype` overloads, `QStringView` gaps, `QMetaType` / `qRegisterMetaType` differences, `QSerialPort` / `QAbstractSocket` signal names such as `errorOccurred`, `QTest` 6-only macros) with forms valid in both;
     - use `QT_VERSION_CHECK` only where no common form exists;
     - every place needing `QT_VERSION_CHECK` is listed in the Dev notes.
  4. **Presets:** add `qt5-msvc-debug` and `qt5-msvc-release` (Qt 5.15.0 msvc2019_64; no ADS until T-079) to `CMakeUserPresets.json.example` and the local `CMakeUserPresets.json`. Agents build Qt5 trees in `build/cmake-qt5-msvc*` (`--preset … -B`), never in `build/qtc-*`.
  5. **Check scripts:** `scripts/check.ps1 -QtDir C:/Qt/5.15.0/msvc2019_64` runs green, with the GUI skipped by message. Add Qt5 stages to the scripts only if the plain `-QtDir` call cannot do it.
- **Acceptance criteria:**
  - Qt 5.15 MSVC Debug and Release: build warning-free with `MC_WARNINGS_AS_ERRORS`, and full ctest green. Every label runs except `gui` (skipped with the message).
  - qmake with the Qt 5.15 kit: `jom -j 32` and `check` green, with the same test-case lists as CMake.
  - `check.ps1 -QtDir C:/Qt/5.15.0/msvc2019_64` green.
  - Qt 6 (MSVC and MinGW, Debug and Release, CMake and qmake) unchanged and green. `check.ps1` (both Qt 6 kits) and `check.sh` stay green.
  - No golden vector or test assertion weakened. Behaviour is identical on both Qt majors: the same tests, with no Qt-5-only skips except the GUI.
