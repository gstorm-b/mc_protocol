## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the incremental receive parser for serial formats 1–4 (spec §6.3), shared by 3C and 1C.
- **Approach:**
  - `src/core/protocol/serial_parser.h/.cpp`: start on STX / ACK / NAK (format-dependent), junk before the start counted and reported through `skipped()`; ETX scan over **new bytes only** (no rescan, O(n) total); SUM after ETX when enabled; `CR LF` for F4; F2 block number; F3 `QACK`/`QNAK` (3C) and `GG`/`NN` (1C) forms incl. short responses and `f3ShortResponseHasSum`. No allocation, no exceptions.
  - Synthetic frames built in the tests from the spec's format table (the golden vectors come in T-046…T-049); every response kind of every format fed byte-at-a-time and whole.
- **Files expected to change:** `src/core/protocol/serial_parser.h/.cpp`, `src/CMakeLists.txt`, `mc_core.pri`, `tests/core/protocol/test_serial_parser.cpp`, `tests/CMakeLists.txt`, `tests/qmake/mc_core_protocol_tests.pro`.
- **Acceptance criteria:**
  1. Synthetic frames for every format (1–4) and response kind (with data, without data, error; F3 short forms with and without SUM) parse byte-at-a-time and whole, identically.
  2. STR-03: junk before the start is skipped and reported in `skipped()`.
  3. STR-04 passes for serial.
  4. No allocation in the parser (extend ALC-01 once the frames exist; here: an allocation-counter check over the synthetic set).
- **Common to every Phase 6 task:** see `tasks/done/T-041.md` "Common to every Phase 6 task" (binding: specs, public headers ask-first, golden-vector rules, independence rule, zero allocation, coverage bars, BLD-04, verification command, batch-level verification). Serial-frame source of truth: `SPEC-core-protocol.md` "Frames 3C and 1C, formats 1–4", "Error mapping", test table; reference spec §2.5, §2.7, §5.4–§5.6, §6.3 and Appendix A.7–A.19.

## Dev notes  *(developer writes)*

- Files changed:
  - `src/core/protocol/serial_parser.h` / `.cpp` (new): `serialFeed(params, buffer, cursor, frame, error)`,
    the spec 6.3 state machine. Start byte STX/ACK/NAK (Format 3: STX only), junk counted in
    `cursor.skipped`; ETX scan resumes at `cursor.scanned` (new bytes only; while SUM / CR LF are
    missing `scanned` rests on the ETX, so the body is never re-read); SUM (when enabled) read and
    verified over "after STX through ETX" (the same range in all four formats); F4 CR LF; ACK / NAK
    of fixed length; Format 3 classified by its end code (`QACK`/`QNAK`, 1C `GG`/`NN`) with the short
    forms carrying a SUM only under `f3ShortResponseHasSum`. It returns the layout of the frame
    (`SerialFrame`: kind, block / route / data offsets, `end`); judging frame ID, route, block,
    data size and the PLC error code is left to `frame_serial` (T-046). Also `SerialParams`,
    `serialParamsOf(cfg)`, `serialRouteSize/CodeSize/BlockSize/DataOffset`.
  - `src/CMakeLists.txt`, `mc_core.pri`: `serial_parser.cpp/.h`.
  - `tests/core/protocol/test_serial_parser.cpp` (new): SER-01..13, STR-03 and STR-04 for serial.
  - `tests/core/protocol/serial_synthetic.h` (new, test helper): builds the synthetic frame set (96
    frames: 3C and 1C x formats 1-4 x sum on/off x Data (2 lengths) / Ack / Nak, Format 3 with and
    without a SUM on the short forms, Format 2 with two block numbers), with its own sum loop and
    the layout it laid out itself.
  - `tests/core/protocol/test_alloc.cpp`: two ALC-01 cases over the synthetic set (byte-at-a-time
    feed of all 96 frames; junk, wrong SUM and a short Format 3 body).
  - `tests/CMakeLists.txt`, `tests/qmake/mc_core_protocol_tests.pro`: `test_serial_parser.cpp`
    (and `serial_synthetic.h` in the qmake HEADERS).
- Deviations from plan (+ reason):
  - `test_alloc.cpp` is not in the Plan's file list; the Plan's criterion 4 asks for an allocation
    check "over the synthetic set", and only that file may include `alloc_counter.h`
    (duplicate symbols otherwise). `serial_synthetic.h` is the shared helper so the set is built once.
  - The incremental cursor is NOT a new `Parser` member: `include/mc/core/protocol.h` has no cursor
    field and adding one is a public-header change (Ask first). `serialFeed` therefore takes a
    `SerialCursor{scanned, skipped}` of its own; T-046 stores it in the two existing `Parser`
    members `m_frameLength` (scan position, only while `NeedMore`) and `m_skipped`, which
    `frameLength()` documents as valid only after Done/Failed. If a dedicated `m_cursor` member is
    preferred it is a one-line private-member addition to `protocol.h` (owner call).
  - No bound on how long the parser waits for an ETX that never comes (neither the plan nor the spec
    names one); the caller's timeout and `maxResponseSize()` are the limit. Raise it if a cap is wanted.
  - Parser-level error choices the spec table does not list (recorded, tested): a Format 4 frame not
    ending in CR LF, a Format 3 end code that is neither expected string, and a body too short for
    `P` (+ end code) map to `FrameMismatch` / `FrameMismatch` / `LengthMismatch`; a wrong SUM is
    judged before the body-size check of Formats 1, 2, 4, but after the end-code classification of
    Format 3 (the classification decides whether a SUM follows at all).
- Commands run / outcomes:
  - `. scripts/vsdev.ps1; cmake --build build/cmake-debug` (auto re-configure for the new files):
    clean, zero warnings (`MC_WARNINGS_AS_ERRORS` on in that tree).
  - The common verification command (`ctest -L "device|mock|integration|core_session|core_protocol|
    core_model|build"`): 30/30 passed. `mc_core_protocol_tests`: 68 doctest cases, 21489 assertions,
    0 failed (was 50 cases before this task; 18 new cases incl. 2 ALC-01).
  - Mutation checks (restored and rebuilt afterwards, green): ETX scan restarting at the body start
    instead of the cursor fails SER-03 (and proves the probe can tell a rescan from a resume); SUM
    range one byte short makes the binary fail (exit 255; the synthetic-set cases, I did not list
    each one).
- Env notes: none new.
- Notes for the tester:
  - Not run by me: MinGW, qmake, `scripts/check.ps1`, coverage (batch checkpoint). `mc_core.pri` and
    `tests/qmake/mc_core_protocol_tests.pro` changed: delete the qmake `Makefile.*` per
    `build-env.md` and compare `--list-test-cases` with the CMake binary.
  - `serialFeed` is tested directly through the private header (like `test_commands.cpp` does for the

  - SER-13 holds the spec's own A.12-A.19 response frames with the layout offsets worked out by
