## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the `mc_device` target exists on CMake and qmake with the abstract
  `Transport`, a working `TcpTransport` and the meta-type registration; the
  QtTest infrastructure for label `device` is in place.
- **Approach:**
  - `include/mc/device/transport.h` exactly as the spec's sketch;
    `tcp_transport.h` (`TcpSettings`, `TcpTransport`) and
    `src/device/tcp_transport.cpp`: `QTcpSocket`, async `connectToHost`,
    connect timeout as a single-shot `QTimer` (`connectTimeoutMs`),
    `LowDelayOption` and `KeepAliveOption` set once connected; exactly one of
    `opened()`/`openFailed()` per `open()` unless `close()` comes first;
    `lost()` on peer close or error while `Open`, never after `close()`;
    `read()` non-blocking. `describe()` → `"host:port"`.
  - `include/mc/device/meta_types.h` + `src/device/meta_types.cpp`:
    `Q_DECLARE_METATYPE` for every type the spec's signals carry that exists by
    now, and `registerMetaTypes()` (idempotent); later tasks add their types
    to the same place.
  - Build: `mc_device` library (alias `mc::device`) under `MC_BUILD_DEVICE`,
    `AUTOMOC ON`, links `mc::core` and `Qt6::Core Network SerialPort` only
    (never `mc_mock`); its source list is a variable defined and exported to
    `mc_sources.txt` **even when `MC_BUILD_DEVICE=OFF`** (the comment at
    `src/CMakeLists.txt` ~line 93; lesson T-034), and the BLD-05(d)
    link-library export at ~line 116 now applies. `mc_device.pri` lists the
    same files (BLD-04).
  - Tests (QtTest, label `device`): `tests/device/tst_tcp_transport.cpp`
    against a local `QTcpServer` on `127.0.0.1` with an OS-chosen port. Each
    QtTest binary gets its `tests/qmake/*.pro` (own intermediate dirs,
    `QT += testlib network`). ctest must find the Qt DLLs: set the test's
    `ENVIRONMENT`/`ENVIRONMENT_MODIFICATION` PATH to the Qt `bin` of the kit
    (write the pattern into Env notes).
  - A ctest script check `QDV-HYG` (label `device`): no `waitFor`,
    `QEventLoop`, `QThread` or `QMutex` token in `src/device`
    (spec success criterion 2), with a negative control on a fixture, like
    MCK-HYG.
- **Files expected to change:** `include/mc/device/transport.h`,
  `tcp_transport.h`, `meta_types.h`, `src/device/tcp_transport.cpp`,
  `meta_types.cpp`, `src/CMakeLists.txt`, `mc_device.pri`,
  `tests/CMakeLists.txt`, `tests/device/tst_tcp_transport.cpp`,
  `tests/device/check_device_tokens.cmake` (+ fixture),
  `tests/qmake/*.pro`, `tests/qmake/tests.pro`.
- **Acceptance criteria:**
  1. QDV-12: the connected socket has `LowDelayOption` and `KeepAliveOption`.
  2. Transport-level part of QDV-06: `open()` to a port nobody listens on
     emits `openFailed` within `connectTimeoutMs + 500 ms`; one signal only.
  3. `opened`/`lost`/`close` contract: peer close → one `lost()`;
     `close()` → no signal afterwards; bytes written arrive at the server and
     bytes sent back come out of `read()`.
  4. `QDV-HYG` green, its negative control proves it bites.
  5. `mc_device` links no `mc_mock` (BLD-05(d) active and green); a configure
     with `-DMC_BUILD_DEVICE=OFF` still passes BLD-04 and never searches Qt.
  6. Each new QtTest binary's qmake twin lists the same test functions
     (`-functions`).
- **Common to every Phase 5 task (T-035…T-039):**
  - `docs/spec/SPEC-qt-device.md` is binding (Objective, Public API,
    Behaviour, Boundaries). `McDevice` is a thin adapter: protocol behaviour
    stays in `Session`; `src/core` is not changed in this phase (a needed core
    change → stop and report).
  - **Qt 6.2 API minimum** (owner decision, enforced by review): use only
    APIs available in Qt 6.2 even though Qt 6.11 is installed; when unsure,
    check the class docs' "since" note and list any borderline API in Dev notes.
  - **Never:** block (`waitFor*`, nested event loop), start a thread or take a
    mutex in the library, emit a signal while the `Session` holds undrained
    outputs, link `mc::mock` into `mc_device`.
  - **Ask first** (stop and report, do not decide): a new signal,
    `LinkState`/`LinkReason` value or config key; any automatic reconnect;
    installing virtual COM software; a change to a public `mc/core` or
    `mc/mock` header; a spec contradiction.
  - Before writing code, check that the spec's sketches compile against the
    existing `mc/core` types (lesson T-007).
  - Tests: QtTest, label `device`, loopback `127.0.0.1` with OS-chosen ports,
    **no fixed sleeps** — wait on signals (`QSignalSpy::wait`, `QTRY_*`) with
    bounded timeouts. A timing-sensitive test is run 20 times in a row before
    hand-back (report the command); flakiness is a defect.
  - New sources in CMake **and** the `.pri` (BLD-04); every test binary gets
    its qmake twin (Definition of Done; `build-env.md` qmake gotchas). Test
    function names start with the spec's test ID. Public headers follow
    `docs/rules/doc_comment_style.md`.
  - Verification (MSVC daily loop, `agent-team/project/build-env.md`), one

- Deviations from plan (+ reason):
  - The test binary is named `mc_tcp_transport_tests` (one QtTest binary per `tst_*.cpp`, each with its own `QTEST_GUILESS_MAIN`), not the spec text's single `mc_device_tests`: the spec lists several `tst_*.cpp` files and QtTest allows one main per binary. `mc_device_tests` stays free for T-037 (`tst_mc_device.cpp`); `mc_add_qt_test()` is the pattern for later binaries.
  - The device test block is under `MC_BUILD_DEVICE` only (the spec table also demands `MC_BUILD_MOCK` for `mc_device_tests`); these tests use no mock. T-037's mock-linking binary must sit under both options.
  - QDV-HYG also forbids `QMutexLocker`, `std::mutex`, `std::thread` (the spec names four tokens; Boundaries say "no thread, no mutex"). Whole-word match over the whole file, comments included. It scans `src/device` only, as the Plan says (not `include/mc/device`).
  - `TcpTransport` defers an `openFailed` that Qt raises from inside `connectToHost()` to the event loop (`m_inOpen` + a generation counter), and the `lost()` that follows a failed `write()` likewise ("lost() follows", never re-entering the caller). The spec sketch does not say this; it is the safe reading of "Asynchronous. Emits exactly one ...". On this machine Qt reports the empty-host error asynchronously, so TRN_07 does not fail when the deferral is removed (mutation tried): the deferral is defensive for platforms where connect errors surface synchronously, and is not proven by a test.
  - `registerMetaTypes()` also registers `QVector<mc::Change>`. The link-state types (`LinkState`, `LinkReason`, `LinkFaultInfo`, `DeviceSnapshot`) do not exist yet; T-037 adds them to the same header and function.

- Env notes:
  - **Qt DLLs for ctest:** `set_tests_properties(... ENVIRONMENT_MODIFICATION "PATH=path_list_prepend:$<TARGET_FILE_DIR:Qt6::Core>")` (generator expressions are evaluated in test properties; the value came out as `C:/Qt/6.11.1/msvc2022_64/bin`, and follows the kit the tree was configured with). Needs CMake >= 3.22 (3.30.5 here); on an older CMake the property is skipped and the kit bin must be on PATH. Verified: ctest passes with no `C:\Qt\6.11.1\...` entry on PATH. For MinGW the GCC runtime DLLs still come from the `C:\Qt\Tools\mingw1310_64\bin` PATH entry that the build-env recipe already sets.
  - **QtTest prints nothing when its output is a pipe on Windows** (ctest, an agent shell, `| Out-String`), so a failing test says nothing. `QT_ASSUME_STDERR_HAS_CONSOLE=1` fixes it; the test helper sets it (`ENVIRONMENT_MODIFICATION ...;QT_ASSUME_STDERR_HAS_CONSOLE=set:1`). To run a test binary by hand in a captured shell, set that variable or pass `-o file.txt,txt`. `-functions` works regardless.
  - **`QTRY_*` evaluates its condition again after it first holds** (the final `QVERIFY`): a condition that consumes data (`read()` into a buffer) fails the macro although the data arrived. Use an idempotent accumulator (TRN_02 does).
  - **Windows reports a refused loopback connect only after 2 to 4 s**, so QDV-06 "nobody listens" ends on the connect timer there, not on the refusal (Linux: immediate). The test asserts only what the spec does: one `openFailed` within `connectTimeoutMs + 500`.
  - qmake: `QT = core network serialport testlib` in the test `.pro` keeps QtGui out (`mc_device.pri` only adds to the default QT); `-W3` under qmake, no `-WX` (as the other twins).
  - Borderline Qt 6.2 API: none knowingly. Used: `QAbstractSocket::errorOccurred` (5.15), `setSocketOption`, `QTimer::singleShot(int, context, functor)` (5.4), `QMetaType::fromName`/`fromType` (6.0, tests only), `QTEST_GUILESS_MAIN`, `QTRY_*_WITH_TIMEOUT`. `QTest::qWait` is used once (TRN_04, a negative wait).
