## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the FX3 boundary steps no longer report a false failure at D8000, and every bench profile
  exists as a local draft that passes the dry run with its plan. The leader packs the profiles and plans
  for the v0.1.0 release.
- **Spec (leader, done 2026-10-08):** `SPEC-hil-capture.md` "Profile" gains the optional key
  **`specialFrom`**. The rules:
  - A reference resolving into the special range names a device that exists, so a step expecting
    `plcError` there runs with expectation `ok`.
  - A request spanning the general and the special range is not sent: it is skipped with the reason.
  - Q and FX5 omit the key.

  `COMMAND-CATALOGUE.md` G5-02 and G5-03 are annotated to match. The X/Y paragraph and the operator
  prerequisites were updated at the same time.
- **Approach:**
  1. **`tools/hil_capture`:**
     - The profile loader accepts `specialFrom`: an object of device type to a number in that type's
       radix, validated against `deviceEnd` (it must be greater). Unknown keys stay refused.
     - The resolver applies the two rules above.
     - The dry run and the summary show the changed expectation and the skip reason.
     - The safety gate is untouched. These steps are reads; a write never targets a special range,
       because scratch decides.
  2. **Tests** in `mc_hil_tool_tests`:
     - the loader accepts `specialFrom` and refuses bad values;
     - G5-02 → `ok`, and G5-03 → skipped with the reason, for an FX3-like profile, on both `a1e` and
       `a1c`;
     - a profile without the key behaves exactly as before, on all four plans;
     - the replay tests are unchanged.
  3. **Example profiles** (`tests/hil/profiles/*.example.json`, committed): add `specialFrom`
     `{"D": 8000, "M": 8000}` to the two FX3 examples, and fix their values to the owner's decisions in
     `temp-docs/hil-scratch-areas.md`:
     - scratch `D100-D2099`, `M100-M2099`;
     - `supports` `D R M S X Y TS TN CS CN`;
     - `deviceEnd` `D=7999, R=32767, M=7679, S=4095, T=511, C=255, X=377, Y=377`;
     - Q examples: no R/ZR, `Y0-Y7`;
     - FX5U example: `Y0-Y7`, and B/W consistent with its `deviceEnd`.
  4. **Local draft profiles** (git-ignored by the existing `.gitignore` rule `tests/hil/profiles/*.json`):
     - **The 14 bench profiles** of the spec table, plus 2 FX5U RS-485 3C drafts (F1 sum on, F4).
     - **Values** come from `temp-docs/hil-scratch-areas.md` as the owner decided them.
     - **Frame settings:**
       - each profile's `FrameConfig` matches its row: code, format, sum check, block number 5AH for
         3C F2, station 0;
       - FX X/Y fields per `SPEC-core-model.md`;
       - FX5U uses `Binary` or `ASCII (X,Y HEX)` (`xyAsciiDigits` Hex).
     - **Placeholders:** the TCP host `192.0.2.10` (TEST-NET), and serial `COM1` 9600 7E1 or the row's
       usual line. Every value the owner must fill or confirm is marked inside the free-text fields
       `firmware`, `adapter` and `plcState`, starting with `FILL:`, because the loader refuses unknown
       keys.
     - **Name:** `<id>.json`, with ids such as `q03ude-eth-3e-bin`, `q03ude-c24-3c-f1-sum`, …,
       `fx5u-rs485-3c-f4`.
     - **Dry run:** every draft must pass `hil_capture --dry-run` with its family plan (exit 0, safety

  5. **`tests/hil/profiles/README.md`** (committed):
