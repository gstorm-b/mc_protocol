- Deviations from plan (+ reason):
  - Files beyond the Plan's list: `test_commands.cpp` is in it; `test_parser_stream.cpp`,
    `test_alloc.cpp`, `test_frame_3e.cpp`, `serial_vector_config.h`, `frame_serial.h`, `cmdd.vec` and
    `include/mc/core/protocol.h` (doc comment only, as briefed) are not. Reasons as in T-046: the module
    spec puts STR-01/02/04 and ALC-01 there, the 3E test would break once 1C works, the helper is shared.
  - The Plan names `1c_f1.vec` / `1c_f4.vec` rows "A.16, A.19" and the AnA command set belongs to T-049
    (`JR/QR/JW/QW`); the letters table is one table, so AnA is live here: V-1C1-09 (QR D100 x 3) is an
    A.16 row of this task's vector file. Its explicit test case (1C-04) is T-049's. The 1C formats 2 and 3
    stay gated off here (`frameSerialFormatSupported` is false for 1C F2/F3, so they are reported as not
    implemented) so this task's tested surface is exactly formats 1 and 4; T-049 removes the gate.
  - A `messageWait` above 15 returns `InvalidConfig` from `a1cRequestData()` (and so from
    `McProtocol::encode()`); not in the Plan. `McProtocol` does not run `FrameConfig::validate()` (leader
    decision 3 of T-047) and an unchecked value would put a non-hex character on the wire. `encodedSize()`
    still returns a size for such a config (it has no error path for config values).
  - Derived vector rows (22 in `1c_f1.vec`, 24 in `1c_f4.vec`, 4 in `cmdd.vec`): not in
    Appendix A, produced by a one-off perl script from the format table (spec 5.4), the sum ranges (2.5) and
    the 1C command layout (4.3); the script also re-verifies the SUM of every A.16 / A.19 request and
    response it copies, that each spec row's text line equals its hex line and its byte count. The CMD/CMDD
    command strings were extracted from the spec tables by script (hex computed from the strings). The
    script is not part of the tree. Derived ids are `1C<n>-...` (no `V-` prefix); the NAK-to-write row uses
    error code 10 (arbitrary, to show the 2-character code is not a constant).
  - V-1C4-07 (A.19) has no text line in the spec; it is transcribed without one.
  - CMD-33 duplicates PRIM-07 (the same manual sum): kept as its own `kind: sumcheck` row so CMD-25..33
    is complete in `cmd.vec`.
  - Formatting: `.clang-format` was run on the files I created or fully own (`command_a1c.*`,
    `frame_serial.*`, `protocol.cpp`, the new test code). In the committed test files
    (`test_commands.cpp`, `test_frame_3e.cpp`, `test_parser_stream.cpp`) the unrelated reformatting it
    produced was reverted (3-way merge against the formatted HEAD), so their diffs hold only my changes.
