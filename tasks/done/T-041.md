## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the 1E (A-compatible 1E frame) command layer: request data for
  00H–03H and response-data decoding, byte-for-byte against the CMD/CMDD vectors.
- **Approach:**
  - `src/core/protocol/command_a1e.h/.cpp`, following the existing
    `command_qna.*` structure: request data = head device, points u8 (256 →
    `00`, spec E8), fixed `00`, [write data]; the **command code goes into the
    frame subheader**, not the request data (the command layer returns it for
    the frame layer). Response size computed from the request (no length
    field): bits ASCII N + (N mod 2) characters with a trailing dummy on odd N,
    bits Binary ⌈N/2⌉, words 2N / 4N. Binary writes with odd N pad the last
    nibble with 0; ASCII writes send exactly N characters (spec Q3).
    Device encoding for 1E comes from the existing `device_encode` (1E ASCII:
    code hex(4) + number hex(8) regardless of radix; 1E Binary: number LE4 +
    code LE2).
  - 04H/05H (random access / test) tables and encoders present in the source
    but not reachable through `Op` in v1 (decision 2), with their CMD vectors
    tagged `v1.1` as the spec's test table says.
  - Vectors: add the 1E rows to `tests/vectors/cmd.vec` / `cmdd.vec`,
    transcribed from `docs/mc_reference/mc-protocol-frame-spec.md`.
- **Files expected to change:** `src/core/protocol/command_a1e.h/.cpp`,
  `src/CMakeLists.txt`, `mc_core.pri`, `tests/vectors/cmd.vec`,
  `tests/vectors/cmdd.vec`, `tests/core/protocol/test_commands.cpp`.
- **Acceptance criteria:**
  1. CMD-15…21 byte-for-byte.
  2. The 1E rows of CMDD pass (odd-count dummy character, zero nibble, wrong

  3. 04H/05H encoders exist and are unreachable through `Op`; their vectors
     are tagged `v1.1` and skipped like the other `v1.1` rows.
  4. VEC-02 (transcription guard) green with the new rows.

## Dev notes  *(developer writes)*

- Files changed:
  - `src/core/protocol/command_a1e.h` / `.cpp` (new): 1E 00H-03H request data, response size
    (`a1eResponseDataSize`: bits `Codec::bitsSize(N + N % 2)` = ceil(N/2) Binary, N + (N mod 2)
    ASCII, words 2N / 4N, writes 0), response decode, `a1eCommandCode()` (goes to the frame
    subheader in T-042), and the 04H/05H encoders (`a1eTestBitsRequestData`,
    `a1eTestWordsRequestData`, `A1eTestBit`/`A1eTestWord`) reachable by tests only.
  - `src/core/protocol/bit_payload.h` (new): `encodeBits()` / `decodeBits()` moved here verbatim
    from the anonymous namespace of `command_qna.cpp`, so both command layers share them.
  - `src/core/protocol/command_qna.cpp`: the two helpers removed, `#include "bit_payload.h"` added
    (no behaviour change).
  - `src/CMakeLists.txt`, `mc_core.pri`: `command_a1e.cpp/.h` and `bit_payload.h` added.
  - `tests/vectors/cmd.vec`: CMD-15..21 (enabled), CMD-22, 23, 24, 37 (tagged `v1.1`), all `frame: 1e`.
  - `tests/vectors/cmdd.vec`: CMDD-09..13 (enabled, `frame: 1e`) plus four derived 1E rows:
    CMDD-13a (`"101"`, LengthMismatch, the second half of the spec's CMDD-13 row), CMDD-10a (Binary
    N=5 `10 10 10`, zero last nibble), CMDD-17e / CMDD-18e (1E twins of CMDD-17 / CMDD-18).
  - `tests/core/protocol/test_commands.cpp`: existing QnA cases now go through a `QnaCommands`
    trait and skip `frame: 1e` rows (an unknown `frame:` fails); new cases CMD-15..21,
    CMDD-09..13, A1E-CODE, CMD-22..24/37 (direct encoder proof), A1E-REQUEST-ERRORS, A1E-BITS,
    A1E-WRITE-RESPONSE.
- Deviations from plan (+ reason):
  - `bit_payload.h` and the edit to `command_qna.cpp` are not in the Plan's file list. The 1E
    write/read of bits needs the same chunked nibble packing as QnA; copying 60 lines would break
    the DoD "no duplicated logic" item, so the helpers moved to a shared private header.
  - The 04H/05H encoders are also driven by a direct TEST_CASE (CMD-22..24, 37) although their
    vectors are tagged `v1.1` and skipped by the vector runner, so the code the plan asks for is
    not left untested (coverage bar 95 %).
  - Derived rows CMDD-13a / 10a / 17e / 18e (not in the spec's CMDD table verbatim) carry the
    "wrong length", "zero nibble", "invalid nibble" cases criterion 2 names for 1E; bytes are
    taken from CMDD-06/13/17/18 patterns, byte counts hand-checked.
