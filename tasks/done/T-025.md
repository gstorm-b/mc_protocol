## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** Ad-hoc requests next to polling: arena, queue, burst cap,
  chunked reads and split writes, exactly-once `RequestDone`.
- **Approach:** as the module spec's "Ad-hoc requests" and "Exactly-once
  completion": a FIFO ring arena of `adHocArenaBytes` (default 64 KiB), a queue
  of `adHocCapacity` (64), dispatch with `maxAdHocBurst` (4; 0 = strict
  priority), chunked ad-hoc reads and split writes, `QueueFull` when full,
  every submitted id completed exactly once (also on `linkDown`).
- **Files expected to change:** `src/core/session/adhoc_queue.h`,
  `src/core/session/adhoc_queue.cpp`, `src/core/session/session.cpp`,
  `src/CMakeLists.txt`, `mc_core.pri`, `tests/CMakeLists.txt`,
  `tests/core/session/test_session_adhoc.cpp`,
  `tests/core/session/test_alloc.cpp`.
- **Acceptance criteria:**
  1. SES-09…SES-15 pass, including the W1–W4, C1, W5–W8 wire order and the
     arena wrap-around.
  2. ALC-02: zero allocations across 1000 submit/complete cycles, including a
     `linkDown` with a full queue.
  3. `ctest -L "core_session|core_protocol|core_model|build"` green on MSVC.

- Files changed:

    `completeInFlightChunk()`, `chunkPayloadDest()`, `completeAllForLinkDown()`,
    `confirmDrained()`). Class-level doc comment documents the lifetime rule
    (a job's arena reservation is released only once its `RequestDone` is
    popped, not the moment it completes).
  - `src/core/session/adhoc_queue.cpp` (new, 331 lines): the FIFO ring arena
    (absolute, ever-increasing byte offsets so a wrap-time gap folds into the
    job's own `reserveLength` — never split across the physical wrap point),
    two-pass `submit()` (pass 1 sums every chunk's encoded frame size against a
    probe job, to size/validate the reservation before anything is committed;
    pass 2 copies write data and encodes every real chunk's frame into the
    reserved arena bytes), `Op::ReadBits`'s `bitLayout` fix (see below).
  - `src/core/session/session.cpp`: `AdHocQueue` member added to the
    constructor's init list; `linkDown()` now drains
    `completeAllForLinkDown()` into one `RequestDone{LinkDown}` per
    not-yet-completed job, submission order; `submit()` rewritten from
    T-022's placeholder to validate, check `isLinkUp()`, delegate to
    `m_adHocQueue->submit()`, and dispatch immediately if idle;
    `dispatch()` gained step 1 (ad-hoc priority, capped by `maxAdHocBurst`
    while a round is in progress, uncapped between rounds) ahead of the
    existing round-in-progress/round-start logic; removed the now-unused

  - `src/core/session/session_rx.cpp`: `bytesIn()` now routes to

    ad-hoc reads never touch `ValueStore` — pushes `RequestDone` exactly when

    unavoidable pattern flagged in every Phase 3 task so far (T-022/23/24):
    `AdHocQueue` is a PIMPL detail type kept out of the public header (only a
    forward declaration + `unique_ptr` member reach `session.h`), but the new
    private methods/members and the corrected `submit()`/`dispatch()` doc
    comments have nowhere else to live.
  - `src/core/session/session_rx.cpp` touched though not named in the Plan's
    Files list — it is the receive path proper (`bytesIn()`'s dispatch to
    `completeAdHocResponse()`), inseparable from `session.cpp`'s own dispatch
    changes; treating it as in-scope mirrors how T-023 put the whole receive
    path there in the first place.
  - `tests/qmake/mc_core_session_tests.pro` touched though not named in the
    Files list — needed so `BLD-04.pri_sync`/the qmake build actually compile
    `test_session_adhoc.cpp`; same reasoning as `mc_core.pri` itself, which
    *is* named.
  - Two bugs found and fixed while writing/running the acceptance tests (both
    caught by the tests themselves, not found and then rationalized away):
    1. `chunkRequestAt()`'s `Op::ReadBits` case built its `Request` via
       `Request::readBits(chunkHead, chunkPoints)`, which has no `bitLayout`
       parameter (unlike `writeBits()`) and always defaults to
       `BytePerPoint` — silently discarding the job's own `bitLayout`, so a
       `PackedLsbFirst` ad-hoc bit read would decode wrong. Fixed by setting
       `r.bitLayout = job.bitLayout;` explicitly after construction. Caught
       by SES-11's `PackedLsbFirst` subcase (payload bytes came back wrong:
       `0x01`/`0x00` instead of `0x05`/`0x03`).
    2. Two test-only bugs in `test_session_adhoc.cpp` itself (not library
       bugs — both confirmed against the actual `dispatch()`/`AdHocQueue`
       code before fixing the test, not the code):
       - SES-13's "arena wraps correctly" subcase never sets
         `cfg.cycleIntervalMs`, so it defaults to 100; the loop runs 200
         iterations advancing the clock 1ms each, and with an empty plan
         (no subscriptions) that crosses the round boundary at i=99 and
         `dispatch()` correctly starts-and-instantly-ends an empty round
         (spec "Dispatch": "a round with no chunks still runs ... and still
         emits `CycleDone`"), interleaving an extra `CycleDone` with the
         ad-hoc `RequestDone` the test wasn't expecting. Fixed by pinning
         `cfg.cycleIntervalMs = 1'000'000` in that one subcase (no
         subscriptions there anyway, so polling timing is irrelevant to what
         it's testing).
       - SES-10's shared `completeNext` lambda assumed exactly one `Output`
         appears per response, but every write in that test is one point
         (one chunk): completing it always produces its own `RequestDone`
         *and* — synchronously, in the same `dispatch()` call — the next
         chunk's `Send`, both landing in the same drain batch (`RequestDone`
         first). Fixed by having `completeNext` accept 1 or 2 outputs,
         checking a leading `RequestDone` when present, and always reading
         the *last* one as the newly-sent frame.
     Root-cause note for both: confirmed with a temporary `MESSAGE()` dump of
     `rec.size()`/`rec[i].kind` before deciding the fix, per the project's
     usual "diagnose before patching" habit; the debug prints were removed
     before finishing.

- Notes for the tester:
  - The two ad-hoc-specific design points worth double-checking independently:
    (a) the lifetime-safety rule — `AdHocQueue::confirmDrained()` runs only
    from `Session::nextOutput()` when popping the matching `RequestDone`,
    never at completion time, so a `RequestDone`'s `payload` (a view into the
    arena) stays valid until the caller actually drains it, even if a later
    `submit()` happens first; covered by the "T-025 lifetime" regression test.
    (b) the two-pass `submit()` design (size everything against a probe job
    before committing any arena state, then encode for real) — chosen so a
    failure partway through chunking never leaves `m_arenaTail` advanced or a
    partially-written job in the ring.
  - `AdHocQueue::frontUnfinished()` is a linear scan bounded by `m_jobCount`
    (itself bounded by the configured, typically small, `adHocCapacity`) —
    O(capacity), not strict O(1); accepted as a scope/time tradeoff rather
    than adding a second index structure, called out explicitly for the
    checkpoint reviewer.
  - `dispatch()` does **not** recurse into itself after `startRound()` (T-024's
    own no-recursion doc comment on `dispatch()` still applies): analyzed the
    spec's SES-10 wire-order example specifically for whether ad-hoc ought to
    preempt a freshly-started round's very first chunk, and concluded no —
    the existing non-recursive structure already produces the spec's own
    wire order, given the round's first ("unlabeled") chunk is already in
    flight before the ad-hoc writes are even submitted in the test.
  - Both fixed test bugs (SES-13, SES-10) above are worth a close read before
    accepting the tests at face value: neither indicated a real library
    defect, but both are the kind of thing a differently-shaped test could
    have missed silently (masking a real regression later) rather than
    failing loudly.
