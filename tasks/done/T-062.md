## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `bench` steps measure ttfb / rx / rtt per request, and `--report` turns every
  `bench.csv` into the `BENCH.md` tables (spec "Timing benchmark").
- **Approach:**
  - `bench` step: 200 repetitions by default (`--bench-reps` overrides), 1 warm-up discarded,
    spaced by the profile's `cycleIntervalMs`; t_send / t_first_byte / t_complete from the
    `RecordingTransport` stamps; `scan_ms` from `scanTimeDevice` read before each bench
    (empty when not declared).
  - `--plc-state RUN|STOP`: the tool asks the operator to confirm the state (inside the D4
    prompt; `--yes` skips) and records it in `run.meta` and `bench.csv`; it never changes
    the PLC state.
  - `bench.csv` columns exactly: `profile, plc_state, step, op, device, count, req_bytes,
    resp_bytes, rep, ttfb_ms, rx_ms, rtt_ms, scan_ms`. A STOP pass appends to (does not
    replace) the RUN rows of the same profile folder — say how in Dev notes.
  - The poll step's round-duration series from `CycleInfo::durationMs`: put it where it
    belongs (e.g. `session.vec` events) and say where.
  - `bench_report.h/.cpp`, `hil_capture --report`: reads every `bench.csv` under the root,
    writes one table per profile with bytes out/in and min / median / p95 / max of ttfb, rx
    and rtt, RUN and STOP columns, and the spec's caveats at the top. Percentiles:
    **nearest-rank** (leader decision), stated in the report header. An output-path option;
    the default is `docs/hil/BENCH.md`, but in Phase 7 the report is only written under the
    build tree (D5).
- **Files expected to change:** `tools/hil_capture/bench_report.h/.cpp`, `runner.cpp`,
  `main.cpp`, the test source, CMake + qmake lists.
- **Acceptance criteria:**
  1. HIL-06: `--report` on a hand-made `bench.csv` (RUN and STOP rows, odd and even counts)
     produces the expected min / median / p95 / max, worked out by hand in the test.
  2. A bench run against `virtual_plc` (`--only GB`, small `--bench-reps`) writes
     `bench.csv` rows with the right columns and repetition count (warm-up excluded), then
     `--report` produces a readable report (pasted, shortened, into Dev notes).
  3. A STOP pass on the same profile adds STOP rows and the report shows both columns.
- **Gate 1 approval:** 2026-10-02 — leader, under the owner's delegation extended to Phase 7
  (`rules.md`). Common rules and decisions D1–D5: `tasks/active/T-057.md`.

## Dev notes  *(developer writes)*

- Files changed:
  - `tools/hil_capture/bench_report.h/.cpp` (new): `seriesStats`, `benchReportText`, `writeBenchReport`. One table per profile; per request bytes out/in and, for ttfb, rx and rtt, `min / median / p95 / max (n=..)` in a RUN and a STOP column; the spec's caveats at the top. Percentiles are **nearest-rank** (rank ceil(0.95 n) of the sorted series), stated in the report header; the median is the statistical median (mean of the two middle values for an even count), also stated there (a leader reading of "median = nearest-rank p50" would give the lower middle value for an even n; say if you want that).
  - `tools/hil_capture/runner.cpp` (changed): `bench` steps. A request bench submits the operation through `McDevice` `warm-up + reps` times (default 200 / 1, `--bench-reps` overrides `reps`, a step's own `reps`/`warmup` win), spaced by `session.cycleIntervalMs`; times come from the RecordingTransport chunk stamps of that repetition (ttfb = first write to first received byte, rx = first to last received byte, rtt = first write to last received byte; a split request counts from its first frame to the last byte); bytes are the sums of both directions. `scan_ms` is the raw word of `scanTimeDevice`, read once before the bench (empty when not declared; no unit conversion). A bench of a poll set (`pollSet`) runs the poll step's subscriptions and heartbeat for `warm-up + reps` rounds; one row per round with `op` `PollRound`, `device` = the poll step id, `count` = subscribed points, bytes from the wire chunks of the round, `rtt_ms` = `CycleInfo::durationMs`, `ttfb_ms`/`rx_ms` empty; its transcript is not stored in session.vec. A repetition that fails counts toward a failed step; a link lost mid-bench is reconnected.
  - **Round-duration series of an ordinary poll step:** the `duration_ms` key of its `cycleDone` events in `session.vec` (documented in `capture_writer.h`).
  - `tools/hil_capture/capture_writer.h/.cpp` (changed): `BenchRow`, `benchText`, `writeBench(rows, merge)`, `writeRunMeta(..., append)`, `prepare(error, keepExisting)`, `has()`.
  - `--plc-state RUN|STOP`: recorded in `bench.csv` (`plc_state`) and `run.meta` (`plc_state`); the D4 summary shows "Operator-set state: STOP (confirm the PLC really is in STOP; the tool never changes it)", so typing the profile id confirms it (`--yes` skips). `dry_run.h/.cpp`, `tool.cpp`.
  - **How a STOP pass appends** (the spec says a re-run replaces the folder; a STOP pass is the exception): with `--plc-state STOP` the folder is not emptied; `bench.csv` keeps the rows of other states and the old STOP rows are replaced by the new ones (so repeating the STOP pass does not pile rows up); `run.meta` gets a `stop_pass.plc_state/date/git_commit/operator_note` block (an earlier block is replaced); `steps.vec` and `session.vec` of the RUN pass are not touched (written only if missing). A RUN pass replaces the whole folder as before.
  - `--report`: `tool.cpp`, `options.h/.cpp` (new `--report-out FILE`, default `docs/hil/BENCH.md`; reads `--output-root`). In Phase 7 the tests and my manual run write only under the build tree (D5); `BENCH.md` is not regenerated.
