## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** Logging and the zero-allocation guarantee of core-model:
  `include/mc/core/log.h` (`LogLevel`, `LogSink`, `NullLogSink`, `hexDump()`),
  a shared counting allocator for every later ALC test, and ALC-01.
- **Approach:** as `SPEC-core-model.md` `log.h`: `hexDump` renders control
  codes by name (`<STX>`, …) into caller storage without allocating.
  `tests/common/alloc_counter.h` replaces the global `operator new`/`delete`
  (all standard forms) with a counter that tests can reset and read; it is
  included by exactly one translation unit per test binary, and says so at
  the top of the file. ALC-01 runs every function of the zero-allocation list
  with realistic inputs after a warm-up and asserts zero counted allocations.
- **Files expected to change:** `include/mc/core/log.h`,
  `src/core/model/log.cpp`, `src/CMakeLists.txt`, `mc_core.pri`,
  `tests/CMakeLists.txt`, `tests/common/alloc_counter.h`,
  `tests/core/model/test_log.cpp`, `tests/core/model/test_alloc.cpp`.
- **Acceptance criteria:**
  1. LOG-01: a counting sink proves `write()` is never called and no message
     string is built when `enabled()` is false.
  2. LOG-02: `hexDump` renders control codes by name, per the spec's example.
  3. ALC-01: zero allocations across `parseDevice`, `validate`, `chunk`,
     `convert::float64At`, `hexDump`, `formatDevice`; a positive control
     proves the counter is live (a `new` it does count).
  4. `ctest -L "core_model|build"` green.

  - Public headers follow `docs/rules/doc_comment_style.md`; every public

## Dev notes  *(developer writes)*

- Files changed:
  - `include/mc/core/log.h` — new header: `LogLevel`, `LogSink` (`enabled()` const, `write()`
    not — a sink may need to mutate its own state to write, matching the module spec's sketch),
    `NullLogSink`, `hexDump()`.
  - `src/core/model/log.cpp` — new: `NullLogSink::enabled()`/`write()`, and `hexDump()`
    (snprintf-like: always returns the full logical length, writes only what `capacity` allows,
    matching `formatDevice()`'s convention from T-007). The eight spec §8.6 control-code names are
    a small table matched by raw byte value only; `EOT`/`CL` (spec §2.7) are deliberately not
    among them, since §8.6 does not name them either.
  - `tests/common/alloc_counter.h` — new: a counting override of every standard global
    `operator new`/`delete` form (throwing/nothrow, array/non-array, sized/unsized), backed by
    `malloc`/`free` so it never recurses into itself. **Updated by the Rework below:** also
    covers the C++17 aligned-new forms (20 overloads total now), backed by
    `_aligned_malloc`/`_aligned_free` — see "Rework (leader)". Carries the "include from exactly
    one .cpp per binary" banner the Plan asked for; a second inclusion in the same binary is a
    duplicate-symbol *link* error by design, not something this header detects itself.
  - `tests/core/model/test_log.cpp` — new: LOG-01 (a `CountingSink` proves `write()` is never
    called and a stand-in "message built" counter stays 0 when `enabled()` is false; a companion
    case proves the enabled path does call `write()` with the right arguments; `NullLogSink`
    itself checked too), LOG-02 (`hexDump` against the exact byte string log.h's own doc comment
    quotes, `"50 00 00 FF FF 03 00"`, both without and with `names=true` — byte `0x03` in that
    same example happens to be ETX, so one example covers the plain form and one name
    substitution at once; a second case renders all eight spec §8.6 codes together; a third
    checks the snprintf-style truncation/capacity-0 contract).
  - `tests/core/model/test_alloc.cpp` — new: ALC-01, the one file in this binary that includes
    `alloc_counter.h`. A positive control (`new int`) first, then one `TEST_CASE` per function
    named in the acceptance criterion, each: warm-up call (discarded), `resetAllocCount()`, the
    real call, `allocCount()` captured into a local *before* any `CHECK`/`REQUIRE` runs (so
    doctest's own machinery can never be misattributed to the code under test), then assertions.
  - `src/CMakeLists.txt`, `mc_core.pri` — added the new source + header to `mc_core`/`mc_core.pri`
    in the same change (BLD-04).
  - `tests/CMakeLists.txt` — added `test_log.cpp` and `test_alloc.cpp` to `mc_core_model_tests`;
    added a `PRIVATE` include path to the `tests/` root (mirroring T-009's `src/` path) so
    `test_alloc.cpp` can `#include "common/alloc_counter.h"`.
  - `CHANGELOG.md` — one line under `Unreleased` (same Definition-of-Done reason as T-007
    through T-010).

- Deviations from plan (+ reason): **the one below was superseded by the Rework — kept as a
  record of the original submission.** None otherwise. `alloc_counter.h`'s scope (which operator
  new/delete forms to override) was a judgment call the Plan left to me ("all standard forms"); I
  read that as the 10 throwing/nothrow/array/sized overloads a pre-C++17 codebase would need, and
  explicitly did not add the C++17 aligned-new overloads, recorded above and in "Notes for the
  tester" in case that reading was narrower than intended. The leader's ruling: add them — the
  counter exists to prove "zero allocations", and a form it does not count is a silent false pass
  the day any type needs extended alignment, which the Plan's "all standard forms" already covers
  without needing an owner amendment (unlike T-009's spec conflict, this was a scope judgment
  call within the Plan's own wording, not a conflict with it).

- Notes for the tester:
  - **Superseded by the Rework below.** `alloc_counter.h` does not override the C++17
    aligned-new overloads (`operator new(size_t, std::align_val_t)` and friends) — a scope
    choice, not an oversight; revisit if a future type in this codebase ever declares `alignas`
    beyond `max_align_t`.
  - ALC-01's `chunk` and `validate` cases build their `Request`/`FrameConfig` values *before* the
    `resetAllocCount()` call, specifically so that constructing those plain-struct values (which
    do not allocate anyway, but are constructed outside the measured window regardless) can never
    be mistaken for part of what's being measured — the measured window is only the named
    function's own call.
  - The `float64At` ALC-01 case deliberately uses a raw stack byte array instead of
    `convert::fromFloat64()` to build its input, because `fromFloat64()` itself allocates one
    `ByteBuf` (by contract) — using it would have made the *setup* allocate, not the code under
    test, and defeated the point of the test if that setup weren't clearly outside the measured
    window.
  - LOG-01's "message built" counter is a stand-in: no real library log call site exists yet at
    this phase (core-session/core-protocol, which will actually call into a `LogSink`, come
    later), so the test demonstrates the mandated `if (sink.enabled(level)) {...}` pattern itself
    rather than exercising a production call site.

- Rework (leader): add the C++17 aligned-new/delete forms to `alloc_counter.h`, counted exactly
  like the plain ones, plus a positive control proving an over-aligned allocation is both counted
  and actually aligned.
  - `tests/common/alloc_counter.h`: added `operator new`/`new[]` taking `(size_t,
    std::align_val_t)` and their nothrow variants, and the matching `operator delete`/`delete[]`
    taking `(void*, std::align_val_t)`, the sized form `(void*, size_t, std::align_val_t)`, and
    the nothrow form — 10 more overloads (20 total), each incrementing `g_allocCount` exactly like
    the plain forms.
  - Backed by `_aligned_malloc`/`_aligned_free` (`<malloc.h>`), not `std::aligned_alloc`, per the
    leader's instruction: the MSVC CRT does not provide `std::aligned_alloc`, while
    `_aligned_malloc`/`_aligned_free` are available on both CRTs this project builds against (MSVC
    and MinGW-w64, which targets the same Windows CRT). Every aligned allocation is freed with
    `_aligned_free` specifically — never plain `free()`, which is undefined behaviour for a
    pointer `_aligned_malloc` returned — documented in the file's own banner comment so a future
    editor doesn't casually "simplify" it to one shared `free()` path.
  - `tests/core/model/test_alloc.cpp`: new positive control, `alignas(64)` struct, allocated with
    plain `new`/`delete` (the compiler itself routes this through the aligned overloads above
    since 64 exceeds `__STDCPP_DEFAULT_NEW_ALIGNMENT__`, no explicit placement/align_val_t needed
    at the call site). Checks both that `allocCount()` sees it (proving the aligned overloads are
    wired in, not just present-but-unreachable) and that the returned address is actually a
    multiple of 64 (proving `_aligned_malloc` honoured the alignment, not merely that some
    allocation happened).
  - Rebuilt and re-ran `ctest -L "core_model|build"`: still 4/4 green; full `ctest` also green
    (see Commands run / outcomes above, updated with the post-Rework counts: 66/66 test cases,
    821/821 assertions, +1 test case / +2 assertions over the original submission).
