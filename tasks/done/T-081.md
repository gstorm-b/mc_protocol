  **The field case** (3E Binary over TCP, cable pulled and re-plugged): the PLC kept the old connection half-open. It accepted the new TCP connection at once but answered the first MC request only about 40 s later. v0.1.0 faulted that request after `timeoutMs` (1000 ms), and the app aborted the connection.
- **Goal:** an opt-in, longer response deadline for the **first frame sent after each `linkUp`**, with no resend. Default 0 keeps v0.1.0 behaviour byte for byte.
- **Approach:**
  1. **Public field.** `include/mc/core/session.h`: add `uint32_t firstResponseTimeoutMs{0};` to `SessionConfig` after `serialFlushMs`, with a Doxygen comment per `docs/rules/doc_comment_style.md`. Its meaning: 0 = `effectiveTimeoutMs()`; first frame after each `linkUp` only; never a resend; must be 0 or ≥ `effectiveTimeoutMs()`. Update the `linkUp()` Doxygen to mention it.
  2. **Validation.** `SessionConfig::validate(frame)` rejects `0 < firstResponseTimeoutMs < frame.effectiveTimeoutMs()` with `InvalidConfig`, using the message in the spec.
  3. **Engine.**
     - `linkUp()` marks "first send pending".
     - The **first** frame sent afterwards gets `deadline = now + firstResponseTimeoutMs` when it is nonzero, else `effectiveTimeoutMs()`, and clears the mark. The first frame is whichever goes first: heartbeat write, polling chunk or ad-hoc frame.
     - Every later send uses `effectiveTimeoutMs()`. That includes a serial resend of that same frame (`readRetries`) and the flush cap.
     - Find **every** site that arms `m_responseDeadline` for a new send: `session.cpp` `sendChunk`, and the `session_rx.cpp` sites at about lines 257, 297 and 363. Route them through one helper so no path is missed.
     - Serial: the grace bounds the time to the first byte only; `serialInterCharMs` is unchanged.
     - `linkDown` clears the mark, so a grace never outlives its link-up.
     - No allocation: ALC-01 and ALC-02 must stay at zero.
  4. **Tests.** SES-28 in `tests/core/session/test_session_fault.cpp`, covering every clause of the spec row:
     - Ethernet and serial;
     - heartbeat on and off;
     - the second frame using the normal deadline;
     - an unanswered first frame faulting at exactly +grace;
     - the grace applying again after `linkDown` + `linkUp`;
     - 0 = today's deadline;
     - the serial resend using `effectiveTimeoutMs()`;
     - `validate()`: values 1…999 rejected, 0 and 1000 accepted, with `timeoutMs` 1000.

     Also assert `nextDeadline()` while the first frame is in flight. Literals come from the spec, not from the code.
  5. **JSON.** `src/device/mc_device_config.cpp`: read and write `session.firstResponseTimeoutMs` like the other numeric session keys:
     - missing → 0;
     - a wrong type or out of range (negative, above `UINT32_MAX`) → `{Config, InvalidConfig}` with path `session.firstResponseTimeoutMs`.

     QDV-10 in `tests/device/tst_config_json.cpp` gains: the round trip with a nonzero value, the missing-key default, a wrong type and a negative value. `McDeviceConfig::validate()` already calls `session.validate(frame)`; add one QDV-10 case for the "below effectiveTimeoutMs" path.
  6. **GUI field.** `tools/mc_workbench/config_binding.cpp`: add `session/firstResponseTimeoutMs`, "First response timeout (ms)", `Int64`, 0 … u32. Tooltip: "Deadline of the first request after connect; 0 = the frame timeout". GUI-06 (every leaf of `toJson()` has a field) must pass.
  7. **Loopback fixture and QDV-18.**
     - `tests/device/mock_plc_server.h/.cpp`: add `holdFirstRequest(int ms)`, which applies to connections accepted after the call; 0 = off. For each connection, the bytes of its **first** request are held and handed to that connection's `MockPlc` after `ms`. Later bytes queue behind them, in order. Use a `QTimer` owned by the server and no blocking. A connection closed during the hold drops the held bytes without a crash.
     - QDV-18 in `tests/device/tst_mc_device.cpp`, exactly as the spec row says. Use generous margins, as the existing timing tests do; read `tst_mc_device.cpp` QDV-05 and QDV-11 first.
  8. **No change** to `FrameConfig`, the fault table semantics, or any golden vector.
