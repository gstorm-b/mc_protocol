## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `McDevice` talks to serial PLCs: `SerialTransport`, the serial
  bridge test helper, QDV-13 (3C F1 over TCP) and QDV-14 over the owner's
  virtual COM pair.
- **Approach:**
  - `include/mc/device/serial_transport.h` + `src/device/serial_transport.cpp`:
    `QSerialPort` with `SerialSettings`; `open()` completes on the next
    event-loop turn (both transports behave alike); `lost()` on port errors
    while open, never after `close()`; `lastLossWasPeerClose()` false for
    port errors; `describe()` like "COM3 9600 7E1"; no blocking call
    (QDV-HYG covers it). `McDevice` builds it for `TransportKind::Serial`
    (remove the "not available" path and its doc notes); the unusual-pairing
    `Info` line stays.
  - `tests/device/serial_bridge.h/.cpp`: the `QSerialPort` end of a virtual
    COM pair hosting a `MockPlc`. `tests/device/tst_serial.cpp` (QDV-14): 3C
    F4 and 1C F1, one round and one write each; `QSKIP` when
    `MC_TEST_SERIAL_PAIR` is unset. On this PC set
    `$env:MC_TEST_SERIAL_PAIR = "COM50,COM51"` (pairs COM50↔COM51 and
    COM52↔COM53 were installed by the owner — never install or reconfigure
    serial software).
  - QDV-13 gains 3C F1 over TCP (a serial frame over a TCP serial-device server).
  - `virtual_plc --serial COMx [--baud N]` serves a `MockPlc` on a COM port;
    `qt_console_poller` accepts `--serial COMx [--baud N]` and `--format N` too, so the
    COM-pair demo works.
- **Files expected to change:** `include/mc/device/serial_transport.h`,
  `src/device/serial_transport.cpp`, `src/device/mc_device.cpp`,
  `include/mc/device/mc_device.h` and `mc_device_config.h` (doc),
  `src/CMakeLists.txt`, `mc_device.pri`, `tests/device/serial_bridge.h/.cpp`,
  `tests/device/tst_serial.cpp`, `tests/device/tst_mc_device.cpp`,
  `tests/CMakeLists.txt`, `tests/qmake/*.pro`, `examples/virtual_plc/main.cpp`,

  2. QDV-14 passes with `MC_TEST_SERIAL_PAIR=COM50,COM51` and is skipped
     (QSKIP) without it.
  3. No blocking call in `SerialTransport`; QDV-HYG green.
  4. Scripted COM-pair demo: `virtual_plc --frame 3C --format 4 --serial COM50`
     ↔ `qt_console_poller --frame 3C --format 4 --serial COM51 --rounds N`
     exits 0 (output in Dev notes); all processes stopped.
  5. (Added by the leader after T-051, open question B.) A serial line that

## Dev notes  *(developer writes)*

- Files changed:
  - `include/mc/device/serial_transport.h`: `SerialTransport` added next to the existing `SerialSettings` (the only public header
    that gained a declaration; `@file` brief updated, `SerialSettings` untouched). `lastLossWasPeerClose()` is not overridden: the
    `Transport` default `false` is the right answer for every port error, and the class doc says so.
  - `src/device/serial_transport.cpp` (new): `QSerialPort` child. `open()` schedules the real port open for the next event-loop
    turn (generation counter, so `close()` cancels it and nothing is emitted), `opened()` / `openFailed("COM3: <Qt text>")` come
    from that turn; `close()` silent and idempotent; `write()` returns false and reports `lost()` from the event loop on a
    failure (an error the port raises from inside `write()` is only recorded, so `lost()` is never emitted from that call);
    `read()` non-blocking; `describe()` = `"COM3 9600 7E1"` (data bits, parity N/E/O/S/M, stop bits 1/1.5/2); any port error while
    Open except `NoError` / `TimeoutError` closes the port and emits `lost()` once. No blocking call (QDV-HYG green).
  - `src/device/mc_device.cpp`: `ensureTransport()` builds a `SerialTransport` for `TransportKind::Serial`; the "not available in
    this version" path is gone; the unusual-pairing `Info` line is unchanged.
  - `include/mc/device/mc_device.h`, `mc_device_config.h`, `transport.h`: doc comments only (Serial no longer "not available";
    `@see SerialTransport`).
  - `src/CMakeLists.txt`, `mc_device.pri`: `device/serial_transport.cpp` (BLD-04 green).
  - `tests/device/serial_bridge.h/.cpp` (new): the `QSerialPort` end of a COM pair hosting a `MockPlc`, plus
    `serialPairFromEnvironment()` (`MC_TEST_SERIAL_PAIR="COM50,COM51"` = device port, bridge port).
  - `tests/device/smoke_check.h` (new): `verifySmoke()`, the body of the old `smokeOverTcp` (one round, one word write, one odd-count
    bit write) shared by QDV-13 and QDV-14, so both prove the same thing and only the wire differs.

    `McDevice` on a missing port publishes `(Connecting, Requested)` then `(Disconnected, OpenFailed)` with the port name in the
    detail; SER-06 (pair) bytes both ways, `close()` silent, reopen. SER-01..05 need no hardware.

- Interpretations / borderline points:
