## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the "Workspace" row of the spec.
- **Approach:** one JSON workspace file holding the set of tabs (device tabs via `McDeviceConfig`
  JSON, mock tabs with their config and memory presets, HIL runner selections) and the ADS dock
  state; open / save / save as / recent files; unknown keys reported with their path (as the
  `hil-capture` loaders do); no IP or COM name is ever written anywhere else than the workspace
  file the user saves.
- **Acceptance criteria:** GUI-08 passes (save, close, load restores tabs, configs and layout); a
  damaged workspace file is refused with a message and the app stays usable.
- **Gate 1 approval:** 2026-10-03 — leader (Phase 8 delegation). Common rules: `T-067.md`.

  - Tests: `tests/gui/tst_gui_workspace.cpp` (`WorkspaceTest`, 13 functions; the damaged-file one loops over 20 damages), `tests/gui/gui_suites.h`, `gui_tests_main.cpp` (registered), `tests/CMakeLists.txt`, `tests/qmake/mc_workbench_tests.pro` (the source).
- File format (one JSON object): `format` = "mc-workbench-workspace", `version` 1, `devices[]` {`name`, `config` = `McDeviceConfig::toJson()`}, `mocks[]` {`name`, `settings` = the qpb grid values nested by group (`Frame`, `Errors`, `Serving`), `memory[]` {`head`, `kind` words|bits, `values[]`}}, optional `hil` {profile, plan, groups, plcState, outputRoot, source plc|mock|virtual_plc, note, benchReps, overwrite}, optional `layout` {`windowGeometry` and `docks` as base64 of `saveGeometry()` / ADS `saveState()`, `currentDevice`, `currentMock`}. Not saved: link state, subscriptions added at run time, trend ticks, the console, traces and logs, captures, the mock's memory image and faults (only the explicit presets), `capturedRoot` and the replay program of the HIL view (machine paths, found again at start).
- How load works: `WorkspaceIo::load` reads and parses on a worker thread; the GUI thread then builds every device tab (`setConfig`) and mock tab (`loadState`: keys checked against the grid, values applied through the grid's own validators, preset heads parsed in the mock's X/Y numbering) **before** touching the window. Any problem discards the new tabs (their runner threads are joined) and the window stays exactly as it was ("Workspace refused: <path>", every problem with its path, "Nothing was changed."). On success the new tabs are adopted, the old ones closed, the HIL inputs set, the ADS state restored (if ADS refuses it the previous state is put back and a warning is added) and the window geometry restored. Every `McDevice` and mock of a loaded tab is created by its `DeviceHost` / `MockHost` on its own runner thread, as for any tab. A not-serving mock is rebuilt from the loaded frame and codes at once and gets its presets; a loaded mock is never started by the load.
- Deviations from plan (+ reason):
  - Unknown keys are a refusal, not a warning: the `hil-capture` loaders refuse them, and a misspelled `timeoutMS` silently keeping the default in a configuration that talks to a PLC is worse than a message. Every unknown key is listed, not only the first.
  - "Memory presets" are explicit: the user presses "Keep this range as a preset" (the memory editor's range is read and stored); a preset replaces one of the same head and kind. The whole memory image is not saved (`MockPlc` has no way to export it, T-070 limit; and an image can be 100 KiB of words).
  - Presets are sent when the rebuild answer arrives, not queued behind the rebuild call: a refused rebuild then writes nothing into the old mock. Consequence: right after `loadFinished` the presets may not be in the mock yet (the test polls).
  - The recent list stores file paths only, in an INI file given by `main.cpp` (the user's config folder); without a store path (every test) it lives in memory. Tests that use a store put it under `MC_GUI_OUTPUT_DIR`.
  - Closing the replaced tabs on load joins their runner threads on the GUI thread (each bounded by the 3 s stop bound, as closing a tab by hand). Healthy runners stop in a few milliseconds; the file read, parse and write are off the GUI thread.
  - Not done: a dirty flag / "save changes?" prompt, "New workspace", a file preview. The HIL runner's profile and plan paths are saved as typed (relative paths stay relative).

- How GUI-08 is proven (`tests/gui/tst_gui_workspace.cpp`):
  - Save, close, load: `GUI_08_saveCloseLoadRestoresTabsConfigsAndLayout` builds a window with 3 device tabs (TCP 3E ASCII, serial 3C format 4, FX octal 1E), 2 mock tabs (a COM-serving 3C mock with changed error codes and two presets, an octal FX mock with a bit preset), HIL view inputs, a changed layout (Properties closed, Debug log moved to the left, HIL runner current) and chosen current tabs; saves; destroys the window (runner threads joined, `liveRunners` back); loads into a fresh window that starts with a different layout and size. Asserts per tab name, `McDeviceConfig::toJson()` equality, mock grid JSON equality and the spot values of the grid, presets in the mocks (read back from the rebuilt mocks), current tab indexes, every HIL field, the dock layout (per dock: closed, floating, tab siblings, current tab of the area), the window size, the recent list, a second save writes the same devices / mocks / hil, and thread identity of every loaded device (`ThreadReport`) and mock.
  - Damaged files: `GUI_08_aDamagedFileIsRefusedAndTheAppStaysUsable` loops over 20 damages in one window (truncated, empty, binary, top-level array, wrong format, future / missing version, port 0, wrong JSON type, unknown key in a config, unknown key / refused value in a mock grid, bad preset kind / device / bit-word mismatch, bad base64 layout, bad PLC state, too many points, missing file, over 16 MiB). Each is refused with a message holding the expected path and "Nothing was changed"; the tabs, configs, HIL inputs, the dock `saveState()` bytes and the window title are identical afterwards; no runner thread of a discarded tab is left (`liveRunners`); the window then still takes a new tab, saves and loads a good file. `GUI_08_aFailedSaveIsReportedAndKeepsTheOldFile` covers the write side (missing folder, a folder in the way: the old file is untouched).
  - Unknown keys with their path: `GUI_08_unknownKeysAreReportedWithTheirPath` plants 11 unknown keys (top level, device, config top level, `frame`, `session.heartbeat`, `transport.tcp`, `subscriptions[0]`, mock, preset, `hil`, `layout`) and asserts the exact sorted set of paths, each as "<path>: unknown key" in the user text; unknown keys inside a mock grid are reported at load by `MockTab::loadState` ("mocks[0].settings.Frame.bogus: unknown key", in the damaged-file loop). `Workspace_allProblemsAreCollected` shows several problems come back together.
  - Off the GUI thread: `GUI_08_fileWorkStaysOffTheGuiThread` loads and saves a 3 MB workspace (8 presets of 65536 points); the GUI event gap stays below 250 ms (measured values are not printed; limit asserted), a second file operation is refused while one runs, no temporary file is left.
  - No address leaves the file: `GUI_08_recentMenuAndNoAddressLeavesTheWorkspaceFile` checks the saved file holds the host and the COM name the user put in, and that no other file in the output folder (the recent INI included) holds either; hosts and COM names in the tests are built from numbers at run time, no literal in the sources.
- Notes for the tester:
  - Setup: nothing beyond the gui test setup (ADS DLL on `PATH`, offscreen). Files go under `<build>/tests/gui_out/gui-t073-*`. The serial pair is not opened by this suite (the COM name in a workspace is only text).
  - Timing assertions: the GUI gap limit is 250 ms on a 3 MB file (the binary is `RUN_SERIAL`); under extra load this is the one to watch.
  - The look of the File menu entries, the real `QFileDialog` and the warning box were not clicked in tests (`openWorkspace()`, `saveWorkspace()` and `saveWorkspaceAs()` call the native dialogs and are not driven; the controller they call is). The recent menu entry is triggered in a test.
  - ADS `restoreState` is trusted for the layout; a state saved by a different ADS version, or damaged but valid base64, goes through `restoreState` and, if ADS refuses it, the previous layout is put back and "the dock layout could not be restored" is appended to the message (no test builds such a state beyond the base64 case).
  - Mutation ideas that should fail a test: apply tabs one by one instead of building all first (damaged-file loop); skip the `validate()` call in `workspaceFromJson` (port 0); let `MockTab::loadState` ignore `validationFailed`; write the recent list with the file content; skip `QSaveFile::commit`.
  - Env notes for `build-env.md`: `mc::Expected<T>` has no `operator->` (use `.value()`); a `QJsonObject` is compared with `QCOMPARE` directly; the offscreen platform screen is 800x600 and clamps `restoreGeometry`; `QByteArray::fromBase64Encoding(..., AbortOnBase64DecodingErrors)` is the strict decode; qpb `serialization::toJson/fromJson` store a group as nested objects keyed by property id and `PropertyModel::validationFailed` fires for a value a validator refuses; `QSaveFile` leaves no temporary behind after `commit()`; piping `jom` into `Select-Object -First N` kills jom when N lines are read (exit -1): redirect to a file instead.
