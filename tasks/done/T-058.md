## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** before anything connects, every write a run could make is proven to land inside
  the profile's scratch area; `--dry-run` shows exactly what would be sent.
- **Approach** (spec "Safety gate", "The capture tool"):
  - `safety_gate.h/.cpp`:
    - `write` and `poll` steps (including a poll's ad-hoc writes): head … head + count − 1
      inside **one** scratch range of that device type.
    - `mutate` and `raw` steps: the final frame bytes (after every edit) are fed to an
      `mc::MockPlc` configured like the profile (frame, code, format, station/route,
      `deviceEnd` limits); `requests()` says what the frame asks for; any write outside
      scratch refuses the run. A frame the mock cannot decode must carry `readOnly: true`
      in the plan, otherwise the run is refused; `readOnly` frames go into the confirmation
      summary (decision D4).
    - `bench` steps that write are checked like `write`.
    - Any violation refuses the **whole run** and prints every offending step (id, kind,
      resolved range, why). No flag bypasses it (decision D4).
  - `main.cpp` CLI: `--profile`, `--plan`, `--dry-run`, `--only <groups>`, `--yes`,
    `--bench-reps`, `--plc-state`, `--report`, plus the output-root option (D3). Exit codes
    documented in `--help` (e.g. 0 ok, 1 run failures, 2 bad arguments or input, 3 refused
    by the gate — your choice, documented).
  - `--dry-run`: resolve, run the gate, print every frame it would send as hex (encoded by
    `McProtocol` for `write`/`read`/`poll`/`bench`; the edited bytes for `mutate`; the
    literal for `raw`), never construct a transport.
  - Confirmation prompt (D4): prints PLC identity, transport, scratch area and the
    `readOnly` list, then waits for the profile id on stdin; `--yes` skips it.
- **Files expected to change:** `tools/hil_capture/safety_gate.h/.cpp`,
  `tools/hil_capture/main.cpp` (and a small CLI/options unit if you split it), the test
  source, CMake + qmake source lists.
- **Acceptance criteria:**
  1. HIL-02: a `write`, a `poll` (subscription range and ad-hoc write), a `mutate` (an
     edited head device that moves a write out of scratch) and a `raw` step that reach
     outside scratch are each refused; one run with several offenders lists all of them;
     nothing is sent (proved with a counting/spy transport or by the tool never creating
     one). A write straddling two adjacent scratch ranges is refused (must lie inside one).
  2. An undecodable `mutate`/`raw` frame without `readOnly` refuses the run; with
     `readOnly: true` it appears in the confirmation summary.
  3. HIL-03: `--dry-run` output equals, frame for frame, the bytes `McProtocol::encode`
     produces for the resolved steps (the test encodes independently and compares).
  4. No option, environment variable or plan key disables the gate (reviewer reads the
     code; the test runs the refused plan with `--yes` too and it is still refused).
- **Gate 1 approval:** 2026-10-02 — leader, under the owner's delegation extended to Phase 7
  (`rules.md`). Common rules and decisions D1–D5: `tasks/active/T-057.md`.

- Deviations from the Plan (+ reason):
  - **The mock's log cannot be read naively.** `MockPlc` logs a request it frames but does not execute (e.g. `0403`, `1402`, 1E `04H`) and every run of bytes that cannot start a frame as a record with the default operation `ReadWords`, head `D0`, count 0, `answered == false`. Taken at face value that is a harmless read. The gate therefore treats a record with `count == 0` as "not understood" (it needs `readOnly: true` and is listed for the prompt, like a frame with no record), and a frame that is only partly understood (a decoded write followed by junk, e.g. an appended byte) also needs the declaration while the writes the mock did understand are still checked. An EOT counts as understood. No library change (D1).
  - **Poll subscriptions need `"input": true` outside scratch** (the T-057 decision, implemented here): HIL-02's "subscription range" is refused unless the plan marks it `input`. Heartbeat and ad-hoc writes of a poll are always checked, as is the profile's own session heartbeat.
  - Skipped steps (failed `requires`, `scratchTooSmall: skip`) are not checked: they send nothing.
  - `--only` selects steps before the gate runs, so the gate checks what will actually run.
- Commands run / outcomes:
  - `cmake --build build/cmake-debug --parallel 32`: warning-free (`/W4 /WX`).
  - `ctest -L hil_tool`: 1 entry, 92 test cases (71 profile/plan + 21 gate), 0 failures. `ctest -L "device|mock|integration|core_session|core_protocol|core_model|build|hil_tool|replay" -j 8` is re-run at the end of T-060 (serial entries skip without `MC_TEST_SERIAL_PAIR`).

- Notes for the tester:
  - HIL-02 "nothing is sent": `HIL_02_aRefusedRunSendsNothingEvenWithYes` points a profile at a `QTcpServer` on loopback and runs the refused plan with `--yes`/`--dry-run` in all four combinations; each exits 3, no connection is ever accepted and the output root is never created. The tool has no transport in this task; T-060's runner creates one only after the gate.
  - Mutation ideas that should make tests fail: skip the `count == 0` rule in `checkFrames` (U-05, U-07, R-03), drop the `partial` handling (U-07, U-08), drop the range-straddle rule (S-01), call `checkGate` after the prompt (the four-combination test).
  - HIL-03 compares the printed frames with `McProtocol::encode` called in the test (and with `ReadPlan::build` for the poll step's read plan, which is the library's own planner: a poll's frames are the planner's chunks, not something the tool derives).
  - The gate cannot verify writes in frames `MockPlc` does not decode (random write `1402`, 1E `04H/05H`, 1C `BT/WT`): see the G9 exception in T-057's Dev notes.
