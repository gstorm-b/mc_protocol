## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** every fault the integration matrix needs on 3E works with exactly
  the documented bytes.
- **Approach:**
  - `mute(on)`, `muteNext(n)`: requests are decoded and logged with
    `answered = false`, nothing is sent.
  - `corruptNext(c, n)` in `src/mock/corruption.cpp`, applied to the next n
    responses. Ethernet modes: `WrongSubheader` (binary: first byte XOR 01H;
    ASCII: first character becomes `'E'`), `WrongRoute` (network / PC /
    station field + 1, per the enum's comment), `Truncate` (last byte
    dropped), `ExtraByte` (one 00H after the frame; for ASCII also 00H — the
    enum says so), `JunkPrefix` (three 55H before the frame). Serial-only
    modes (`WrongSumCheck`, `WrongBlockNo`) on an Ethernet frame leave the
    response unchanged — document this in the header; T44 gives them bytes.
  - `clearFaults()` clears `failRange`, mute and pending corruptions.
  - Unsupported commands (0403, 1402, …) → `unsupportedQna` with error
    information, as the vector error layout.
- **Files expected to change:** `src/mock/corruption.cpp` (+ header),
  `src/mock/mock_plc.cpp`, `include/mc/mock/mock_plc.h` (doc comments only),
  `src/CMakeLists.txt`, `mc_mock.pri`, `tests/mock/test_mock_faults.cpp`,
  `tests/CMakeLists.txt`, `tests/qmake/mc_mock_tests.pro`.
- **Acceptance criteria:**
  1. MCK-09 (3E): 0403 and 1402 requests get `unsupportedQna` (C059H) with
     the error information of the request.
  2. MCK-11, Ethernet cases, 3E Binary and 3E ASCII: `mute`, `muteNext(n)`
     and each Ethernet `Corruption` mode produce exactly the documented bytes
     (or none), asserted byte-for-byte against a clean response; `n`
     counts down and the (n+1)-th response is clean; the request log shows
     `answered` correctly.
  3. `clearFaults()` restores clean answers.
- **Common to every Phase 4 task:** see T-029.
- **Gate 1 approval:** 2026-09-30 — leader, under the owner's delegation
  extended to Phase 4 (`rules.md`). Gate 2: leader, one commit for the phase.

## Leader decisions on the open points (2026-09-30, T-029…T-031)

All accepted as implemented; the reviewer judges them against the spec at T-034.

1. A muted request is decoded and logged, **not executed** (a muted write leaves memory untouched).
2. `WrongRoute` changes only the response header's network, PC and station fields (wrap at FFH).
3. Requests the mock cannot execute (unknown command/subcommand/device code, count 0, bad
   layout, bit op on a word device, response over the u16 length) → `unsupportedQna` with the
   request's error information; `setBit`/`bit` on a word device ignored / false (documented).
4. A contiguous junk run is one unanswered log record, independent of fragmentation.
5. Check order: not executable → bit op on word device → `failRange` → device limit → size; the
   mock does not enforce the spec §4.4 point limits (a lenient server; the client's `chunk()`
   is what INT-07 checks).
6. Pimpl `MockPlc`: destructor, move operations, no copy; `corruptNext` calls queue FIFO,
   `n = 0` is a no-op.
