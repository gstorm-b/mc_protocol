## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** A qmake consumer can compile the library from one `include()`,
  and the repository builds and runs its test through the `.pri` files alone
  (BLD-03), per `SPEC-build-packaging.md` ("qmake `.pri` contract").
- **Approach:**
  - `mc_core.pri`: guard `!defined(MC_CORE_PRI_INCLUDED, var) {
    MC_CORE_PRI_INCLUDED = 1 … }`; `CONFIG += c++17`; `INCLUDEPATH +=
    $$PWD/include $$PWD/src`; `HEADERS += $$PWD/include/mc/version.h`;
    `SOURCES += $$PWD/src/core/version.cpp`. One entry per line
    (`HEADERS += \` continuation), so T-004's BLD-04 parser has one format.
  - `mc_mock.pri`: own guard, `include($$PWD/mc_core.pri)`, no sources yet
    (comment: `src/mock` arrives with T25).
  - `mc_device.pri`: own guard, `include($$PWD/mc_core.pri)`,
    `QT += core network serialport`, no sources yet (T30).
  - `mc_protocol.pri`: includes `mc_core.pri` and `mc_device.pri`.
  - No `.pri` sets `TARGET`, `TEMPLATE` or `DESTDIR`.
  - `mc_protocol.pro`: `TEMPLATE = subdirs`, `SUBDIRS = tests/qmake`
    (`examples/qmake` joins when examples exist).
  - `tests/qmake/tests.pro`: `subdirs` of the test `.pro` files.
  - `tests/qmake/build_version.pro`: builds `../build/test_version.cpp`
    through `include(../../mc_core.pri)`, `QT =` (no Qt), `CONFIG += console
    testcase warn_on`, `INCLUDEPATH += ../third_party`. Named `build_version`
    (todo said `core_version`) because the test lives in `tests/build/` since
    T-002.
- **Files expected to change:** `mc_core.pri`, `mc_mock.pri`, `mc_device.pri`,
  `mc_protocol.pri`, `mc_protocol.pro`, `tests/qmake/tests.pro`,

- Deviations from plan (+ reason):
  - **qmake `SUBDIRS` syntax, not a change in outcome.** The Plan's Approach
    bullets write the shorthand `SUBDIRS = tests/qmake` (root) and describe
    `tests/qmake/tests.pro` as "subdirs of the test .pro files". I implemented
    the *intent* (the `tests/qmake` tree joins the subdirs build) but not that
    literal syntax, because it does not work: I probed qmake 3.1 (Qt 6.11.1)
    directly under `build/` (scratch, not committed) and confirmed a bare
    `SUBDIRS = <name>` entry always resolves to `<name>/<name>.pro` — i.e.
    `SUBDIRS = tests/qmake` would look for `tests/qmake/qmake.pro`, not
    `tests/qmake/tests.pro`, and a bare sibling-file entry (no subdirectory at
    all, e.g. `SUBDIRS = build_version` inside `tests/qmake/tests.pro` with only
    `build_version.pro` next to it) resolves the same way and fails for the
    same reason. Adding both `<entry>.subdir` and `<entry>.file` together
    produces a qmake `WARNING: Cannot assign both file and subdir for subdir
    <entry>`. The clean, warning-free form — verified twice, in
    `mc_protocol.pro` and in `tests/qmake/tests.pro` — is `<entry>.file =
    <path-to-the-real-.pro>` alone (no `.subdir`). This changes only how the
    `SUBDIRS` entry is spelled, not the file list, the tree layout, or any
    acceptance criterion; it is why AC1 passes end-to-end (see below). No other
    file or piece of the approach changed.
  - Everything else matches the Plan's file list and per-file approach exactly.
