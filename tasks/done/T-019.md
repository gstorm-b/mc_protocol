- **Env notes (new, for build-env.md's qmake gotchas section):** a `TEMPLATE = subdirs` parent
  whose children all use `.file =` (no `.subdir =`, per the existing T-003 gotcha) builds every
  child in the **same physical directory** — there is no per-target subfolder qmake would
  otherwise create. That means qmake's default `OBJECTS_DIR` (and `MOC_DIR`/`RCC_DIR`/`UI_DIR`)
  is shared identically across every child `.pro`, so two children compiling a same-named source
  file (a shared `.pri`'s own sources, or two binaries that each happen to have their own
  `main.cpp`/`test_alloc.cpp`) will silently let whichever built last reuse — not rebuild — the
  first one's object file, and link it in even though it belongs to a different, unrelated
  source file of the same name. Every child `.pro` in a directory-sharing `subdirs` group needs
  its own `$$TARGET`-named `OBJECTS_DIR`/`MOC_DIR`/`RCC_DIR`/`UI_DIR`
  (`CONFIG(debug, debug|release) { OBJECTS_DIR = $$TARGET/debug; … } else { OBJECTS_DIR =
  $$TARGET/release; … }`) to stay isolated; this is easy to miss because the build still
