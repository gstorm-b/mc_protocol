## Plan  *(leader writes; Gate 1 approves)*

- **Skill pack: not used** (owner experiment, `rules.md` "Skill pack").
- **Background:** `docs/spec/SPEC-gui-tool.md` GUI-06, amended 2026-10-12 (option b). The spec text is the contract; do not edit it.

  **Today:** `ConfigBinding` (`tools/mc_workbench/config_binding.cpp`, about line 480–520) runs `fromJson()` and then `McDeviceConfig::validate()` on every single edit, and rejects the edit when either fails. The Serial fields are enabled only when `transport/kind` is Serial. Switching to Serial with the empty default `portName` therefore can never be accepted, and the user is stuck.
- **Goal:** an edit is rejected only when it is malformed (what `fromJson()` refuses: wrong type, out of the field's own range). A config that parses but fails `validate()` is kept as a **draft**:
  - the failing field (`where`) is marked with the library's message;
  - Connect stays disabled until the draft passes;
  - the runner only ever receives a valid config.
- **Approach:**
  1. **`ConfigBinding`** holds the draft (`draft()`) next to the last valid config (`config()`, unchanged meaning), plus a draft status:
     - `draftValid()`;
     - `draftMessage()`;
     - `draftWhere()`, the JSON path, mapped to the property path.

     Choose names that match the file's style.
     - **Signals:** keep `configChanged` for valid configs only, `rejected` for malformed edits, and add a signal for "draft changed / became invalid / became valid".
     - **The existing frame-family fallback** (`presetFor`) stays: a frame change that would be invalid but becomes valid with the family's defaults is still applied as valid.
     - **Marking the failing field:** use what qpb 1.7.0 offers for an invalid or highlighted property (read `components/qpb` headers; **never modify `components/`**). If qpb has no such state, show the message in the tab's existing status or message line and select the field. Say which in the Dev notes.
     - **Enabled-state rules** (`setEnabledWhen`) follow the draft, so after selecting Serial the Serial fields are editable at once.
  2. **`DeviceTab`:**
     - Connect is enabled only when Disconnected **and** the draft is valid, with a tooltip carrying the message.
     - `connectToPlc` uses the valid config.
     - A config pushed from outside (workspace load, `setConfig`) that fails validation is loaded as a draft and marked, not dropped. Read how `setConfig` callers use the return value; GUI-08 must keep passing.
  3. **Workspace save/load (GUI-08):** saving writes the draft (so nothing the user typed is lost), and loading restores it as a draft. If the existing workspace format cannot hold an invalid config without a schema change, stop and report it.
  4. **Other config grids:** if the mock tab or another view uses `ConfigBinding`, it gets the same behaviour. List each user in the Dev notes.
  5. **Tests** (`tests/gui/tst_gui_device_tab.cpp`; GUI-06 additions):
     - TCP → Serial with an empty port name: the kind edit is accepted as a draft, the port-name field is marked, Connect is disabled, and the runner still holds the old valid config;
     - entering `COM54` makes the draft valid, enables Connect, and emits `configChanged`;
     - a malformed edit (out of range) is still rejected and the draft is unchanged;
     - Serial → TCP with an empty host behaves the same way;
     - a workspace round trip with an invalid draft keeps the draft and its mark.

     Existing GUI-06 and GUI-08 assertions may only change where the spec amendment changes behaviour. List every changed assertion in the Dev notes with the reason.

## Dev notes  *(developer writes)*

- Files changed:
  - `tools/mc_workbench/config_binding.h/.cpp`: `ConfigBinding` holds `draft()` next to `config()` (last valid, unchanged
    meaning). New: `draftValid()`, `draftMessage()`, `draftWhere()` (property path mapped from validate()'s dotted
    path, nearest-field fallback, `frame` -> `frame/frame`), `invalidAttribute()`, signal `draftChanged()`.
    `configChanged` = valid configs only, `rejected` = fromJson refusals only. `candidate()` builds from the draft and
    returns `parsed` (fromJson ok) / `ok` (validate ok) / `where`; the qpb validator refuses only when `!parsed`.
    Frame-family fallback (`presetFor`) kept. `setConfig()` always loads the config as the draft and returns true iff
    valid. A constructor argument that fails validate() starts as a draft (`config()` = default config). The
    enabled-state rules read the model, which is synced from the draft, so Serial fields are editable at once.
  - `tools/mc_workbench/device_tab.h/.cpp`: Connect enabled only when Disconnected and `draftValid()`, tooltip = draft
    message (`connectEnabled()`, `connectToolTip()` accessors for tests); `connectToPlc()` returns when the draft is
    invalid; `onDraftChanged()` shows "Not valid yet: ..." in the message line and selects/scrolls to the failing
    field, clears the line when valid; `setConfig()` loads an invalid config as a draft, sets `*error` to the message
    and still returns true (false only when not Disconnected).
  - `tools/mc_workbench/workspace.cpp`: a config that parses but fails validate() is kept (no problem reported);
    `workspace_controller.cpp`: capture saves `binding()->draft()`. Doc comments in `workspace.h` updated.
    No schema change: the file holds `toJson()` of the draft.
  - `tests/gui/tst_gui_device_tab.cpp`, `tests/gui/tst_gui_workspace.cpp` (see below).

  delegate and model roles). So the property gets the attribute `mcInvalid` (= the message), its tool tip becomes the

  selects the field. Cleared when the draft is valid or the failing field moves. No colour (no Foreground role in qpb).
