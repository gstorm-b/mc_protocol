## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `McDevice` drives a `Session` over a `Transport`: link state
  machine, drain → FIFO signal queue → emit at the outermost call, one
  single-shot deadline timer, Qt value types in signals; the `MockPlcServer`
  test helper.
- **Approach:**
  - `include/mc/device/mc_device.h` + `src/device/mc_device.cpp` as the
    sketch; add the new signal types to `meta_types.h` / `registerMetaTypes()`
    (called once by the constructors).
  - Link state machine: every row of the spec's table; every `connectToPlc()`
    ends in at least one `linkStateChanged`; `requestFinished` from
    `linkDown` before the state signal of the same call.
  - Pump (spec "Pump and signal order"): every public method, transport slot
    and timer slot ends with drain → arm → flush-at-outermost-call. `Send` is
    written at once; other outputs are converted (`QVector<Change>`,
    `DeviceSnapshot` copied from `values()` including `chunks`, `QByteArray`
    payload) into the queue; a failed `write` → `session.linkDown(now)` after
    the drain, then drain again. Time: `QElapsedTimer` from construction;
    timer `Qt::PreciseTimer` at `nextDeadline() - now`, stopped when none.
    `readyRead`: fixed 4 KiB buffer, `read` until 0, `bytesIn` + drain per read.
  - `tests/device/mock_plc_server.h/.cpp`: `QTcpServer` on `127.0.0.1`,
    OS-chosen port, a fresh `MockPlc` per accepted connection; exposes the
    current mock, a connection counter, `closeClient()` and `mute()`.
  - `tests/device/tst_mc_device.cpp` (QtTest, label `device`) + qmake twin.
- **Files expected to change:** `include/mc/device/mc_device.h`,
  `src/device/mc_device.cpp`, `include/mc/device/meta_types.h`,
  `src/device/meta_types.cpp`, `src/CMakeLists.txt`, `mc_device.pri`,
  `tests/device/mock_plc_server.h/.cpp`, `tests/device/tst_mc_device.cpp`,
  `tests/CMakeLists.txt`, `tests/qmake/*.pro`.
- **Acceptance criteria:**
  1. QDV-01, 02, 03, 04, 07, 15 pass over loopback TCP on 3E Binary with the
     expectations of the spec's table (signal order asserted, not only counts).
  2. Every `connectToPlc()` ends in at least one `linkStateChanged` —
     asserted for each starting state (Disconnected, Connecting, Connected).
  3. A test proves the flush rule: a slot connected directly to a signal
     that calls back into the device gets its nested signals after the ones
     already queued (the full QDV-08 is T-038; this is the minimal pump test).
- **Common to every Phase 5 task:** see T-035.
- **Gate 1 approval:** 2026-09-30 — leader, under the owner's delegation
  extended to Phase 5 (`rules.md`). Gate 2: leader, one commit for the phase.

- Deviations from plan (+ reason):
  - **`Transport::lastLossWasPeerClose()` (public header addition, not in the spec sketch).** The spec table says `lost(r)` gives `(Disconnected, PeerClosed or TransportError, r)`, but `Transport::lost(reason)` carries no cause, so the device cannot choose. A non-signal virtual with a default keeps other transports source-compatible. If the leader or owner prefers no addition: drop it and always publish `PeerClosed` (QDV-04 still passes). It is not one of the T-035 "Ask first" kinds (no signal, `LinkState`, `LinkReason` or config key), so I did not stop; please confirm.
  - **`connectToPlc()` while Connecting republishes `(Connecting, Requested)`.** The spec table lists the row with no signal, the slot doc says "no-op ... Always publishes a state", and the Plan (criterion 2) demands a `linkStateChanged` from Connecting too; I followed the Plan and the sentence "every call to connectToPlc() ends in at least one linkStateChanged". No second socket is opened.
  - **`Serial` transport kind without an injected transport** publishes `(Disconnected, OpenFailed, "the serial transport is not available in this version")`: `SerialTransport` arrives with T46 (Phase 6). No new `LinkReason`.
  - **`setConfig()` refuses a config that fails validation and keeps the previous one** (returns the `validate()` error and its path); the spec is silent. The constructors, which cannot fail, keep an invalid config and report it through `configStatus()` and `connectToPlc()` (QDV-16, tested in T-038).
  - With an injected transport, `cfg.transport/tcp/serial` are also ignored for validation (validated as defaults), as the spec says they are ignored.
  - `DeviceRecorder` and the support functions are header-only instead of one more `.cpp`; they are listed in the CMake target so AUTOMOC and IDEs see them.
