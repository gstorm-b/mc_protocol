## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `McProtocol`/`Parser` speak 1E Binary and 1E ASCII end to end,
  pinned to the Appendix A.5/A.6 vectors.
- **Approach:**
  - `src/core/protocol/frame_1e.h/.cpp` (spec §5.3): request = subheader
    (command code 00–03), PC, monitoring timer LE2 / 4 chars, request data;
    default timer from `FrameConfig::frame1E()`.
  - Response parse: subheader must equal command | 0x80, else `FrameMismatch`;
    end code `00` → exactly the computed response size; `5B` → one more byte /
    2 chars as `abnormalCode`, fail with `Plc`; any other end code → fail with
    `Plc` after exactly 2 bytes / 4 chars, **never waiting for more**. Error
    mapping per the spec's table (`plcCode` u8, `abnormalCode` when 5BH).
  - Wire it into `protocol.cpp` (the facade's frame dispatch) and the
    streaming `Parser` (`frameLength()`, partial input), the way 3E is.
  - Vectors: `tests/vectors/1e_binary.vec`, `1e_ascii.vec` from Appendix
    A.5/A.6 (VEC-02 guard; 1E-12 and any `v1.1` rows tagged).
  - Tests: `tests/core/protocol/test_frame_1e.cpp`; STR-02 extended with a
    1E pair; ALC-01 (core-protocol) extended to 1E.
- **Files expected to change:** `src/core/protocol/frame_1e.h/.cpp`,

  - ALC-01 covers 1E through the public `McProtocol`/`Parser` only (as the existing cases do); no
    ALC test for `payload()` on a Failed frame (not called there).
