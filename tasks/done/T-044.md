### Rework after batch review  *(developer, 2026-10-01)*

1. **`autoGap(cfg, Op::ReadBits)` fixed** (`src/core/session/read_plan.cpp`). Cause: the old code
   took the per-unit wire cost as the whole-byte difference of the 100- and 101-point responses and
   extrapolated back by subtracting `99 * unit`. For a packed Binary bit read that difference is 1
   byte for half a byte of cost, so `respBig - 99 * 1` wrapped the unsigned subtraction. Now, from
   `maxResponseSize()` at 100, 101 and 200 units (the data term dominates at 100 and 200, so the
   envelope cancels): `hundredUnits = r200 - r100` (wire size of 100 more units), real 1-unit
   response `= r101 - hundredUnits` (keeps the pad nibble / dummy character of an odd count),
   and the spec formula with the fractional unit `hundredUnits / 100` in integers:
   `gap = (100 * (request(1) + response(1)) - hundredUnits) / hundredUnits`, every subtraction
   guarded (returns 0 when it would go negative). Word reads are unchanged (16, 16, 7, 7).
   Values ReadBits, before (tester) and after, with the arithmetic (unit = 2 points per byte for
   Binary; R = request(1), S = response(1), both from the spec appendix A sizes):
   - 3E Binary: before 4294967278 (wrapped); R = 21, S = 11 + 1 = 12, hundredUnits = 50;
     (100 * 33 - 50) / 50 = 65.
   - 3E ASCII: before 64 (right); R = 42, S = 22 + 1 = 23, hundredUnits = 100;
     (100 * 65 - 100) / 100 = 64.
   - 1E Binary: before 4294967260; R = 12, S = 2 + 1 = 3, hundredUnits = 50;
     (100 * 15 - 50) / 50 = 29.
   - 1E ASCII: before 4294967260; R = 24, S = 4 + 2 = 6 (one point plus the dummy character),
     hundredUnits = 100; (100 * 30 - 100) / 100 = 29.
   New tests in `tests/core/session/test_range_set.cpp`: "PLN-03 autoGap(): ReadBits, by hand from
   the spec formula and the frame sizes" (the four literals with the arithmetic in comments) and
   "PLN-03 ReadPlan::build(): with bitsAsWords off, two far bit subscriptions stay two chunks"
   (the tester's repro M0 x 8 + M8000 x 8 on the four cells: 2 chunks each, was 32 on 1E and one
   7168-bit chunk on 3E Binary). Mutation (`scaled` + 100) fails the session tests.
2. `src/core/model/chunk.cpp` file comment now describes `detail::validateRequest(r, cfg, false)`
   (validate() without rule 6).
3. Nits: the new 1E subscribe test is renamed "SUB-1E-01 Session::subscribe() on 1E ..." (SES-22
   is the spec's); `include/mc/core/limits.h` `chunkCount` and `chunk` docs gain `@retval
   DataSizeMismatch` and a `PointCount` line that also names an empty request (doc only);
   `request_decode_ethernet.cpp` (two lines over 100 columns, the double blank line) and
   `response_build.cpp` (one comment line) tidied. No spec text touched.
