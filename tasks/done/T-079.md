# T-079: Qt 5.15 support — GUI `mc_workbench` (ADS for Qt5, property browser, app sources)

- **Created:** 2026-10-07  ·  **Plan ref:** Qt 5.15 follow-up (owner, 2026-10-07: scope "Toàn bộ, kể cả GUI")
- **Class:** `full` → batch tester and reviewer together with T-078
- **Status:** done — batch tester and reviewer PASS 2026-10-08; committed

## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `mc_workbench` and `mc_workbench_tests` build and pass on Qt 5.15 (MSVC `msvc2019_64` kit), with CMake and qmake. Qt 6 stays unchanged.
- **Known blockers (leader, 2026-10-07):**
  - **qpb** (vendored in `components/qpb`, MIT, "stays unmodified") requires **Qt ≥ 6.5**: `QPB_MIN_QT_VERSION 6.5` and `Qt6::` targets only.
  - **ADS:** the prebuilt package in `C:\build_packages` is Qt6/MSVC. The ADS source there supports Qt5 (`QT_VERSION_MAJOR 5`), so `scripts/build-ads.ps1` can build it for the Qt5 kit into `build/ads-qt5-msvc2019_64/install`. Only `build/` is written.
  - **The GUI sources** were written for Qt ≥ 6.5 and need a portability pass.
- **qpb path (owner, 2026-10-07):** the owner is having qpb updated to **1.7.0**, which supports
  Qt 5.15. The leader vendors it into `components/qpb`, replacing 1.6.1 unmodified, when the owner hands
  it over. Neither option (a) nor (b) below is needed. Step 2 becomes "vendor qpb 1.7.0 and build it on
  both Qt majors".
- **qpb 1.7.0 received (owner, 2026-10-07):** it is in `reference_source/qpb-1.7.0/qpb` (git-ignored reference),
  MIT, 18 files changed and 2 new `compat_p.h`, no binaries. Upgrade note: "Qt 5.15 needs MSVC 2019 / 2022, GCC or
  Clang (not MSVC 2026)". Part B copies it unmodified over `components/qpb` (README and `components/qpb.pri`
  updated for any new sources). **Toolchain (leader decision):** every Qt 5 tree builds with MSVC toolset
  **14.44** (v143); Qt 6 trees stay on 14.51 (T-078 implements the environment switch).
- **Split (leader, 2026-10-07):**
  - **Part A, now, beside T-078:** step 1 (the spike, report-only) and the ADS Qt5 build in step 3
    (`scripts/build-ads.ps1` with the Qt5 kit into `build/ads-qt5-msvc2019_64/install`).
  - **Part B, after T-078 is implemented and qpb 1.7.0 is vendored:** steps 2–5.
  - In part A the developer touches only `scripts/build-ads.ps1`, `mc_local.pri.example` and the task
    file. T-078 owns every CMake / qmake build file and the library sources.
- **Approach:**
  1. **Spike, report-only.** List every Qt 6-only API that qpb and `tools/mc_workbench` use, with the count and a rough effort. This lets the owner choose the qpb path.
  2. **qpb on Qt5 (owner decision).** Two options:
     - **(a)** Port the vendored qpb to Qt 5.15 with minimal, documented patches. This changes third-party code. The licence allows it, but the "qpb stays unmodified" rule must be lifted.
     - **(b)** Keep qpb Qt6-only and give the GUI a small Qt5 fallback property editor behind one interface. The two editors are duplicated UI code, and GUI-06 must pass on both.
  3. `scripts/build-ads.ps1` gains a Qt5 kit, and `mc_local.pri.example` gains an `MC_ADS_DIR_QT5` key. The GUI detection in CMake and qmake accepts Qt 5.15 with Qt5 ADS.
  4. Port `tools/mc_workbench` and `tests/gui` to compile on both majors, using `QT_VERSION_CHECK` only where no common form exists. The threading rules and the HIL gate stay unchanged.
  5. Add Qt5 GUI presets: `qt5-msvc-debug` and `qt5-msvc-release` gain `MC_ADS_DIR`.
- **Acceptance criteria:**
  - Qt 5.15 MSVC: the `gui` label is green (every GUI-01…09 case, GUI-02 COM case with COM54/COM55), on CMake and qmake.
  - Qt 6 kits unchanged and green.
  - Check scripts green on all kits.
- **Gate 1 approval:** 2026-10-07 — leader, under the owner's delegation for this follow-up. Step 2 is the owner's choice. Gate 2: one commit with T-078 after the batch tester and reviewer pass.
