## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** the "Frame trace", "Debug log" and "Capture and export" rows of the spec.
- **Approach:** per tab, a trace view (tx / rx chunks, nanosecond stamps, hex and ASCII, frame
  boundaries, optional decode) fed by the runner's batched copies; a log view of every `LogSink`
  (session, device, mock) with level / tab filters, search, copy, save; bounded ring buffers
  (configurable) everywhere; capture of a tab's traffic with `CaptureWriter` in the `hil-capture`
  formats. Export of a real-PLC capture as replay test data to `tests/vectors/captured/<profile-id>/`
  (the owner confirms before `git add`); captures of mocks or `virtual_plc` only to a user folder,
  never to `tests/vectors/captured/`.
  From T-068: `RecordingTransport` (in `mc_hil_tool`) keeps every chunk in memory and
  `DeviceRunner` only forwards new chunks — GUI-05's memory bound must cover it (e.g. a new device
  per connect or per capture); a change to `tools/hil_capture` must leave its tests and gate unchanged.
- **Acceptance criteria:** GUI-05 passes (memory bounded and GUI event latency below a stated
  limit while a mock answers as fast as it can for N seconds); a capture made in the GUI against a
  mock replays green with `mc_replay_tests --replay-root=...`; the export refuses a mock or
  `virtual_plc` capture as a target under `tests/vectors/captured/`.
- **Gate 1 approval:** 2026-10-03 — leader (Phase 8 delegation). Common rules: `T-067.md`.

- What it does:
  - **Memory bound of `RecordingTransport` (T-068 note):** the runner takes the recording off the transport at every flush tick (`takeChunks()`), so it holds one tick of chunks, never the whole link. No rebuild per connect is needed. The chunks go on to (a) the decoder, (b) an active capture, (c) a pending queue for the view (cap 20 000 chunks / 8 MiB, newest dropped and counted, signal `framesDropped`).
  - **Back-pressure:** each runner emits a batch (values, frames, log lines, requests, status) only when the GUI acknowledged the previous one (`FlowGate`, one batch in flight; the host answers the last signal `flushed()` with `ackFlush()`). While the GUI is behind, the runner keeps collecting in bounded queues. State changes and shutdown still flush at once. Off by default for a runner without a host; both hosts turn it on.
  - **Trace:** `TraceModel` ring per tab (rows and bytes, both configurable; default 100 000 rows / 32 MiB), columns `#`, `t (ns)`, `Dir`, `Len`, `Frame` (frame / part), `Hex`, `ASCII`, `Decode`; pause, clear, decode on/off (runner side), follow, copy, save (worker thread). Mock tabs trace what the mock receives (TX = the client requests) and sends. Decoder: a `MockPlc` reads the request, `McProtocol::parser()` the answer (ok / PLC error code / partial).
  - **Log:** one shared `LogModel` ring (default 100 000 lines) of every tab `LogSink` lines plus the GUI own link state and fault lines; `LogFilterModel` (level, tab, search); copy, save (worker thread), ring size.
  - **Capture:** `TabTelemetry` / `CapturePanel` start and stop a recording on the runner (device or mock tab), limits `maxChunks` (default 200 000) / `maxBytes` (64 MiB); `Save to folder` and `Export as replay data` write `run.meta`, `steps.vec`, `session.vec` through `CaptureWriter` on a short-lived worker thread of the runner (the device keeps polling). A request the mock can decode as a read becomes a `via: api` record; writes, EOT and junk are literal `via: raw` records; mid-stream unanswered requests are `timeout`; the last request of a recording with no answer is left out (`run.meta: unanswered_last_request`); `device_end` is the highest point accessed successfully.
  - **Export rule:** `checkOutputTarget()` runs on the runner before anything is written: a folder at or under `tests/vectors/captured` (resolved: `..`, links, case; or any path with the segments `vectors/captured`) takes `Real PLC` captures only; an existing capture folder is never replaced without the overwrite flag; a `Real PLC` capture of a loopback host or of a mock is refused at the start. The export button asks for confirmation and says "review before git add". `# source:` is `mock` / `virtual_plc` for those captures and `run.meta` says "not hardware".
- Deviations from plan (+ reason):
  - Capture writes `steps.vec` records only; `session.vec` is written empty (as `hil_capture` does for a plan without poll steps), so RPL-04 notes "no poll transcript" and passes. A GUI session has no plan, hence no read-back to satisfy RPL-05: writes are kept as literal frames (`via: raw`, `op: Raw`) instead of `api` records; reads are `api`. Raw writes still replay in RPL-03.
  - `StepRecord::source` added in `tools/hil_capture` (not named in the Plan; its tests and gate are unchanged and green). Without it a mock capture would say `source: plc`.
  - The tests write under `MC_GUI_OUTPUT_DIR` (`<build>/tests/gui_out/`, a fresh sub-folder per case, never `tests/vectors/captured/`), not under `build/_scratch-t071/`: a shipped test cannot depend on a scratch folder that is deleted at the end. `build/_scratch-t071/` held only my build logs and edit scripts and is deleted.
  - Test seam `DeviceRunner::logSink()`: the library logs only at events (link up, faults), so a healthy link never floods the log; GUI-05 writes lines through the runner own sink to exercise the log path (about 100 000 lines a second).
  - A save of the trace or of the log builds its text on the GUI thread (bounded by the ring) and writes the file on a worker thread; only the capture is built and written on the worker.
  - `applyConfig` / `reconfigure` stop an active capture (the frame settings may change).
