## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** The device model: the constexpr table of every symbol of spec
  §3.2, `deviceInfo()`, `parseDevice()`, `formatDevice()`, `Device`
  comparison (`include/mc/core/device.h`).
- **Approach:** as `SPEC-core-model.md` `device.h` and "Code Style": table
  indexed by `DeviceType`, `static_assert` that its size equals
  `DeviceType::Count` and every row's `type` equals its index. Parsing per
  spec §3.4: case-insensitive, longest symbol first, number radix per symbol;
  field width is **not** checked here (that is `validate()`, T-008).
  `formatDevice` behaves like `snprintf` (returns the length that would be
  written, never allocates).
- **Files expected to change:** `include/mc/core/device.h`,
  `src/core/model/device_table.cpp`, `src/core/model/device_parse.cpp`,
  `src/CMakeLists.txt`, `mc_core.pri`, `tests/CMakeLists.txt`,
  `tests/core/model/test_device.cpp`.
- **Acceptance criteria:**
  1. DEV-07-data: every row of `kDeviceTable` equals spec §3.2 — symbol, kind,
     radix and every code column (QnA ASCII/binary for Q/L and iQ-R, 1E, 1C),
     footnote rows included — one `SUBCASE` per row, with expected values typed
     from spec §3.2, not copied from the implementation.
  2. DEV-01…DEV-06 pass (happy paths, radix, longest match, ambiguity,
     malformed: "T10", "C5", "", "D", "100", "Q10" are errors).
  3. DEV-14 passes: `==`, `!=`, `<` order by table order, then number.
  4. The `static_assert`s on table size and row index hold; `ctest -L
     "core_model|build"` green.
- **Reviewer note (class `protocol-core`):** diff the table against
  `docs/mc_reference/mc-protocol-frame-spec.md` §3.2 row by row, not only
  against the module spec.
