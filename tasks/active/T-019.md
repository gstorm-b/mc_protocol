  measured coverage, the whole phase verified and reviewed, and `protocol.h`
  handed to the owner for review before Phase 3.
- **Approach:** MinGW build and tests; `scripts/check.ps1` with both kits;
  extend the coverage report so it can measure `src/core/protocol` (a
  directory parameter, default unchanged) and measure it in
  `build/cmake-coverage`. Close coverage gaps with tests only; a gap that
  reveals a defect stops the task (Dev notes, `Status: blocked`).
- **Files expected to change:** `cmake/mc_coverage_report.cmake`,
  `CMakeLists.txt` or `tests/CMakeLists.txt` (report target), test files
  under `tests/core/protocol/` for gaps.
- **Acceptance criteria:**
  1. MSVC and MinGW: `ctest -L "core_protocol|core_model|build"` green;
     `scripts/check.ps1` green with both kits (run one after the other).
  2. MinGW `-DMC_COVERAGE=ON`: line coverage of `src/core/protocol` ≥ 95 %
     (per file and total reported); core-model stays ≥ 95 %.
  3. Every row of the module spec's "Error mapping" that 3E can produce has a
     test; Dev notes map row → test name.
  4. **Phase verification (tester):** every acceptance criterion of T-013…
     T-018 re-verified by running things, one line per criterion prefixed
     with the task ID.
  5. **Phase review (reviewer):** the Phase 2 diff (working tree against the
     Phase 1 commit) reviewed against the Plans, `rules.md` and the
     Definition of Done, with the reference diffs the `protocol-core` tasks
     name (§2, §3.3, §4.1, §5.1, §7.2, Appendix A.1–A.4). Findings are fixed
     by the developer before the checkpoint closes.
  6. **Owner review of `protocol.h`:** after 4 and 5 pass, the leader sends
     the owner a summary of `include/mc/core/protocol.h`; Phase 3 does not
     start until the owner has seen it (`rules.md`).
