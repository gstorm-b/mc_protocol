## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** The tests that keep the two build systems and the public surface
  honest from now on: BLD-04 and BLD-05 as ctest entries (label `build`), and
  the two consumer smoke projects BLD-06 and BLD-07 (`SPEC-build-packaging.md`,
  Testing Strategy).
- **Approach:**
  - **Source lists become explicit.** Each library target lists its headers
    as well as its sources in `add_library` (today: `mc_core` gets
    `include/mc/version.h`), so CMake and the `.pri` files describe the same
    sets.
  - **BLD-04 `pri_sync`:** at configure time `src/CMakeLists.txt` writes
    `${CMAKE_BINARY_DIR}/mc_sources.txt` with `file(GENERATE)` — one line per
    (target, repo-relative path). `cmake/check_pri_sync.cmake` runs with
    `cmake -P`, parses `HEADERS`/`SOURCES` of `mc_core.pri`, `mc_mock.pri`,
    `mc_device.pri` (`$$PWD`, `+=`, `\` continuations), and compares each as a
    set with the matching target (`mc_core`, `mc_mock`, `mc_device`); a target
    that does not exist yet must have an empty `.pri` list. Any difference
    fails and prints file name, `.pri` and target.
  - **BLD-05 `include_hygiene`:** `cmake/check_include_hygiene.cmake`
    (`cmake -P`) over `include/mc/**` and `src/**`:
    (a) every quoted include in `include/mc/**` is `"mc/…"` and resolves under
    `include/`; in `src/**` it resolves under `include/` (`"mc/…"`) or `src/`;
    (b) no `#include <Q`, `QT_` or `Q_OBJECT` in `include/mc/core`,
    `include/mc/mock`, `src/core`, `src/mock`; (c) nothing under `include/mc/`
    resolves into `src/`; (d) nothing under `include/mc/device` or
    `src/device` includes `mc/mock/…`, and the `LINK_LIBRARIES` of `mc_device`
    (exported at configure time next to `mc_sources.txt`) does not contain
    `mc_mock` — reported as "not applicable yet" while `mc_device` does not
    exist. Every violation prints path:line and the rule letter.
  - Both registered in `tests/CMakeLists.txt` as `BLD-04.pri_sync` and
    `BLD-05.include_hygiene`, label `build`.
  - **BLD-06:** `tests/consumer_cmake/` is its own project:
    `add_subdirectory(${CMAKE_CURRENT_SOURCE_DIR}/../.. mc_protocol)` and
    `target_link_libraries(consumer PRIVATE mc::core)`; `main.cpp` prints
    `mc::version()`. `mc::device` is added to it when that target exists
    (T30). Built into `build/consumer-cmake`.
  - **BLD-07:** `tests/consumer_qmake/app.pro` with exactly one
    `include(../../mc_protocol.pri)` line; `main.cpp` prints `mc::version()`
    and `qVersion()` (links QtCore — proves MSVC 2026 links the
    `msvc2022_64` kit). Built into `build/consumer-qmake`.
  - The consumers are run by hand here and become check-script stages in
    T-005.
- **Files expected to change:** `cmake/check_pri_sync.cmake`,
  `cmake/check_include_hygiene.cmake`, `src/CMakeLists.txt`,
  `tests/CMakeLists.txt`, `tests/consumer_cmake/CMakeLists.txt`,
  `tests/consumer_cmake/main.cpp`, `tests/consumer_qmake/app.pro`,
  `tests/consumer_qmake/main.cpp`.
- **Acceptance criteria:**
  1. `ctest -L build` in `build/cmake-debug` runs BLD-04, BLD-05 and BLD-08,
     all green.
  2. Removing `version.cpp` from `mc_core.pri` makes BLD-04 fail and name the
     file; adding `#include <QString>` to `include/mc/version.h` makes BLD-05
     fail with rule (b) and path:line (both by hand, reverted).
  3. `tests/consumer_cmake` configures and builds as its own project, runs,
     and its build tree contains no `mc_build_tests` or other library test
     target (`cmake --build … --target help`).
  4. `tests/consumer_qmake/app.pro` builds with qmake + nmake and the program
     runs, printing both versions.
- **Verification commands:**
  ```powershell
  . scripts/vsdev.ps1
  cmake -S . -B build/cmake-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/msvc2022_64
  cmake --build build/cmake-debug
  ctest --test-dir build/cmake-debug -L build --output-on-failure
  cmake -S tests/consumer_cmake -B build/consumer-cmake -G Ninja; cmake --build build/consumer-cmake
  # qmake consumer: in build/consumer-qmake, qmake ../../tests/consumer_qmake/app.pro; nmake; run the exe
  ```
