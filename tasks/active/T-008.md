## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** Frame configuration and requests: `include/mc/core/frame_config.h`
  and `include/mc/core/request.h`, with `validate(Request, FrameConfig)`.
- **Approach:** as `SPEC-core-model.md` `frame_config.h` / `request.h`: the
  enums; `FrameConfig` named constructors with spec §8.3 defaults
  (`checkRoute` true for 3C/1C, false for 3E/1E); `FrameConfig::validate()`;
  `effectiveTimeoutMs()`; `Request` and its builders; `validate(Request,
  FrameConfig)` applying the module spec's seven rules **in the stated
  order** and returning the first failure.
- **Files expected to change:** `include/mc/core/frame_config.h`,
  `include/mc/core/request.h`, `src/core/model/frame_config.cpp`,
  `src/core/model/validate.cpp`, `src/CMakeLists.txt`, `mc_core.pri`,
  `tests/CMakeLists.txt`, `tests/core/model/test_frame_config.cpp`,
  `tests/core/model/test_device.cpp` (DEV-08…13 live with the device tests,
  per the module spec's structure).
- **Acceptance criteria:**
  1. CFG-01…CFG-05 pass: defaults equal spec §8.3; format 5 rejected for every
     frame; messageWait 16 rejected; timer 0 without timeout rejected; `Ascii`
     forced for 3C/1C; `effectiveTimeoutMs` derivation.
  2. DEV-08…DEV-13 pass (width overflow per family, unsupported symbol per
     family, `e1AliasLS`, multiple-of-16 incl. M9000, bit op on word device).
  3. Each of the seven `validate` rules has a test whose input breaks only
     that rule and asserts that rule's specific `ErrorCode`.
  4. `ctest -L "core_model|build"` green.
