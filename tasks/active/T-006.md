## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** The error and byte-view vocabulary every other module uses:
  `include/mc/core/types.h` and `include/mc/core/result.h`, header-only.
- **Approach:** `ByteView`, `MutableByteView`, `ByteBuf`, `kNoCode`;
  `ErrorCategory`, `ErrorCode` (incl. `NotSubscribed`), `ErrorInfo`, `Error`
  with `ok()`, `Expected<T>` (implicit from value and from `Error`; a
  move-only `T` makes `Expected` move-only) and `Expected<void>`. No
  exceptions, no allocation of its own. Creates the test binary
  `mc_core_model_tests` with `tests/core/model/main.cpp` holding the one
  `DOCTEST_CONFIG_IMPLEMENT_WITH_MAIN`. Header-only headers still appear in
  the `mc_core` header list and in `mc_core.pri` `HEADERS`.
- **Files expected to change:** `include/mc/core/types.h`,
  `include/mc/core/result.h`, `src/CMakeLists.txt`, `mc_core.pri`,
  `tests/CMakeLists.txt`, `tests/core/model/main.cpp`,
  `tests/core/model/test_result.cpp`.
- **Acceptance criteria:**
  1. RES-01…RES-03 pass: value/error semantics of `Expected<T>` and
     `Expected<void>`, `Error::ok()`, `message` is a static string.
  2. RES-04 passes: `Expected<std::unique_ptr<int>>` moves in and out, and a
     static check proves copying it does not compile
     (`!std::is_copy_constructible_v<…>`).
  3. `static_assert`s: `Error` and `Expected<int>` are trivially copyable.
  4. `ctest -L "core_model|build"` green on MSVC; BLD-04/05 green with the
     new headers.

- **Common to every Phase 1 task:**
  - Implement exactly the public API of `docs/spec/SPEC-core-model.md` for the
    headers named here; "spec §N" there means
    `docs/mc_reference/mc-protocol-frame-spec.md` §N.
  - Every new header/source goes into `src/CMakeLists.txt` (`mc_core`, headers
    listed too) **and** `mc_core.pri` in the same change (BLD-04); tests go into
    `mc_core_model_tests` (`tests/CMakeLists.txt`, label `core_model`).
  - Public headers follow `docs/rules/doc_comment_style.md`; every public
    function carries `@par Complexity` with the figures of the spec's
    "Complexity and allocation" table. No exceptions; `noexcept` as the spec
    shows. Definition of Done: `agent-team/project/definition-of-done.md`.
  - Test names start with the spec's test ID (e.g. `DEV-03 ...`).
  - Verification (MSVC daily loop, `agent-team/project/build-env.md`), one
    PowerShell call:
    `. scripts/vsdev.ps1; cmake --build build/cmake-debug; ctest --test-dir build/cmake-debug -L "core_model|build" --output-on-failure`
    — MinGW runs at Checkpoint A (T-012).
