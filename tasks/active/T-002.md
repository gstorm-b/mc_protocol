## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** The first buildable library: CMake project with the option set of
  `SPEC-build-packaging.md`, static target `mc_core` / `mc::core`, the single
  version header, warning and version helpers, vendored doctest, and one test
  binary proving BLD-08; plus `scripts/vsdev.ps1` so every role enters MSVC the
  same way.
- **Approach:**
  - `scripts/vsdev.ps1`: dot-sourced (`. scripts/vsdev.ps1`). If `cl.exe` is
    already on `PATH`, do nothing. Otherwise find the latest VS install with
    `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` via
    `${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe`,
    then call its `Common7\Tools\Launch-VsDevShell.ps1 -Arch amd64 -HostArch
    amd64 -SkipAutomaticLocation`. Prepend `C:\Qt\Tools\CMake_64\bin` and
    `C:\Qt\Tools\Ninja` to `PATH` when not present. Clear error text when
    vswhere or the C++ workload is missing. PowerShell 5.1 compatible.
  - `CMakeLists.txt` (root): `cmake_minimum_required(VERSION 3.16)`; include
    `cmake/mc_version.cmake` before `project(mc_protocol VERSION … LANGUAGES
    CXX)`; top-level detection `CMAKE_SOURCE_DIR STREQUAL
    CMAKE_CURRENT_SOURCE_DIR`; all eight options of the spec's option table
    with their defaults (`MC_BUILD_TOOLS` depends on top-level, DEVICE, MOCK);
    `add_subdirectory(src)`; `tests/` only when `MC_BUILD_TESTS`.
  - Only `mc_core` is created now. `mc_mock`, `mc_device` and any
    `find_package(Qt6)` arrive with their first sources (T25, T30); the options
    exist already but have nothing to switch yet.
  - `cmake/mc_version.cmake`: `file(STRINGS … REGEX)` reads the four
    `MC_VERSION_*` macros from `include/mc/version.h`; `FATAL_ERROR` when
    `MAJOR.MINOR.PATCH` differs from `MC_VERSION_STRING`.
  - `cmake/mc_warnings.cmake`: `mc_apply_warnings(target)` — MSVC `/W4`,
    GCC/Clang `-Wall -Wextra -Wpedantic`; `/WX` / `-Werror` when
    `MC_WARNINGS_AS_ERRORS`. Every target (library and tests) gets
    `cxx_std_17`, `CXX_EXTENSIONS OFF`.
  - `include/mc/version.h`: as in the spec's Version section, commented per
    `docs/rules/doc_comment_style.md` — `@file` block, the one `@namespace mc`
    block (§13.1), `Version` and `version()` documented. `0.1.0`.
  - `src/CMakeLists.txt` + `src/core/version.cpp` (a static library needs one
    source; it may define nothing beyond what keeps the target non-empty,
    e.g. a `static_assert` on the version macros).
  - `tests/third_party/doctest/doctest.h`: **doctest v2.5.3** (latest release,
    github.com/doctest/doctest), single header, MIT, with a `LICENSE.txt` beside
    it and the version and URL recorded in a comment line of
    `tests/CMakeLists.txt`.
  - `tests/build/test_version.cpp` → binary `mc_build_tests`, ctest label
    `build`, test name contains `BLD-08`. **Deviation from todo T01**: the todo
    listed `tests/core/test_version.cpp`, but `tests/core` belongs to the core
    module specs (ownership rule); the version test belongs to build-packaging,
    whose other `build`-label tests (BLD-04/05, T03) join it later.
- **Files expected to change:** `scripts/vsdev.ps1`, `CMakeLists.txt`,
  `cmake/mc_version.cmake`, `cmake/mc_warnings.cmake`, `include/mc/version.h`,
  `src/CMakeLists.txt`, `src/core/version.cpp`, `tests/CMakeLists.txt`,
  `tests/third_party/doctest/doctest.h`, `tests/third_party/doctest/LICENSE.txt`,
  `tests/build/test_version.cpp`.
- **Acceptance criteria:**
  1. From a plain PowerShell with no VS environment, `. scripts/vsdev.ps1`
     makes `cl`, `cmake` and `ninja` available; run a second time it changes
     nothing.
  2. MSVC (`build/cmake-debug`) and MinGW GCC 13.1 (`build/cmake-mingw`) both
     configure and build with zero warnings under `MC_WARNINGS_AS_ERRORS=ON`,
     and `ctest -L build` runs BLD-08 green in both.
  3. BLD-08 fails when `mc::version()` and the macros disagree (checked once by
     hand and reverted), and configure fails with a clear message when
     `MC_VERSION_STRING` disagrees with the three numbers.
  4. `PROJECT_VERSION` equals `MC_VERSION_STRING`; `MC_BUILD_TESTS`,
     `MC_BUILD_EXAMPLES`, `MC_WARNINGS_AS_ERRORS` and `MC_BUILD_TOOLS` are ON
     when top-level and OFF when the folder is consumed via `add_subdirectory`
     (checked with a scratch consumer under `build/`, not committed), and a
     consumed build creates no test target.
  5. `include/mc/version.h` follows `docs/rules/doc_comment_style.md`; nothing
     is written outside `build/` by the build.
- **Verification commands:**
  ```powershell
  . scripts/vsdev.ps1
  cmake -S . -B build/cmake-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/msvc2022_64
  cmake --build build/cmake-debug
  ctest --test-dir build/cmake-debug -L build --output-on-failure
  # MinGW, fresh PowerShell:
  $env:PATH = "C:\Qt\Tools\mingw1310_64\bin;C:\Qt\Tools\CMake_64\bin;C:\Qt\Tools\Ninja;$env:PATH"
  cmake -S . -B build/cmake-mingw -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH=C:/Qt/6.11.1/mingw_64
  cmake --build build/cmake-mingw
  ctest --test-dir build/cmake-mingw -L build --output-on-failure
  ```
