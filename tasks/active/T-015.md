## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** `qnaDevice()`, `e1Device()`, `c1Device()` — the wire form of a
  device for every family of spec §3.3 (QnA ASCII/Binary × Q/L and iQ-R, 1E
  ASCII/Binary, 1C ACPU/AnA).
- **Approach:** per the module spec's "Device encoding" table, on top of the
  core-model device table and the T-014 field codecs; `*` is never a space
  and leading zeros are never spaces; no allocation.
- **Files expected to change:** `src/core/protocol/device_encode.h`,
  `src/core/protocol/device_encode.cpp`, `src/CMakeLists.txt`,
  `mc_core.pri`, `tests/CMakeLists.txt`,
  `tests/core/protocol/test_device_encode.cpp`.
- **Acceptance criteria:**
  1. DEV-07 (wire half): every cell of the spec §3.3 example table (D100,
     X1F, TN10, M1234, M9000 × 8 families), one `SUBCASE` per cell, expected
     bytes typed from §3.3.
  2. Tests prove `*` padding and zero padding explicitly (no spaces anywhere).
  3. A device the family cannot encode returns the module spec's error.
  4. `ctest -L "core_protocol|core_model|build"` green on MSVC.

- **Common to every Phase 2 task:**
  - Implement exactly what `docs/spec/SPEC-core-protocol.md` specifies for the
    files named here; "spec §N" / "Appendix A" there mean
    `docs/mc_reference/mc-protocol-frame-spec.md`. The reference wins over
    `reference_source/` (module spec "Boundaries").
  - **Golden vectors:** typed from Appendix A (and the CMD/CMDD/PRIM tables of
    spec §9) into `tests/vectors/*.vec` in the spec's `.vec` notation, each
    with `# bytes: N` taken from its heading. A vector is never edited to make
    a test pass; a mismatch between code and vector is reported in Dev notes.
  - Every new header/source goes into `src/CMakeLists.txt` (`mc_core`, headers
    listed) **and** `mc_core.pri` in the same change (BLD-04); tests go into
    `mc_core_protocol_tests` (`tests/CMakeLists.txt`, label `core_protocol`).
  - Public headers follow `docs/rules/doc_comment_style.md` (`@par Complexity`
    with the module spec's figures); no exceptions; test names start with the
    spec's test ID and vector-driven assertions name the vector ID.
    Definition of Done: `agent-team/project/definition-of-done.md`.
  - Before writing code, check that the spec's sketches compile as declared
    (lesson T-007); report any contradiction instead of choosing silently.
  - Verification (MSVC daily loop, `agent-team/project/build-env.md`), one
    PowerShell call:
    `. scripts/vsdev.ps1; cmake --build build/cmake-debug; ctest --test-dir build/cmake-debug -L "core_protocol|core_model|build" --output-on-failure`
    — MinGW and coverage run at Checkpoint B (T-019).
  - Phase-batched verification (`agent-team/project/rules.md`): no tester or
    reviewer per task, no commit per task; the leader re-runs the verification
    and marks the task `implemented`.
