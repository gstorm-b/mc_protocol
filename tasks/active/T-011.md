## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** Logging and the zero-allocation guarantee of core-model:
  `include/mc/core/log.h` (`LogLevel`, `LogSink`, `NullLogSink`, `hexDump()`),
  a shared counting allocator for every later ALC test, and ALC-01.
- **Approach:** as `SPEC-core-model.md` `log.h`: `hexDump` renders control
  codes by name (`<STX>`, …) into caller storage without allocating.
  `tests/common/alloc_counter.h` replaces the global `operator new`/`delete`
  (all standard forms) with a counter that tests can reset and read; it is
  included by exactly one translation unit per test binary, and says so at
  the top of the file. ALC-01 runs every function of the zero-allocation list
  with realistic inputs after a warm-up and asserts zero counted allocations.
- **Files expected to change:** `include/mc/core/log.h`,
  `src/core/model/log.cpp`, `src/CMakeLists.txt`, `mc_core.pri`,
  `tests/CMakeLists.txt`, `tests/common/alloc_counter.h`,
  `tests/core/model/test_log.cpp`, `tests/core/model/test_alloc.cpp`.
- **Acceptance criteria:**
  1. LOG-01: a counting sink proves `write()` is never called and no message
     string is built when `enabled()` is false.
  2. LOG-02: `hexDump` renders control codes by name, per the spec's example.
  3. ALC-01: zero allocations across `parseDevice`, `validate`, `chunk`,
     `convert::float64At`, `hexDump`, `formatDevice`; a positive control
     proves the counter is live (a `new` it does count).
  4. `ctest -L "core_model|build"` green.

- **Common to every Phase 1 task:**
  - Implement exactly the public API of `docs/spec/SPEC-core-model.md` for the
    headers named here; "spec §N" there means
    `docs/mc_reference/mc-protocol-frame-spec.md` §N.
  - Every new header/source goes into `src/CMakeLists.txt` (`mc_core`, headers
    listed too) **and** `mc_core.pri` in the same change (BLD-04); tests go into
    `mc_core_model_tests` (`tests/CMakeLists.txt`, label `core_model`).
  - Public headers follow `docs/rules/doc_comment_style.md`; every public
    function carries `@par Complexity` with the figures of the spec's
    "Complexity and allocation" table. No exceptions; `noexcept` as the spec
    shows. Definition of Done: `agent-team/project/definition-of-done.md`.
  - Test names start with the spec's test ID (e.g. `DEV-03 ...`).
  - Verification (MSVC daily loop, `agent-team/project/build-env.md`), one
