## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** One command proves the whole folder (`SPEC-build-packaging.md`,
  "Everything, one command"), plus the repository documents a consumer needs.
  Closes Phase 0 at Checkpoint A0.
- **Approach:**
  - `scripts/check.ps1 -QtDir <kit>` (PowerShell 5.1). Enters the right
    toolchain from the kit name: `*msvc*` → `. scripts/vsdev.ps1`; `*mingw*`
    → prepend `C:\Qt\Tools\mingw1310_64\bin` (overridable `-MinGWDir`). Each
    stage prints `== [n/5] <name>` and a failing stage stops the script with
    `FAILED: <name>` and exit code 1. Stages use fresh folders under
    `build/check-*`:
    1. **cmake-full** (BLD-01, BLD-09): configure with `-DCMAKE_PREFIX_PATH=<kit>`,
       build, `ctest`; then assert `CMAKE_PROJECT_VERSION` in the cache equals
       `MC_VERSION_STRING` from `include/mc/version.h` (BLD-08, script half).
    2. **cmake-core** (BLD-02): `-DMC_BUILD_DEVICE=OFF`, `CMAKE_PREFIX_PATH`
       unset and every `Qt` entry removed from `PATH`, `--trace-expand` to a
       file; configure + build + ctest; fail if the trace contains
       `find_package(Qt6`.
    3. **qmake** (BLD-03): `<kit>/bin/qmake mc_protocol.pro`, then `nmake`
       (MSVC) or `mingw32-make` (MinGW), then the same tool with `check`.
    4. **consumer-cmake** (BLD-06): configure + build + run
       `tests/consumer_cmake`; fail if its build tree has a library test target.
    5. **consumer-qmake** (BLD-07): build + run `tests/consumer_qmake/app.pro`.
  - `scripts/check.sh <kit>`: the same five stages in POSIX sh for Git Bash
    with MinGW (`mingw32-make`), same messages and exit behaviour.
  - `.clang-format`: exactly the spec's settings (`BasedOnStyle: LLVM`,
    `IndentWidth: 4`, `ColumnLimit: 100`, `BreakBeforeBraces: Attach`,
    `PointerAlignment: Left`).
  - `README.md`, under one screen: what `mc` is; the three consumption paths
    (CMake `add_subdirectory`, qmake `include(.pri)`, copy the folder);
    version policy (SemVer, `include/mc/version.h`, tags `vX.Y.Z`, breaking
    change bumps major after 1.0); verified platforms (Windows, MSVC and
    MinGW GCC; Linux not verified; Qt 6.2 API, verified on Qt 6.11).
  - `CHANGELOG.md`: Keep a Changelog format, `## [Unreleased]` on top with
    the Phase 0 additions.
  - `LICENSE`: MIT, `Copyright (c) 2026 dev28` (holder named by the owner at Gate 1).
- **Files expected to change:** `scripts/check.ps1`, `scripts/check.sh`,
  `.clang-format`, `README.md`, `CHANGELOG.md`, `LICENSE`.
- **Acceptance criteria:**
  1. `scripts/check.ps1 -QtDir C:/Qt/6.11.1/msvc2022_64` exits 0 and prints
     all five stages.
  2. `scripts/check.ps1 -QtDir C:/Qt/6.11.1/mingw_64` exits 0 and
     `scripts/check.sh C:/Qt/6.11.1/mingw_64` in Git Bash exits 0
     (Checkpoint A0: both compilers, both build systems).
  3. A deliberately broken stage (e.g. a compile error injected into
     `version.cpp`, reverted) stops `check.ps1` at that stage with its name and
     a non-zero exit code; later stages do not run.
  4. The cmake-core stage's trace contains no `find_package(Qt6` and the
     stage runs with no Qt on `PATH` (BLD-02).
  5. README fits one screen (≤ 60 lines) and covers the three consumption
     paths, the version policy and the verified platforms; CHANGELOG has
     `Unreleased`; LICENSE is MIT, `Copyright (c) 2026 dev28`.
- **Verification commands:**

  scripts/check.ps1 -QtDir C:/Qt/6.11.1/mingw_64
