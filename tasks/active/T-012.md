## Plan  *(leader writes; Gate 1 approves)*

- **Goal:** Checkpoint A — core-model proven on both compilers with measured
  line coverage.
- **Approach:** implement the existing `MC_COVERAGE` option (GCC/Clang only:
  `--coverage` on `mc_core` and the core test binaries; a clear message and no
  effect on MSVC). Measure with MinGW's `gcov` in a fresh
  `build/cmake-coverage` — there is no Python on this machine, so no gcovr: a
  `cmake -P` script `cmake/mc_coverage_report.cmake` runs `gcov` over the
  `src/core/model` objects and prints per-file and total line coverage, and a
  custom target `mc_coverage_report` runs it. Close gaps with new tests only.
  If a gap reveals a real defect, stop and report it (Dev notes,
  `Status: blocked`) instead of changing production behaviour.
- **Files expected to change:** `cmake/mc_warnings.cmake` or a new
  `cmake/mc_coverage.cmake`, `cmake/mc_coverage_report.cmake`,
  `CMakeLists.txt`, `tests/CMakeLists.txt`, test files under
  `tests/core/model/` for gaps.
- **Acceptance criteria:**
  1. MSVC and MinGW: `ctest -L "core_model|build"` green from their build
     folders; `scripts/check.ps1` green with both kits.
  2. MinGW with `-DMC_COVERAGE=ON`: line coverage of `src/core/model`
     ≥ 95 %, reported by `mc_coverage_report` per file and in total.
  3. Every `ErrorCode` value that core-model code can produce appears in at
     least one test assertion; Dev notes map each code to a test name, and
     name the codes owned by later modules.

  - Public headers follow `docs/rules/doc_comment_style.md`; every public
